# Исследование кода и покрытия ВКМ

Начни с конкретного вопроса и закреплённого base_sha. Не перечитывай весь репозиторий.

1. Для межмодульного вопроса используй локальный Graphify: малый подграф, ограниченный hop/node/output budget. Проверь SHA индекса. Граф старого commit — только указатель, не доказательство текущих вызовов.
2. Найди определения и ссылки через Serena. Сохраняй точные файл, символ и строки. Динамические Python-вызовы, SQL и плагины могут отсутствовать в статическом графе; это ограничение, а не отсутствие связи.
3. Используй ast-grep для проверки однотипных конструкций. Сначала посчитай и локализуй совпадения, затем читай нужные фрагменты. Ограничивай max_results; усечение обозначай явно.
4. Context7 используй только для внешнего API: сначала найди установленную версию в lock/metadata, затем нужную версию документации. Нет версии — не выдавай current docs за точную документацию окружения.
5. Для скважин построй проверяемую цепочку registry → фильтр → модель → сетка → визуализация. Список expected ID берётся из действительного набора данных, не из картинки и не из одной скважины. Для 25/5/1 м проверяй каждую in-scope скважину, неизвестное исключение помечай UNKNOWN.

В review ничего не редактируй. Верни причины дефекта с локаторами, минимальный отрицательный пример, матрицу observed/expected/UNKNOWN и адресные тесты для Codex. Не делай научный вывод из одного tool success.
