# Задание Codex: полностью развернуть и принять VKM OpenCode Worker на Windows

Ты — основной Codex App проекта ВКМ. Выполни работу целиком: анализ существующего состояния, установка, конфигурация, проверки, исправление найденных несовместимостей, реальные прогоны и интеграция. **Пользователь только авторизуется.** Не отдавай ему команды установки, JSON для ручного редактирования, поиск путей или запуск тестов. Сам обнаружь расположение приложенного пакета и доступные checkout. При действительно необходимом входе открой конкретный auth-flow и попроси только подтвердить вход/ввести ключ локально; секреты не запрашивай в чате.

## 1. Архитектура уже выбрана

Сохрани Codex App на Windows главным координатором. Нативный Windows OpenCode CLI служит только headless-площадкой агентных сценариев. Codex выбирает профиль модели, формулирует ограниченную задачу, запускает runtime, проверяет артефакты и интегрирует результат. Внешние модели работают исключительно через OpenRouter. Профили: DeepSeek, Kimi, Gemini Hydrogen, Opus — точные ID, capabilities, provider pins и reasoning установить по актуальной конфигурации и каталогу, не по памяти.

Не устанавливай Ori, Hermes, DeepSeek Harness, Claude Code runtime. Не переноси OpenCode в WSL и не меняй авторизацию/подписку основного Codex. Существующие Linux-сервисы можно использовать через их действующие мосты. Не создавай вторую научную БД, универсальный оркестратор или очередную параллельную платформу.

## 2. Сначала сохранить и понять существующее

Прочитай приложенные README, REVIEW, DEPLOYMENT, CONTRACT и действующие AGENTS.md обоих репозиториев. Определи реальные public/private roots, ветки/SHA, dirty-файлы, активные PR и локальные worktrees; используй VKM_RESOURCES_ROOT и действующие сведения проекта. Не reset/stash/clean чужие изменения. Сохрани контрольные суммы затрагиваемых конфигураций и бэкап только тех файлов, которые действительно меняешь.

Найди установленный `openrouter-delegate` и его реальные budgets/ledger/route policy. Не начинай с устаревшего V1 и не считай пакет из переписки текущей установленной версией. One-shot Delegate оставить для задач без инструментального цикла; OpenCode использовать для самостоятельного чтения, поиска, правок и тестов. Не считать оба механизма двумя независимыми расходными разрешениями.

## 3. Установить и квалифицировать native runtime

Выполни read-only inventory. Переиспользуй подходящие Git, Python, uv, Node и существующие сервисы. Установи недостающее сам, в пользовательские версионированные каталоги без лишнего admin-доступа. OpenCode — официальный Windows standalone executable; выбери совместимую стабильную версию V2, проверь происхождение, точную версию, SHA256 и доступные checksums/signature. Не копируй неподтверждённые winget/npm-команды и не выполняй скачанный install-script без просмотра.

Сверь фактические `--help`, конфигурационную схему и CLI с реализацией пакета. Используй `--standalone`, noninteractive JSON, собственный named agent, ограничение steps; никаких `--auto`/allow-all. Прочитай наследуемые user/system/parent config и плагины: локальный opencode.jsonc сам по себе не обеспечивает изоляции. Если интерфейс изменился, исправь адаптер и тест, а не ослабляй ограничения.

Windows-квалификацию делай на disposable fixture без платных моделей: скрытое окно, оба pipe, timeout, авария, завершение потомков, рабочий каталог с пробелами/кириллицей, ограничения путей и конфигурации, фактический NDJSON event schema. Перепроверь Windows Job Object. Нельзя ставить native PASS по Linux/fake CLI тесту. Подготовь qualification receipt с хешами реальных evidence; после изменения реализации обнови квалификацию.

## 4. Подключить нужные MCP и существующую инфраструктуру

Локальные Graphify, Serena, ast-grep и remote Context7 настрой сам. Зафиксируй версии/commit SHA и executables; не используй `uvx git+...`/`@latest` как постоянный runtime. Для каждого сделай initialize → tools/list → содержательный tools/call, сохрани receipt и точные имена инструментов. Подключение MCP само по себе не означает, что модель реально им воспользовалась.

Graphify: локальная производная навигация по коду и документации, bounded queries, индекс с repo/commit/content hash. Не отправляй PRIVATE в hosted Graphify и не выдавай граф зависимостей за научные доказательства. Serena: настроенный языковой backend; definitions/references/символьные операции проверяй на реальном языке проекта. ast-grep: structural search и rule tests на известной fixture; записи только по разрешённым файлам. Context7: документация конкретной установленной версии, а не автоматически latest. Имена MCP-actions не угадывать.

Переиспользуй `vkm-corpus`, NAV/Neo4j/ScientificReader; QGIS/CAD подключай только нужным сценариям, без конкурирующего доступа к GUI/файлам. Записывающий MCP должен сам ограничивать область записи: OpenCode edit_permissions не ограничивают побочные эффекты серверного инструмента. До такой проверки оставь соответствующий MCP read-only, не объявляй его write-ready.

## 5. Авторизация и реальные профили

Сначала найди уже действующий разрешённый способ доступа к OpenRouter. Не читай ключ вслух, не печатай auth.json/env и не передавай его argv. При отсутствии доступа сам открой одноразовое окно авторизации/защищённого ввода. Разрешено использовать поставленные DPAPI scripts для существующего ключа. Пользователь не должен работать в OpenCode вручную.

Определи точные model IDs, endpoint pins, tool-calling, modalities, reasoning и тарифы через актуальные metadata. Сохраняй requested отдельно от observed/effective; отсутствие подтверждения не превращай в PASS. Запрети silent fallback. Проверь реальный wire request: provider-only, reasoning, max_tokens, model; не полагайся на поле конфигурации, которое runtime игнорирует.

Проверь действующее расходное разрешение, прежние расходы и конечный серверный cap через GET /key. Старый баланс, лимит профиля и цифра в историческом документе — не новое разрешение. Не повышай cap, не ротируй ключ и не обнуляй ledger ради продолжения. При отсутствии действующего бюджета закончи все бесплатные этапы и обозначь именно денежный blocker. Подготовку не превращай в новый цикл вопросов пользователю.

## 6. Интегрировать skill и выполнить end-to-end

Интегрируй проектный skill и launcher в действующий репозиторий минимальным изменением, сохрани относительные ссылки и структуру runtime; не делай второй несовместимый helper. Заполни host manifest автоматически найденными путями, capability/tool receipts, approved config/plugin sources и бюджетом. Пользователь шаблоны не заполняет.

Прогони пакетные тесты нативно и добавь тесты реальных найденных несовместимостей. Затем в разрешённом бюджете проведи по одному минимальному инструментальному smoke для каждого доступного выбранного профиля: реальный tool call, результат, usage и маршрут. Недоступную модель пометь отдельно; не заменяй молча. Все платные пробы включаются в общий бюджет.

Выполни один содержательный цикл: Codex → OpenCode → OpenRouter → MCP/код → артефакты → независимая проверка Codex. Предпочтительная задача — охват всех скважин при 25/5/1 м, включая №75, но сначала проверь, не исправлена ли она. Если исправлена, возьми актуальную незавершённую регрессию и укажи, почему. Исследование и разрешённое исправление выполняй в отдельных worktrees с явным base SHA, edit_paths, tests и criteria. Не трать деньги на дублирование одинаковых вопросов трём моделям.

После каждого запуска сам сверяй OpenRouter accounting, включая неизвестный исход/timeout. Pending не удалять ради обхода. Вызови reconcile только с реальными provider evidence. Сам проверь diff, source locators, тесты и отсутствие затронутых чужих файлов; CLI exit0 и текст модели не являются приёмкой.

## 7. Память, результат и завершение

Храни приватные receipts, session IDs, хеши входов/выходов и принятые handoff в существующих разрешённых хранилищах. Не создавай автоматически новый knowledge canonical. Непроверенные выводы модели не записывай как FACT; summaries и runtime memory могут быть lossy. Не обещай экономию: измерь tokens/cost/время на сопоставимой реальной задаче, отдельно от качества результата.

Предоставь итог: AS_IS→TO_BE, установленные версии и пути без секретов, конфигурационные изменения, тесты, реальные MCP/model/native статусы, diff/артефакты, стоимость и остаток бюджета, что действительно принято, что осталось NOT_RUN/BLOCKED. Сохрани runbook, rollback и проверенный проектный skill. Merge/push, публикацию исходников и изменение production/canonical не выполнять автоматически без действующего разрешения.

**Не заканчивай на плане, написанном skill или smoke “сложи два числа”. Нужен рабочий и проверенный headless workflow в этой Windows-среде. Не выдумывай PASS и не делай пользователя установщиком.** Если остаётся внешний blocker, покажи точную причину, сохрани выполненное и заверши все независимые доступные этапы.
