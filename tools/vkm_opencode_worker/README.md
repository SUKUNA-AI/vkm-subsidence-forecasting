# VKM · Codex → OpenCode Windows → OpenRouter · v2

Дата ревью: 14.11.2026. Этот пакет заменяет **оба** предыдущих пакета: Skill Draft и Windows Integration v1.

## Пользователь только авторизуется

Передайте Codex App этот каталог/архив и `CODEX_TASK_RU.md`. Codex сам обнаруживает checkout и окружение, устанавливает нативные зависимости, подключает MCP, создаёт заполненные конфигурации, проверяет их, проводит реальные прогоны и интегрирует результат. Пользователь не редактирует JSON, не выбирает пути установки и не запускает команды вручную. При необходимости Codex открывает только окно входа/OAuth или защищённого ввода существующего OpenRouter-ключа.

## Неизменяемая архитектура

**Codex App (Windows) → проектный skill → native Windows launcher → OpenCode headless → OpenRouter → выбранная модель.**

OpenCode — исполнительная среда для инструментального агентного цикла, а не второй пользовательский интерфейс. Вызовы моделей идут только через OpenRouter. Никаких Ori, Hermes, DeepSeek Harness, Claude Code runtime и установки OpenCode в WSL. Доступ к уже существующим Linux-сервисам через их штатные интерфейсы не запрещён. Подписку и авторизацию основного Codex не переключать.

Graphify, Serena, ast-grep, Context7 дополняют имеющиеся инструменты ВКМ. Graphify локальный; научный граф, NAV, корпус, ScientificReader, CAD/QGIS не заменяются новым каноном. MCP и навыки подключаются адресно под сценарий, а не все сразу.

## Граница проверенного

Выполнены offline-тесты Python, реальные временные Git-репозитории, регрессии дефектов v1 и контроль процессов в Linux. Инструментальные интеграционные тесты используют **fake OpenCode CLI**. Их PASS не подтверждает Windows API, настоящий OpenCode, доступность моделей или MCP. Результат этой поставки: **101 тест, 0 failures, 0 errors, 0 skipped**; полный список — `validation/offline-results.json`.

На пользовательской WORKSTATION в этой сессии ничего не устанавливалось. Windows/native, реальные API/MCP/CAD и экономия токенов — **NOT_RUN**, см. `validation/native-status.json`. Это проверенная исходная поставка для развёртывания Codex, **не акт выполненной production-приёмки**. `run` намеренно блокируется без проверяемого локального qualification receipt; флага обхода в пользовательском CLI нет.

## Основные свойства реализации

Запуск из отдельного detached worktree от явно указанного commit SHA; dirty checkout не копируется и не очищается. Сохранение полного исходного состояния проверяется, а при параллельном изменении Codex выдаётся конфликт, не автоматический откат. Владение временными файлами учитывается по пути и хешу: чужие файлы не удаляются при аварии. Изменённые/новые файлы проверяются по точному списку, glob-права не разрешены.

Указаны модель и маршрут OpenRouter без тихого fallback. `title`, `summary`, `compaction` закреплены за тем же модельным профилем. Есть лимиты шагов, времени и объёма stdout/stderr. Skills явно разрешены; MCP-actions получаются из настоящего `tools/list`. Предусмотрены deny-default permissions **и** policies; они не являются ОС-песочницей.

Проверяется текущий конечный лимит OpenRouter-ключа. Неизвестный исход не списывается как ноль; следующий запуск блокируется до сверки **Codex**, а не пользователя. Wrapper не повторяет неудавшуюся задачу автоматически; внутренние retries OpenCode/провайдера могут существовать и должны учитываться в расходах. Серверный cap — граница бюджета партии, не обещание точного бюджета одного вызова/turn.

В журнал wrapper не копируются reasoning и payload всех tool calls. Нативная БД сессий OpenCode при этом может хранить исходные сообщения: Codex обязан проверить её расположение, ACL и retention. DPAPI защищает ключ at rest для Windows-учётной записи; не от программы, запущенной под тем же пользователем.
