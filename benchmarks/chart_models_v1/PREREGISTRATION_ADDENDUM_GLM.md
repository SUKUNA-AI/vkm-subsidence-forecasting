Агент CH, 29.09.2026. Дополнение зафиксировано **до первого запроса к GLM-OCR по рисункам набора**. Сервер
проверен только на рисунке вне набора (SPOT08, VKM-SRC-116 с. 4). sha256 документа — в
[`PREREGISTRATION_ADDENDUM_GLM.sha256`](PREREGISTRATION_ADDENDUM_GLM.sha256).

Основная предрегистрация ([PREREGISTRATION.md](PREREGISTRATION.md)) действует без изменений. Не меняются:

- истина: [`hashes_v1.json`](hashes_v1.json);
- метрики T1;
- статистика.

Отступления будут перечислены в `RESULTS.md`, раздел «GLM-OCR».

## 1. Вопрос

GLM-OCR — наш рабочий OCR: его использует конвейер корпуса. Нужно понять две вещи:
- читает ли он подписи засечек, названия и единицы осей, легенду лучше Tesseract;
- как он выглядит рядом с Qwen3.5-9B и Granite 4.1 4B.

Итог — рекомендация, каким чтецом подписей пользоваться маршруту R.

## 3. Входы и промпты

Для чего построен GLM-OCR:
- конвейер режет страницу моделью разметки PP-DocLayoutV3 на области;
- каждую текстовую область подаёт кропом 200 dpi в сером цвете с полем 2 pt и промптом `Text Recognition:`;
- области с меткой «chart» он **не распознаёт вовсе** (`LABEL_TASK["chart"] = None`);
- в карточке модели есть второй режим — извлечение информации по строгой JSON-схеме.

Отсюда три варианта входа:

| Вариант | Вход | Промпт | Зачем |
|---|---|---|---|
| **C** — кропы | каждый кроп подписи, который маршрут R даёт Tesseract, байт в байт (серый, ×3, поле 20 px; `raster.ocr_blobs`) | `Text Recognition:` | ближе всего к тому, для чего модель построена (маленькая текстовая область); те же пиксели, что у Tesseract |
| **W** — весь рисунок | тот же PNG, что видели Qwen и Granite, переведённый в серый | `Text Recognition:` | тот же вход, что у VLM и у разреженного прохода Tesseract по всему рисунку |
| **IE** — весь рисунок, извлечение | то же | документированный промпт извлечения информации со схемой T1 (текст ниже) | структурированный ответ по осям — как T1 у Qwen и Granite |

Промпт IE (дословно):

```text
请按下列JSON格式输出图中信息:
{
    "x_axis": {
        "title": "",
        "unit": "",
        "tick_labels": []
    },
    "y_axis": {
        "title": "",
        "unit": "",
        "tick_labels": []
    },
    "legend": []
}
```

**Кропы.** Скрипт `scripts/capture_label_crops.py` оборачивает `OcrEngine.read_line` и запускает маршрут R так же,
как рука G. Код FD не меняется.
- **Проверка 0 пройдена:** слова маршрута R с обёрткой совпали со словами руки G на всех 19 рисунках.
- Всего 152 кропа на 14 рисунках. У S1, S2, S4, R3, X32 кропов нет: там маршрут R находит подписи только разреженным
  OCR всего рисунка.
- sha256 кропов — [`hashes_glm_v1.json`](hashes_glm_v1.json).

**Задача T2 (ряды) не применима.** У GLM-OCR есть только два режима:
- распознавание текста, формул и таблиц;
- извлечение полей по JSON-схеме (удостоверения, формы).

Режима «график → ряды» нет, и конвейер области-графики не распознаёт.

## 4. Метрики

**T1 — как в основной предрегистрации.** Подписи сравниваются мультимножеством после `evaluate.norm`: без пробелов,
минусы → «-», запятая → точка.

- **W.** Ответ — свободный текст.
  - Токены: разрезать по пробелам и «|»; снять по краям `,;:()[]{}"'*#$` и `` ` ``; снять конечную точку; убрать
    маркеры LaTeX.
  - **Основная** мера: только токены-числа и даты — то же правило `is_labelish`, что у Tesseract в руке G.
  - **Вторичная**: все токены (как X4).
  - Название и единица осей, легенда — «найдено в тексте» (подстрока после нормализации). Это вторичная мера: с
    точностью полей у VLM её сравнивать нельзя.
- **IE.**
  - Числа схемы читаются как напечатаны (`parse_float=str`).
  - Списки берутся как есть; строка режется по пробелам и «;».
  - Легенда — строки или ключи объектов.
  - Метрики те же, что у Qwen в T1: полнота, полнота с учётом оси, точность, точное совпадение названий и единиц,
    полнота легенды.
- **C.**
  - Ответ на кроп — строка без пробелов. Мультимножество ответов по рисунку.
  - Основная мера — только числа и даты, как у Tesseract. Вторичная — все ответы.
  - Рядом — ответы Tesseract **на те же кропы** и доля кропов, где оба чтеца ответили одинаково.
  - Знаменатель — все подписи истины рисунка. Полнота поэтому ограничена охватом кропов, одинаково для обоих чтецов.

**Вторичное S — маршрут R с другим чтецом** (код FD без изменений). Для каждого варианта — число рисунков с
откалиброванными обеими осями (из 19) и среднее hit@2 % на 17 рисунках с истиной.

| Рука | Что меняется | Скрипт |
|---|---|---|
| RC | GLM-OCR подменяет Tesseract в `read_line` по sha256 кропа; разреженный проход остаётся Tesseract | `scripts/run_route_r_readers.py` |
| RIE | подписи GLM-OCR IE ставятся на блоки подписей, механизм руки H, только подписи | то же |
| RQ | то же с подписями Qwen T1 — эталон для RIE | то же |

**T3.** Секунды на рисунок: W, IE, C (сумма запросов кропов). Пик видеопамяти всей карты (фон рабочего стола 3,7 ГБ).
Запросы идут по одному.

**Статистика.** Парный бутстреп по рисункам: 10 000 повторов, seed 20260929, ДИ 95 %.

## 5. Какое сравнение честное

- **GLM-OCR против Tesseract.**
  - Строго честное по пикселям — **C против Tesseract на тех же кропах** (A2): меняется только чтец. Но это лишь
    152 кропа на 14 рисунках.
  - По всем 268 подписям — **W против Tesseract в руке G** (A1, основное): оба читают тот же рисунок целиком, у обоих
    свободный текст, одно правило фильтра.
  - Дополнительно — IE против Tesseract (A3).
- **GLM-OCR против Qwen и Granite.** Честное — **IE против Qwen T1** (B1, основное): тот же рисунок, тот же
  структурированный ответ по осям. Вторичное — W (все токены) против Qwen (B2) и IE против Granite (B3).

## 6. Правило решения

- **A — лучше Tesseract.** Вариант GLM-OCR проходит, если одновременно:
  - средняя по рисункам разность полноты > 0 и нижняя граница ДИ > 0;
  - точность в норме:
    - для IE (структурированный ответ) — микроточность ≥ 0,90, как §5.1;
    - для W и C (свободный текст) — микроточность не ниже, чем у Tesseract на том же входе, минус 0,05.
- **B — сравнение с Qwen.** IE против Qwen:
  - «лучше», если нижняя граница ДИ разности > 0;
  - «хуже», если верхняя граница < 0;
  - иначе «не различимы».
- **Рекомендация чтеца подписей для маршрута R:**
  1. GLM-OCR (промпт IE), если IE проходит A, по B «не различим» или «лучше» и его точность ≥ 0,90. Довод: он уже
     развёрнут в конвейере, 0,9B, второй сервер не нужен. Qwen остаётся только там, где нужна структура рядов (число
     рядов, соответствие легенды), — GLM-OCR её не даёт.
  2. Qwen3.5-9B, если по B IE «хуже». Тогда GLM-OCR заменяет Tesseract только там, где проходит A (например, как чтец
     кропов, вариант C / рука RC).
  3. Как в основной части (Qwen вместо Tesseract), если ни один вариант GLM-OCR не проходит A.
- Вторичное S показывается рядом и в правило не входит.

## 7. Воспроизведение

```text
capture_label_crops.py   кропы маршрута R + проверка 0
hash_inputs.py --glm-crops
run_glm.py --variants W,IE,C
run_route_r_readers.py --arm RC|RIE|RQ
evaluate_glm.py -> results_glm_v1.json
selftest_glm.py          самопроверка разбора и метрик
```

Самопроверка пройдена:
- истина, записанная как ответ W с «|» и LaTeX и как ответ IE с числами без кавычек, даёт полноту 1;
- пустой ответ даёт 0;
- исключение одно — подпись с пробелом внутри («R 5.2» на R2): в свободном тексте это два токена, она не может
  совпасть.

Пробный прогон `evaluate_glm.py` на поддельных ответах из истины отработал без ошибок.

Всё извлечённое — `DERIVATION`, `AUTO_EXTRACTED_UNREVIEWED`. В канон, evidence, CORE и EDGE ничего не пишется.
