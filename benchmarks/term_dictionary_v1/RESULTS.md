## 1. Решение

| Значение по умолчанию | Правило §6 | Принято |
|---|---|---|
| `topic.TRANSLATE_DEFAULT` — формулировка `translation` досье | выполнено | `True` |
| флаг `translate` гибридного поиска (`HYBRID_TRANSLATE_DEFAULT` сервиса API) | выполнено | `True`, но только когда работает поздняя стадия |

- **Поздняя стадия.** На CORE она включена по умолчанию (`VKM_HYBRID_LATE_DEFAULT=1`). Если запрос её выключает, флаг
  по умолчанию тоже выключен. Это сужение решения до измеренной конфигурации: движок P-E включает позднюю стадию, а
  разведочная проверка без неё показала значимое ухудшение (§5.2).
- **Включение на CORE** — решение координатора после развёртывания (§6 предрегистрации). Выключить флаг без
  пересборки: `VKM_HYBRID_TRANSLATE_DEFAULT=0` у сервиса `api`.
- **Цена, не входившая в правило:**
  - R@100 гибридного поиска −0,026 (§5.1);
  - лишние вызовы: перевод запроса в NAV, кодирование перевода, две ветви OpenSearch. Задержку показывает
    `timings_ms` ответа (`expansion_page_x1`); на CORE её нужно проверить после развёртывания.

## 5. Разведочные проверки

Добавлены после чтения результатов, в правило §6 не входят.

### 5.1 Глубина списка на P-E

| Метки | R@10: Δ, p | R@20: Δ, p | R@100: Δ, p, 95 % ДИ |
|---|---|---|---|
| V | −0,0023, 0,652 | +0,0035, 0,621 | −0,0261, 0,023, [−0,0498; −0,0045] |
| P | +0,0010, 0,522 | +0,0040, 0,363 | −0,0258, < 0,001, [−0,0402; −0,0114] |

- **Что меняется.** Ветви перевода меняют состав RRF-топ-100 — окна поздней стадии. У 87 запросов с переводом общих
  страниц в топ-100 H0 и H1 в среднем 58 из 100.
- **Почему теряется R@100.** Ответ глубиной 100 — это окно поздней стадии. Релевантные страницы, которые в H0 были в
  окне (часть из них поздняя стадия подняла в топ-50), в H1 вытесняются из окна страницами ветвей перевода и в ответ
  не попадают:
  - V: из топ-100 ушло 40 релевантных страниц (19 стояли в H0 на местах 1–50), пришло 13;
  - P: ушло 116 (78 — с мест 1–50), пришло 32.
- **Число релевантных страниц в топ-50 почти не меняется.** На освободившиеся места поздняя стадия поднимает другие
  релевантные страницы из нового окна: на V 290 → 296, на P 1 093 → 1 082.

### 5.2 Без поздней стадии (RRF-порядок: запросы с `late = false`)

| Метки | Метрика | H0 | H1 | Δ | p |
|---|---|---|---|---|---|
| V | nDCG@10 | 0,2574 | 0,2322 | −0,0251 | 0,048 |
| V | R@50 | 0,5666 | 0,5314 | −0,0352 | 0,034 |
| P | nDCG@10 | 0,5927 | 0,5456 | −0,0471 | 0,001 |
| P | R@50 | 0,7098 | 0,6464 | −0,0633 | < 0,001 |

- **Межъязыковые запросы (16) выигрывают:**
  - V: nDCG@10 +0,1228 (p = 0,061), R@50 +0,1734 (p = 0,029);
  - P: nDCG@10 +0,1659 (p = 0,020).
- **Запросы на одном языке теряют.** Без поздней стадии ветви перевода разбавляют список страницами на другом языке.
- **Смещение пула.** judged@10 на P падает с 0,921 (H0) до 0,804 (H1): пул меток V1/V2 собран без перевода, новые
  страницы не размечены и считаются нерелевантными. Часть потерь может быть этим смещением; без новой разметки его
  не отделить.
- **Досье без поздней стадии** — в пределах правила §6: Δ `page_recall@50` −0,0027 (p = 0,19), Δ `mrr@50` +0,0090
  (p = 0,25).

## 6. Вывод

- **Досье.** Словарь полезен как отдельная формулировка: полнота страниц на уровне, первая страница-цель выше.
- **Гибридный поиск.** Ветви перевода с равным весом в RRF:
  - помогают запросам, у которых источники на другом языке;
  - при поздней стадии не вредят верху списка, но теряют глубину (R@100);
  - без поздней стадии разбавляют запросы на одном языке.
- **Следующий шаг.** Вес ветвей перевода, запуск перевода по языку источников или шире окно поздней стадии при
  переводе — каждый вариант нужно измерять отдельно, со своей предрегистрацией.

   Исправлено, стадия C пересчитана; опубликованы числа с seed 20260929. Решения не изменились.
3. **Пакет каталогов** собран из дерева коммита `03fe05de` (`commit_source = argument`). Сверка с git внутри WSL
   была недоступна.
4. **Гибридный флаг только с поздней стадией** — сужение решения §6 до измеренной конфигурации (§1, §5.2).
5. **Разведочные анализы добавлены после чтения результатов:** R@10 / R@20 / R@100, перемещения релевантных страниц и
   вариант без поздней стадии. В файлах они помечены `exploratory` и `EXPLORATORY`.

## 8. Воспроизведение

Переменные окружения описаны в заголовке [scripts/run.sh](scripts/run.sh): рабочий каталог, сборка NAV снимка,
словарь, каноническая DuckDB, коммит каталогов, каталоги V1/V2, модели, два venv.

```bash
bash benchmarks/term_dictionary_v1/scripts/run.sh all   # A (формулировки, перевод запросов) → B (поиск P-E) → C (оценка)
bash benchmarks/term_dictionary_v1/scripts/run.sh x     # разведочный вариант без поздней стадии
```

- Стадия A — venv NAV (pymorphy3).
- Стадия B — venv лаборатории, кодировщики запросов на RTX с ограничением памяти (`TD_VRAM`, по умолчанию 25 %).
- Стадия C пишет `results_v1.json`; вариант `x` пишет `results_v1_nolate.json`.
