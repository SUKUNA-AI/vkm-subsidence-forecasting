## 1. Зачем

- [RESULTS_V1.md](RESULTS_V1.md) §4: после деплоя маршрутов указателя (`entity:PAGE`) и автора (`author:PAGE`) у
  скважин R@10 выросла с 0,244 до 0,988, у «работ автора» доля источников @10 — с 0,514 до 0,978.
- Но истина этих типов и маршруты опираются на один источник:
  - скважины (QT-C-B1…B8): истина — страницы локаторов каталога скважин, указатель собран из тех же каталогов;
  - авторы (QT-D-01…12): истина — источники работ автора по реестру, маршрут автора — авторы канона из того же реестра.
- Поэтому рост показывает, что маршрут воспроизводит свой реестр, а не качество поиска.
- Здесь истина другого происхождения: оценки страниц по их содержанию (текст и изображение страницы), без каталогов и
  реестра. Оценщики — агенты-LLM.
- Вопрос: по этим меткам вредит ли маршрут своему типу, не хуже ли он, даёт ли выигрыш (§7).

## 3. Пул

- **Пары «запрос × страница».** Берутся первые 10 различных `page_id` выдачи каждой из 4 систем по каждому из 20
  запросов. Дубликаты пары схлопываются. Глубина 10 совпадает с глубиной основной метрики.
- **Прежняя автоматическая истина** (локаторы каталога, источники реестра) не исключается и не добавляется: в пул
  попадает только то, что показали системы. Страница истины, которой нет ни в одной первой десятке, не оценивается.
- **Провенанс.** Системы и ранги каждой пары записываются в `pool_qt1.json` (вне git). В пакеты они не попадают.
- **Группы копий.** Union-find по парам «страница — дубль» (`duplicates`) и «страница — копия G1» (`copies`) всех хитов
  всех строк прогона. Группы нужны только для подсчёта (§7); оценивается каждая страница отдельно.
- **Контроль прогона:**
  - 80 строк, 0 ошибок, снимок 2d71e9e8, строка есть у каждой пары (запрос, система);
  - статусы маршрутов записываются в пул. Ожидается:
    - C: `object_ref.entity_route` = APPLIED у `hybrid` и `hybrid_g0`, OFF у `hybrid_noroutes`;
    - D: `author_route.status` = APPLIED у `hybrid` и `hybrid_g0`, OFF у `hybrid_noroutes`;
  - при расхождении работа останавливается до решения владельца.
- **Ожидаемый размер** — около 375 пар (C 155, D 220). Это пересчёт по прогону `1b20e03` тем же правилом, а не порог.

## 4. Пакеты

- **4 пакета**, каждый запрос целиком в одном пакете: все оценки одного запроса ставит один оценщик. Распределение
  детерминированное (LPT): запросы по убыванию числа пар (при равенстве — по ID), каждый — в пакет с наименьшим
  текущим числом пар (при равенстве — с меньшим номером).
- **В пакете только** `unit_id`, текст запроса и `page_id`. Систем, рангов, прежних меток, ID запросов набора нет.
- **Порядок (изменение решения «перемешать»).** Блоки запросов идут в случайном порядке (seed 20261013 + номер пакета),
  внутри блока единицы упорядочены по `page_id` (источник, затем страница). `unit_id` — `P<пакет>-<номер>` в этом
  порядке. Почему:
  - порядок по ID не несёт ни рангов, ни систем;
  - соседство страниц одного источника экономит чтение титульных страниц (D) и соседних страниц (C);
  - оценки страниц одного источника получаются согласованными.
- **Пакет сверки** `xc/xc_01.jsonl`:
  - 10 % пар каждого типа (с округлением), случайная выборка (seed 20261013);
  - свои `unit_id` (`X-<номер>`), тот же формат и тот же порядок блоков;
  - ключ хранится отдельно (`keys/xc_key.json`);
  - оценщик сверки не размечал основные пакеты, желательно другая модель;
  - если сверку не запускают, в итогах — NOT_RUN.
- **Памятка оценщика** — [LABELLER_INSTRUCTIONS_QT1_RU.md](LABELLER_INSTRUCTIONS_QT1_RU.md) (git). Её копия байт в
  байт — `packets/INSTRUCTIONS_RU.md`.

## 5. Разметка

Подробная рубрика — в памятке, её текст главный. Кратко:

- **Шкала 0–3 и UNKNOWN.**
  - C «скважина N»:
    - 3 — данные этой скважины на странице: строка таблицы, разрез, колонка, координаты, отметки с номером N, в том
      числе в разных ячейках;
    - 2 — содержательное упоминание, в том числе положение скважины на плане;
    - 1 — номер без содержания, или неясно, что N — скважина;
    - 0 — не про неё.

    Рудник не различается: в запросе его нет.
  - D «работы X»:
    - 3 — страница работы, где X автор или соавтор по самому документу (титул, шапка статьи, подпись, колонтитул);
    - 2 — X автор только части документа, а страница вне его части;
    - 1 — страница о его работе (цитата, запись в списке литературы); X как научный руководитель, редактор и т. п. —
      тоже 1;
    - 0 — иное.
  - UNKNOWN — когда в пределах бюджета чтения не хватает контекста.
- **Инструменты оценщика** — только MCP `get_page` и `get_page_image`. Запрещены поиск и сведения реестра
  (`get_source`, `get_work`, `find_works`, `find_entities` и все остальные инструменты), каталоги, файлы бенчмарка,
  чужие пакеты и ответы.
- **Бюджет чтения:**
  - C — страница единицы и соседние ±1 того же источника (шапка таблицы, подпись, продолжение);
  - D — страница единицы, две первые страницы источника и ещё до 3 страниц того же источника: в сборниках авторы
    стоят у начала статьи. Всего не больше 5 страниц кроме самой.
- **Оценщику не дают:** этот протокол, пул, прогоны, ключи, автоматическую истину, каталоги, реестр, оценки других
  пакетов.
- **Ответ** — `judgments/packet_NN.jsonl` (сверка — `judgments/xc_01.jsonl`). Одна строка JSON на единицу: `unit_id`,
  `grade` (0–3 или `"UNKNOWN"`), `rationale` (≤ 200 знаков), `pages_read` (вместе со страницей единицы).
- **Один проход.** До приёма исправляется только ошибка записи, не оценка.
- **Источник метки** — `LLM_AGENT_QT1` (сверка — `LLM_AGENT_QT1_XC`), статус CANDIDATE, основание POOL_JUDGMENT.

## 6. Приём (`pool_qt1.py ingest`)

- **Формат.** Каждая строка — JSON с четырьмя полями:
  - `grade` ∈ {0, 1, 2, 3, `"UNKNOWN"`};
  - `rationale` — строка ≤ 200 знаков;
  - `pages_read` — список корректных `page_id`, в нём есть страница единицы;
  - `unit_id` — каждая единица пакета ровно один раз, посторонних нет.

  Нарушение формата — пакет не принимается: оценщик исправляет запись, не оценку.
- **Бюджет чтения.** Нарушение (чужой источник; у C — страница дальше ±1; у D — больше 5 страниц кроме самой) — это
  отступление: метка сохраняется, единицы и коды попадают в итоги.
- **Результат:**
  - `qrels_qt1_pooled.tsv` и `qrels_qt1_xc.tsv` (git): только ID, оценка, источник метки, пакет, число прочитанных
    страниц;
  - обоснования (`rationale`) остаются вне git: в них может быть текст страниц.

## 7. Метрики и решение

- **Основная метрика — nDCG@10**, замороженная `vkm_corpus.retrieval_lab.metrics.ndcg_at`: выигрыш = оценка,
  дисконт log2, идеал — по всем оценённым группам запроса.
  - Берутся первые 10 различных `page_id` системы.
  - Единица ранжирования — группа копий (§3). Оценка группы для запроса — максимум оценок её страниц.
  - Позиция, группа которой уже встретилась выше, остаётся в выдаче с выигрышем 0: повтор копии занимает место.
- **Вторичная метрика — P@10** (`metrics.precision_at`): доля из 10 мест с группой оценки ≥ 2.
- **UNKNOWN.** В основном расчёте UNKNOWN = 0. Проверка чувствительности: UNKNOWN = 2, вердикт пересчитывается и
  показывается рядом. Основной вердикт — при 0.
- **Исключения.** Запрос без группы с оценкой > 0 исключается из средних и тестов своего типа и перечисляется.
- **Порог UNKNOWN.** Если UNKNOWN больше 20 % пар типа (основные метки), вердикт по типу не выносится, числа даются
  описательно.
- **Тесты.** Единица — запрос.
  - Парный тест со сменой знаков, двусторонний: `metrics.paired_randomization`, 10 000 перестановок, seed 20260928.
  - Перцентильный бутстреп 95 %: `metrics.bootstrap_ci`, 10 000, тот же seed.
- **Семейство Холма** — 4 сравнения nDCG@10: C и D × (`hybrid − hybrid_noroutes`, `hybrid − bm25`).
- **Правило** — по маршруту своего типа (C — указатель, D — автор), Δ = `hybrid − hybrid_noroutes`. Применяется сверху
  вниз, по неокруглённым значениям:
  1. UNKNOWN > 20 % пар типа → ВЕРДИКТ НЕ ВЫНОСИТСЯ;
  2. Δ < −0,05 и p < 0,05 без поправки (к вреду — осторожно) → ВРЕД;
  3. Δ > 0 и p_Холм < 0,05 → ВЫИГРЫШ;
  4. нижняя граница ДИ ≥ −0,05 → НЕ ХУЖЕ;
  5. иначе → НЕ ОПРЕДЕЛЕНО.

  `hybrid − bm25` идёт в семейство Холма, но категории вердикта не получает.
- **Мощность.** У C 8 запросов. Наименьший p двустороннего теста со сменой знаков ≈ 2/2⁸ ≈ 0,008, после Холма на 4 —
  около 0,031. Поэтому ВЫИГРЫШ у C возможен, только если все ненулевые разности одного знака и их почти 8.
- **Описательно (без вывода):**
  - P@10 для тех же 4 сравнений, свой Холм на 4;
  - `hybrid_g0 − hybrid` (nDCG@10);
  - nDCG@10 без групп копий (каждая страница сама по себе) — чувствительность к правилу групп;
  - judged@10 каждой системы (контроль, ожидается 1,0);
  - согласие с прежней автоматической истиной:
    - C — доля страниц-локаторов пула с оценкой ≥ 2 и число страниц с оценкой ≥ 2 вне локаторов;
    - D — доля страниц источников реестра с оценкой 3 и число страниц с оценкой 3 вне этих источников;
  - nDCG@10 всех систем по каждому запросу;
  - отступления приёма (§6).

## 8. Сверка вторым оценщиком

- **Пары** пакета `xc`: основная оценка против оценки сверки.
- **Меры** (`pool_t1.agreement`): exact, ±1, κ без весов, κ линейный и квадратичный, α Криппендорфа (ординальная).
  Бинарно (≥ 2) — exact и κ.
- **UNKNOWN.** Пары, где UNKNOWN хотя бы у одного оценщика, исключаются и считаются отдельно.
- **Статус.** Сверка описательная, в подсчёт метрик метки сверки не входят. Если κ линейный < 0,4, итоги называют метки
  ненадёжными, а вердикты — условными (порог — MODEL_CHOICE).

## 9. Ограничения

- **Метки** ставят LLM, не люди; сверку — тоже LLM.
- **Идеал nDCG** считается по пулу 4 систем. Релевантная страница, которой не показала ни одна система, не
  учитывается. Страницы, найденные только маршрутом, оцениваются наравне с остальными. Если маршрут приносит
  релевантное, это засчитывается, и так и должно быть.
- **Мощность мала:** C — 8 запросов, D — 12. При широком ДИ «НЕ ХУЖЕ» недостижимо.
- **Скважины** — по номеру без рудника, как в запросе. Тождество скважин не устанавливается.
- **Авторы** определяются по имени в документе (фамилия и инициалы), а не как установленные личности.
- Всё это сигнал поиска по канону `AUTO_EXTRACTED_UNREVIEWED`, не evidence.
