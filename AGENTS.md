# ВКМ / СКРУ-1 — правила работы агентов в PUBLIC

Редакция: **07.11.2026**. Это правила продолжения, не отчёт о новых вычислениях. Версии, результаты и границы готовности определяются документами состояния и receipts конкретных запусков. Дата правил не является датой научного результата.

## 1. Цель и масштаб

Развивать существующую пространственно-временную модель: полную геологическую структуру, механику, физические поля, взаимодействия и микроядерное представление. Результат — исполнимые семейства связанных физических миров и их развитие во времени. Поиск, инфраструктура и документация обслуживают эту цель.

Общий предмет — ВКМ; целевые рудники — СКРУ-1/2/3. Текущий интегрируемый объект — **всё поле СКРУ-1** с необходимым физическим окружением и неодинаковой детализацией. Сведения других участков сохраняют атрибуцию либо применяются через Transfer. Материалы БКПРУ-4 используются; план его шахтного поля без изменения задачи не строится.

Блок 201, ПЛ12, скважины 75/128 — частные объекты, не представители рудника по умолчанию. Утверждённый участок специальной части сохраняется, но не сужает общую модель. Локальная задача должна указывать проверяемый механизм и связь результата с общей сборкой.

Полнота структуры не означает полной измеренности. Для существенного механизма указать: рассчитывается, задан внешним полем, редуцирован, исключён с обоснованием или ещё не реализован. Механическая постановка выбранного семейства должна быть замкнута.

Названия фиксированы:
- диплом — «Горные и маркшейдерские работы при разработке Верхнекамского месторождения»;
- специальная часть — «Алгоритм прогнозирования оседаний земной поверхности на ВКМ на основе маркшейдерских измерений».

Обучение нейросетей, подбор прогнозной модели и прогнозный benchmark сейчас вне задачи. Геологические и механические ансамбли не требуют ML.

## 2. Активные правила и история

Внутри проектной документации текущая явная задача владельца определяет scope; этот файл содержит общие правила, PRIVATE `AGENTS.md` — ограничения закрытых данных. Системные инструкции среды и права доступа не отменяются документами проекта.

`CLAUDE.md` — указатель на этот файл, не копия правил. `docs/planning/PROMPT_GPT_AGENTS_RU.md` — маршрут начала работы, не отдельная политика. При изменении правил проверить согласованность этих файлов и PRIVATE-инструкций.

D-18/D-19 сохраняются в `docs/governance/PHASE1_DESIGN_DECISIONS_RU.md` как история решений. Действующие роли: **Ansys — основной детальный геомеханический решатель; OGS + MFront — независимая численная сверка; World-0 — микроядерное редуцированное представление; gprMax — отдельный оператор наблюдения GPR.**

Ограничения прежних частных этапов «только 2D», «без графа», «пауза решателей», «ждать GIS предприятия» не распространяются автоматически на текущую задачу связанных миров. Это не открывает ML и не отменяет разрешений на ресурсы, доступ и публикацию.

Полная спецификация при наличии и принятии: `docs/specifications/VKM_COUPLED_WORLD_SPEC_RU.md` (`VKM-CW-SPEC-001`). Проверить версию; файл из переписки не считается опубликованным. При отсутствии работать по текущей задаче, не возвращаясь к старому плану.

## 3. Продолжение от существующего результата

В начале установить доступные checkout, ветки/SHA, окружение и незакоммиченные изменения. Не предполагать sibling-layout или отсутствие чужой работы. PRIVATE находить через `VKM_RESOURCES_ROOT`; недоступность обозначать явно.

Прочитать актуальную часть `README.md`, `PROJECT_STATE_RU.md` и адресный индекс/receipt. Опора сборки 01.11.2026 — `docs/implementation_work/SKRU1_WHOLEMINE_CHECKPOINT_20261101_RU.md`; при наличии использовать следующий принятый результат в своей области. В PRIVATE — `CURRENT_STATE_RU.md` и индекс нужной поставки.

Старые разделы состояния и `CLOUD_TO_LOCAL_PHASE2_HANDOFF_RU.md` — исторические сведения и команды. Проверять дату и scope раздела, а не слово «текущий». Handoff читать для адресного восстановления; не клонировать, не устанавливать runtime и не перечитывать весь корпус автоматически.

Поздний receipt замещает прежний статус только при совпадении объекта, версии, входов и области. Старый NOT_RUN не отменяет позднее исполнение; локальный PASS не закрывает всё направление. Receipt подтверждает запуск, но не выдаёт новое разрешение.

Определить конкретное незавершённое звено общей модели и следующий исполнимый результат. Переиспользовать принятые геометрию, ансамбли, законы, тесты и расчёты. Не создавать новый общий аудит, реестр или backend, когда достаточно существующего модуля.

Повтор оправдан изменением зависимости, дефектом, выходом за область применимости или названной новой проверкой. Указать, что изменилось и что добавит повтор. Новая сессия и возраст файла сами по себе не являются основанием.

## 4. Знание, сценарий и расчёт

```text
источник → извлечение и проверка → evidence → интерпретация → WorldSpec
  → доопределённый PhysicalWorld → представление → совместная траектория
  → оператор наблюдения → сравнение
```

WorldSpec хранит знание и UNKNOWN. PhysicalWorld — отдельная исполнимая гипотеза. Интерполяция, геостатистика и сценарное достраивание допустимы в расчётном слое, но не переписывают первичные записи. Прежняя формула «мир без интерполяций» не запрещает реконструкцию.

Разделять FACT, DERIVATION, INTERPOLATION, MODEL_CHOICE, ENGINEERING_ASSUMPTION, ANALOGUE, UNKNOWN; отдельно — проверку извлечения, исполнение и научный допуск. Хеш/схема/canonical не повышают AUTO_EXTRACTED_UNREVIEWED до факта. Агентская проверка не является человеческой.

У числа есть источник/локатор либо обоснование допущения, единицы, scope, scale и пространственно-временная опора. Нет данных ≠ ноль; нет сведений ≠ однородность; проектное ≠ выполненное; норматив ≠ измерение; оцифровка/интерполяция ≠ первичное наблюдение.

UNKNOWN в исходном знании сохраняется. Для расчёта создаётся связанное сценарное доопределение. Противоречивый сценарий не запускать; его неполнота не блокирует независимые допустимые задачи. Полный производственный архив предприятия не является обязательным условием всей сценарной работы.

Transfer или решение владельца допускают использование гипотезы, **но не превращают ANALOGUE/MODEL_CHOICE в FACT**. Изменение доказательного статуса требует нового свидетельства и проверки. Противоречия сохранять отдельными трактовками, не усреднять молча.

Изменение сетки/решателя — изменение представления, не новый физический мир. Оно не устраняет неопределённость геологии.

## 5. Развивать C1–C5 совместно

- **C1:** геологические области, толщи, пласты, междупластья, контакты, нарушения, опоры и альтернативы.
- **C2:** поля материалов, определяющие законы и совместимые параметры, включая реологию, закладку и контакты.
- **C3:** начальные напряжения и необходимые поля, предыстория, память и границы.
- **C4:** выемка/закладка, порядок и интервалы событий, изменение состояния областей.
- **C5:** механические, контактные и по активной гипотезе гидравлические/тепловые связи, межпластовые и межобластные взаимодействия.

Не откладывать C5 до неопределённого «завершения всей геологии». Интеграционная поставка сохраняет охват всего текущего объекта, пусть с разной детализацией; покрытие СКРУ-1 не выдавать за покрытие других рудников.

Использовать `src/vkm_world`, `evidence/`, `catalogues/`, схемы и существующие индексы. Проверять наличие сущности перед добавлением; не создавать второй канон или provenance-слой.

Архитектура: `docs/worldspec/WORLD_SPEC_VNEXT_RU.md`, `docs/worldspec/WORLD_KERNELS_DESIGN_RU.md` и связанные документы теории v0.2. Читать адресно, не весь комплект перед каждым действием.

## 6. Поиск и сведения соседних участков

Искать недостающий механизм, поле, параметр, связь, событие или разрешение конфликта. Сначала проверять каталоги, локаторы и журналы охвата. При доступном корпусном MCP использовать навигацию и адресное чтение страниц/таблиц/рисунков. Недоступный поиск не имитировать; выдача — кандидат, не доказательство.

Не закрепляться на одном блоке, авторе или наборе страниц. Охватывать нужные процессы, литологии, масштабы, рудники и эпохи; не вводить квоту новых источников. Старый релевантный первоисточник переиспользуется.

Повтор чтения оправдан новым вопросом/локатором, проверкой или конфликтом. Цикл заканчивается новым/уточнённым ограничением, совместимым пакетом параметров либо проверенным отрицательным результатом на перечисленных маршрутах. Пересказ прежнего не считается продвижением; отказ сервиса не означает отсутствия данных в корпусе.

Различать произведение, файл, эксперимент и пересказ. Копии ряда не независимы; равные числа не доказывают дублирование. Scope проверять для каждой записи.

В существующем `Transfer` сохранять донора/локатор, литологию, масштаб, условия, форму закона и единицы, совместимый набор параметров, цель и ограничения. Перенос закона, параметров и оператора отклика — разные решения. Не смешивать коэффициенты несовместимых калибровок; эффективный параметр модели соседа не объявлять свойством нашей породы.

Существенные переносы проверять альтернативными донорами/правилами и, где допустимо, вариантом без заимствования. Близость не доказывает совместимость. Перенос знания не создаёт физическое ребро: ему нужны геометрия, границы и закон связи.

## 7. Поля, геометрия и микроядра

Разделять native-геометрию, документированное преобразование и DISPLAY_ONLY. Визуально изменённые координаты не являются расчётными. Известный datum продукта не устанавливает историческую связь с отметками рудника/устьев; UNKNOWN-смещение не заменять нулём. Контур блока не превращать целиком в пустоту.

Разделять геометрию, свойства, поля состояния, память, события и производные. Поле имеет носитель, координаты, единицы, закон, начальное состояние и связи. Неактивные поля не заполнять фиктивными нулями; пространственные реализации согласовывать с геологией, не с независимым шумом по умолчанию.

Микроядро — редуцированная подсистема, не автоматически блок или конечный элемент: `K_i={G_i,Θ_i,x_i,m_i,P_i,B_i,U_i}`. Разбиение зависит от задачи, горизонта и допуска. Для интерфейса определять механизм, носитель, площадь, ориентацию/базис, единицы, закон и активность; механический порт передаёт необходимые нормальные и касательные компоненты.

Совместно решать равновесие и эволюцию памяти. При выемке/закладке, контакте и повреждении определить изменение областей/связей, перенос массы, энергии и состояния. Обнуление отображаемого перемещения не сбрасывает физическую предысторию.

Не учитывать толщу дважды — явными ядрами и включающим её K/G. После изменения геометрии, закона или контакта проверять применимость оператора. Дальние связи не обрезать ради GPU без оценки ошибки; нелинейную связанность не заменять суммой независимых ответов без обоснования.

Split/merge и редукцию проверять по внешнему отклику, балансам и памяти. Точность поверхности не доказывает точность напряжений в целиках. Не исправлять знаки взаимодействий ради удобной теоремы монотонности.

## 8. GPU-ансамбли

Различать продукты: **L1 — реализации геологии/материалов/историй; L2 — материальные точки и локальные отклики; L3 — связанные траектории микроядер/полей; L4 — детальный FEM.** Это классификация, не требование переименовать API. Их счётчики и выводы не смешивать.

Предметный прирост — L3 с адресной проверкой L4. Готовые ансамбли использовать в своей области; новые нужны для отсутствующих семейств, покрытий, связей или изменённых входов, а не для круглого количества прогонов. Сначала разнообразие физических семейств, затем сгущение выборки; геология, параметры и история должны быть совместимы.

Параллелить независимые миры. Ядра одного мира сохраняют совместный баланс, историю и память. Пакетировать совместимые топологии/законы, учитывать индивидуальные события и активность. Не менять физику ради одинакового shape.

При несошедшемся шаге откатывать пробную память, сохраняя принятое состояние. Записывать world/representation/run id, хеши, seeds, runtime, устройство, precision, допуски и checkpoints. Детерминизм каталогов не гарантирует побитовую тождественность разных GPU.

До серии проверить VRAM/RAM/диск, лицензии, задачи, бюджет и остановку. Использовать общую GPU-блокировку (`work/gpu.lock` либо принятый host-level механизм), не независимые замки разных checkout. Не запускать конкурирующие тяжёлые GPU-задачи и не удалять чужие процессы/locks.

Различать недопустимые входы, неподдержанный режим, несходимость, инфраструктурный отказ и физическое событие. Неудачи не скрывать; несходимость не доказывает невозможность мира. GPU-исполнение подтверждать журналом, ускорение — измерением.

## 9. Полномочия: без лишних остановок и самовольных запусков

Задача на аудит/план/документы **не разрешает тяжёлые симуляции**. В порученной реализации геологии, механики или ансамбля относящиеся к ней интерполяция, сценарное достраивание, Monte Carlo, чувствительность и расчёты на разрешённом runtime входят в работу в согласованных пределах. Не запрашивать разрешение на каждую операцию лишь из-за старой метки «Phase 2+».

До серии определить вопрос, входы, артефакты и проверки. Недостаток разрешения/ресурса блокирует соответствующий запуск, не независимую работу. Подготовленный deck не означает выполненный расчёт.

Отдельно согласовать выход за scope/бюджет, платные ресурсы, тяжёлые зависимости/общие runtime, production/канон/CORE/EDGE, раскрытие данных, публикацию/merge и ML/прогнозный benchmark. Ограничения среды не обходить.

Установочная лестница нужна только для нового runtime или неподтверждённой функции. В проверенном окружении выполнять адресные проверки изменений и регрессии, не снова установку и gravity-case. Синтаксис сверять с установленной версией и официальной документацией; Context7 — только при доступности.

## 10. Проверки и интерпретация

До серии задать целевые величины и допуски. Проверять применимые балансы, единицы/знаки, шаг времени, сетку, границы, контакты, память и restart. Представления сравнивать на одном PhysicalWorld. CI, exit=0 и schema READY не равны научному допуску или field validation.

Отбор миров по наблюдениям — использование данных, даже без ML. Разделять его с независимой проверкой; сохранять происхождение рядов, `valid_time`/`available_from`. Исторический прогноз требует `available_from ≤ t0`; реконструкция с поздними источниками маркируется ретроспективной.

Test/evaluator truth запрещено использовать для подбора параметров, семейств, порогов и выбора реализации. Это не становится допустимым после «gate». Синтетика не заменяет натурную проверку.

NROY требует объявленных правил и обоснованных допусков; без них сравнение диагностическое. Диапазон не превращать автоматически в равномерную вероятность. Частота исхода в ансамбле не является вероятностью фактического исхода без обоснованной меры. Не называть сценарий восстановленной историей или валидированным цифровым двойником.

## 11. Данные и безопасность

PUBLIC (`vkm-subsidence-forecasting`) хранит код, схемы, synthetic tests и public-safe проекции. PRIVATE (`SUKUNA-AI/vkm-subsidence-forecasting_resourses`) — оригиналы, полный evidence, закрытую геометрию и отдельные расчётные поставки. Модельные результаты не смешивать с canonical evidence.

Оригиналы не менять. Цитаты, OCR-дампы, закрытые геоданные, научные бинарники и полные raw-результаты в PUBLIC не публиковать. Использовать `scripts/build_public_catalogues.py`, `docs/reset_2026_09/run_kit/tools/publish_reports.py` и leak/sync-проверки. Удаление `quote` и прохождение порога совпадения 25 слов не гарантируют отсутствия иной закрытой информации.

**Разрешение владельца на чтение:** агентам проекта разрешено без дополнительных запросов читать, искать, извлекать, обрабатывать и анализировать **весь доступный корпус PUBLIC и PRIVATE через облачные AI-модели**, включая VKM-SRC-252, неопубликованные работы, полные тексты, цитаты, OCR, страницы, рисунки, таблицы, геоданные и научные расчётные материалы. Это разрешение распространяется на передачу необходимого содержимого в рабочий контекст подключённой облачной модели; на каждый файл отдельно согласие не запрашивать. Доступность источника и технические права среды проверяются, но старый проектный запрет на чтение отменён. **Чтение и анализ не равны публикации:** граница PUBLIC/PRIVATE, ограничения на публичную выкладку, секреты и правила исходных данных сохраняются.

Пути — относительно проекта/разрешённого корня. Секреты, `.codex/`, host-local конфиги, venv и дампы не коммитить. Временные файлы — git-ignored `work/` или согласованный каталог. Git-настройки и байты оригиналов не менять ради удобства.

Попытки писать отдельно либо через проверенную ротацию. **До очистки** проверить executable, deck, входы, права и checkpoint. Ошибка конфигурации не удаляет прежние результаты. Хранить входы, команду, версии, логи, exit code, проверки и receipt с хешами; архивы не переписывать.

## 12. Git, legacy и завершение

Тематическая ветка, коммиты по явным путям, PR на русском. Не трогать чужие изменения, не делать force-push, не переписывать историю и не сливать в main без указания владельца. Отказы cloud LFS/tag policy не обходить; бинарную публикацию передавать разрешённой workstation-среде.

`legacy` и frozen-релизы не изменять. `SKRU1_ACTUAL_DATA_TABLES_v1`, `inputs/bootstrap/**`, старые v3.x reconstructed/model-ready/EDA/target-пакеты и Physical World v1 не являются current evidence. `scripts/build_evidence_from_legacy.py` используется только для предусмотренного извлечения исходных записей с provenance, не возврата отозванных моделей. Исторический generic solver-test не является моделью рудника.

Выполнить затронутые тесты и требуемые проверки по `docs/development/OFFLINE_CHECKS.md`/действующему workflow. Существующие команды из PUBLIC в подготовленном окружении:

```bash
python -m pytest -q tests/world
python scripts/verify_canonical_repository.py
```

Для PRIVATE-сверок настроить `VKM_RESOURCES_ROOT`. Читать отчёт, не только exit code: отсутствие PRIVATE, LFS-байтов, GPU, лицензии или сервиса может означать NOT_RUN. Не ослаблять тест ради PASS. Непроверенная конфиденциальность блокирует соответствующую публикацию, не независимую работу.

Итог: закрытый пробел; новые области/поля/связи; переиспользованное; файлы; проверки, NOT_RUN и ограничения; следующий шаг. Отчёт, картинка, число сценариев и CI не заменяют физический результат. Документационная задача поставляет файлы, без выдуманных запусков.
