# Привязка моделей реестра формул к объектам формул корпуса

Дата: 13.10.2026. Каталог: [model_formula_links.csv](../../catalogues/mathematics/model_formula_links.csv)
(PUBLIC-копия PRIVATE `11_evidence_vnext/canonical/FORMULAS/MODEL_FORMULA_LINKS.csv`). Сборка:
[build_model_formula_links.py](../../scripts/build_model_formula_links.py), правило `model_formula_links_v1`. Реестр
моделей — [каталог математического фундамента](MATHEMATICAL_FOUNDATION_CATALOGUE_RU.md).

## Что связано

Каждая модель реестра `MM-*` (279 строк) связана с объектами формул канона корпуса (`VKM-SRC-NNN:pNNNN:m<12hex>`,
снимок `snap-20261007T103222Z-2d71e9e8`). Одна строка каталога — одна связь «уравнение модели → формула в книге»:
- единица — модель × источник × номер уравнения. Номер берётся из записи evidence (`equation_number`, «формулы
  (3.1)-(3.5)» разворачиваются). Запись без номера — отдельная единица, она сопоставляется только по форме;
- источники реестра без страницы (TEXTBOOK, EXT-SRC, источник без записи и локатора) — строки `NOT_FOUND` с причиной.

В каталоге только ID и числа: `link_id`, модель, номер, источник, `vn_ids`, страница (`page_index`, `page_label`),
`formula_id`, печатный номер NAV, статус, мера формы, смещение страницы, метод, проверка, группа повторов
(`shared_group_id`, `shared_n_works` из `shared_formulas`). LaTeX корпуса и цитаты в PUBLIC не попадают.

## Правило

1. **Основание страниц.** `pdf_page` записи — физическая страница с 1; `page_index` канона — тоже. Это проверено на
   совпадениях. Смещение источника принимается только доказанным: не меньше трёх единиц на одном ненулевом сдвиге
   и доля не меньше 0,6. Таких источников нет. Кандидаты — формулы страниц `pdf_page ± 1`.
2. **Номер.** Номер уравнения NAV (`formula_context.equation_number`) или метка канона после нормализации совпадает
   с номером записи.
3. **Форма.** Сравниваются канонические токены ключа NAV `formula_keys`. Перед сравнением:
   - кириллица и латиница сводятся по сходству начертаний, в индексах учтены ошибки OCR (Г→Γ, Л→JI, П→Π);
   - `tg` и `tan` считаются одним знаком; дробь читается как косая черта; штрихи, скобки и оформление OCR
     (`\upsigma`, `array`) не учитываются;
   - текстовая форма реестра (`equation_plain`) приводится к LaTeX.

   Мера — максимум из четырёх: доля общих токенов; та же доля по основным буквам (если OCR исказил индексы); доля
   при переименованных обозначениях (для длинных формул); вхождение одной формы в другую (для разбитых и склеенных
   объектов). Форма из нескольких уравнений сравнивается и по частям. Пороги и веса — MODEL_CHOICE, они записаны
   в receipt.
4. **Статус.**

   | Статус | Условие |
   |---|---|
   | `EXACT` | номер совпал, форма ≥ 0,5 |
   | `NUMBER_MATCH` | номер совпал, а форма далека (OCR) или в реестре нет формы этого номера (`reason` NO_REGISTRY_FORM) |
   | `FORM_MATCH` | форма ≥ 0,8, номера нет или он другой |
   | `CANDIDATE` | форма ≥ 0,6 |
   | `NOT_FOUND` | связь не найдена; причина — в `reason` |

5. **Проверка спорных.** Все `NUMBER_MATCH`, `FORM_MATCH`, `CANDIDATE` и 20 самых слабых `EXACT` агент проверил
   по тексту: LaTeX канона против формы реестра, номер NAV и контекст «где…». Картинки страниц не понадобились.
   Решения лежат в PRIVATE `MODEL_FORMULA_LINK_CHECKS.csv` и входят в сборку:
   - `check` — CONFIRMED, REJECTED или UNSURE, `check_note` — причина;
   - если подтверждена другая формула окна, сборка выбирает её (`method` …`+REVIEW_PICK`).

## Как пользоваться

- API `GET /v1/nav/formula/{id}` и MCP `get_formula_context` отдают поле `registry_models`. Это модели, связанные
  с формулой: `model_id`, `name`, `equation_ref`, `match_status`, `check`. Строки REJECTED и `NOT_FOUND` не
  показываются. Без пакета каталогов поле равно `null`.
- `reconstruct_topic`: у каждой модели есть `formula_ids` — до восьми связанных формул, лучшие первыми; в markdown
  показаны три.
- Пересборка: `VKM_RESOURCES_ROOT=<PRIVATE> VKM_API_URL=<API> python scripts/build_model_formula_links.py`
  (`--offline` — по кэшу ответов в `work/`), затем `scripts/build_public_catalogues.py` и
  `scripts/build_record_routing.py`.

## Ограничения

- Это навигация, а не evidence. Связь «уравнение модели ↔ формула в книге» не проверяет закон, не устанавливает
  применимость к СКРУ-1 и не повышает статус модели. Строки — `AUTO_EXTRACTED_UNREVIEWED` и `DERIVATION`.
  Проверка агента (`check`) — не рецензия человека.
- Связь опирается на номер и страницу. Если в реестре нет формы (208 строк `NUMBER_MATCH`), проверялось только
  соответствие формулы теме модели.
- Номера NAV ошибаются: стоят у соседних формул, сдвинуты на единицу, распознаны OCR неверно (3.80 вместо 8.80).
  Совпадение формы без номера (`FORM_MATCH`) у коротких формул слабее.
- В каноне у одной формулы бывает два объекта: два текстовых слоя OCR (GLM-OCR и PaddleOCR-VL). Привязан один —
  тот, у которого есть номер.
- `POST /v1/objects/query` (API 0.1.0) не отдаёт `next_cursor` для одного вида объектов. Сборка делит диапазон
  страниц, пока ответ не станет меньше лимита; страниц с обрезанным ответом нет.
