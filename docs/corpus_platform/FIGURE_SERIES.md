# Оцифрованные графики корпуса: NAV-часть `figure_series`

Запрос пользователя (29.09): оцифровка графиков корпуса должна работать внутри платформы, а результаты можно
смотреть и использовать. Прототип агента FD ([отчёт](../implementation_work/AGENT_FD_FIGURE_DIGITIZATION.md),
квитанция [figure_digitization_v0.json](receipts/figure_digitization_v0.json)) стал детерминированной стадией сборки
навигационного слоя (агент FD2): часть `figure_series`, правило `figure_series_v1`, инструменты MCP
`find_figure_series` и `get_figure_series`, галерея для просмотра. Квитанция —
[nav_figure_series.json](receipts/nav_figure_series.json).

**Статус.** Каждое значение — `DERIVATION` из публикации, `review_status = AUTO_EXTRACTED_UNREVIEWED`, с полушириной
погрешности. Это не наблюдения проекта и не evidence. Модельный результат и измерение автоматически не различаются
(`series_nature = UNCLASSIFIED`; слова «расчёт», «прогноз», «МКЭ» в подписи ставят только флаг
`MODEL_HINT_IN_CAPTION`). Участок (рудник) наследуется от источника (`source_site_scope_raw`, флаг
`SCOPE_INHERITED_FROM_SOURCE`) и не уточняется: VKM-SRC-034 остаётся БКПРУ-4 / безымянным участком, а не СКРУ-1.
Доступность во времени — дата публикации работы (`works_availability`: только год — последний день года; года нет —
`UNKNOWN`). В WorldSpec значение попадает только через запись evidence с проверкой по печатному рисунку.

## 1. Почему NAV-часть и где она собирается

- **NAV-часть, а не отдельный набор.** Ключ — снимок канона, ID — канонические ID рисунков, страниц и источников. Статус
  тот же, что у слоя (DERIVED, `AUTO_EXTRACTED_UNREVIEWED`). Путь выдачи тот же: `nav build` → `manifest.json` →
  `store.pack` → `nav.duckdb` → `NavStore` → `/v1/nav/*` → MCP. Отдельный каталог потребовал бы второго механизма
  выкладки, выдачи и ночных проверок.
- **Только WORKSTATION.** Маршрут A читает исходный PDF:
  - состояние отсечения путей (`get_drawings(extended=True)`): путь, которого читатель не видит, отбрасывается;
  - прямоугольники слов текстового слоя.

  Ни того, ни другого нет в `VECTOR_PATHS_JSON` конвейера (пути без clip) и в канонических блоках (без слов). PDF лежат
  только в клоне PRIVATE на WORKSTATION (`$VKM_RESOURCES_ROOT`), на CORE их нет — так же, как у `nav outlines`.
- **CORE получает готовые датасеты байт в байт.** `python -m vkm_corpus.navigation.figure_series import` сверяет
  снимок, правило, sha256 и число строк, наличие ID рисунков в `canonical.figures` и дописывает записи в
  `manifest.json` каталога NAV. На CORE без клона PRIVATE часть даёт `SKIPPED_NO_INPUT` — её там не собирают.
- **Каждый PDF сверяется с каноном.** Если sha256 файла не совпадает с `sources.source_sha256`, рисунки источника
  получают статус `SOURCE_HASH_MISMATCH` и не оцифровываются. Если файла нет — `SOURCE_UNAVAILABLE`.

Сборка на WORKSTATION (WSL, venv с PyMuPDF 1.28.2, OpenCV и Tesseract 5.5.3; память ограничена):

```bash
export VKM_RESOURCES_ROOT=<клон PRIVATE>
systemd-run --user --scope -p MemoryMax=12G -p MemorySwapMax=0 \
  vkm-corpus nav build --duckdb <копия DuckDB снимка> --out <каталог сборки> --part figure_series \
    --option figure_series.workers=6 --option figure_series.raster_pages=fd_monitoring
```

Опции части: `resources` (вместо `$VKM_RESOURCES_ROOT`), `workers` (процессы, по источнику на процесс), `ocr`
(`auto` | `off`), `sources` (только эти источники; такая сборка частичная и импортом отклоняется), `raster_pages`
(второй набор, §5: `fd_monitoring` — 38 страниц прогона FD, список в коде, — или JSON-файл). Две сборки одного кода
в одной среде дают одинаковые sha256 всех датасетов. Число процессов на результат не влияет. Полная сборка снимка
738eebee идёт около 4 минут (6 процессов, до 12 ГиБ).

Перенос на CORE (выполняет координатор; каталог NAV снимка копируется, в копию импортируется сборка, каталоги
меняются местами):

```bash
rsync -a <каталог сборки>/ core:$VKM_DATA_ROOT/tmp/figure_series_v1/<snapshot_id>/
cp -a $VKM_DATA_ROOT/derived/navigation/<snapshot_id> $VKM_DATA_ROOT/derived/navigation/<snapshot_id>.fs
cd /srv/vkm/infra/core && docker compose --env-file .env --profile jobs run --rm -T --entrypoint python vkm-job \
  -m vkm_corpus.navigation.figure_series import --bundle /data/tmp/figure_series_v1/<snapshot_id> \
  --nav-dir /data/derived/navigation/<snapshot_id>.fs --canon-duckdb /data/duckdb/vkm_corpus.duckdb --pack
# затем <snapshot_id> → <snapshot_id>.prev, <snapshot_id>.fs → <snapshot_id>; образ api/mcp с этим кодом
```

Импорт без `--pack` только копирует датасеты и дописывает манифест; `--dry-run` показывает план. Импорт отказывает
(код 2) при другом снимке, другом правиле, частичной сборке, неполном растровом наборе, расхождении sha256 или числа
строк и при ID рисунков, которых нет в каноне. Опция-путь попадает в манифест CORE только именем файла.

## 3. Маршрут A как стадия: что добавлено к прототипу

- **Повёрнутые страницы** (fd-0.1.3). PyMuPDF отдаёт текст, пути и clip в неповёрнутой системе страницы. Область
  переводится в неё для отбора, а все координаты — обратно через `page.rotation_matrix` в PAGE_PT_TL показываемой
  страницы. В этой же системе рамки канона и `get_pixmap(clip=…)` помощника OCR. Прототип такие страницы пропускал.
- **Логарифмическая шкала — только при размахе меток ≥ 3 раз** (fd-0.1.4). На узком диапазоне вдали от нуля (годы
  1998–2003, 77 900–78 020) логарифмическая и линейная подгонки неразличимы, и log10 выигрывал случайно. Это делало
  ось лет «не временем»: 20 осей снимка.
- **PDF читается один раз на источник**, источники идут параллельно (`spawn`), вывод сортируется. Счётчик вызовов OCR
  убран из провенанса осей, чтобы не зависеть от порядка.
- **Флаги качества.** Пороги записаны в конфигурации (`config_hash`). Первые шесть строк таблицы — **подозрительная
  калибровка** (`SUSPECT_FLAGS`): эти флаги ставятся на рисунок и на все его ряды, фильтр `clean_only` поиска такие
  ряды убирает. Значения при этом не меняются: флаг говорит, что им нельзя верить без проверки по рисунку.

  | Флаг | Уровень | Смысл |
  |---|---|---|
  | `AXIS_LABELS_INSIDE_PLOT` | рисунок, ряды | подписи оси стоят внутри области графика и не привязаны к засечкам: за ось принят столбец подписей кривых, значения легенды или номера узлов |
  | `AXIS_LABELS_DETACHED` | рисунок, ряды | оси x и y взяты с разных панелей многопанельного рисунка: линия у подписей x и линия у подписей y (длинные нейтральные линии не дальше 4 высот подписи) не сходятся в угол графика (допуск 4 pt или 3 % рамки), а у панели одной из осей есть свои подписи другого направления. Панели, стоящие друг над другом с общей осью, её печатают один раз и флаг не получают |
  | `SECOND_Y_AXIS`, `SECOND_X_AXIS` | рисунок, ряды | с другой стороны графика есть вторая шкала: подписи текстового слоя, хотя бы частично привязанные к засечкам, на протяжении ≥ 30 % графика, вне рамки — не дальше 4 высот подписи от неё или рядом с длинной линией оси. У двухосевого графика неизвестно, какой ряд к какой оси относится. Подписи правой оси учитываются, хотя правило легенды прототипа их откладывает (они стоят справа от засечек, как подписи легенды справа от образцов); для второй оси x строки легенды не учитываются, числа внутри рамки — тоже |
  | `POWER_OF_TEN_LABELS` | рисунок, ряды | подписи вида «100, 101, 102» или «100, 102, 104» — степени десяти, у которых верхний индекс слился с числом (10⁴ прочитано как 104; шаг показателя 1–3): логарифмическая ось откалибрована как линейная |
  | `THOUSANDS_SEPARATOR_AMBIGUOUS` | рисунок, ряды | подписи могут быть числами с разрядами, прочитанными как малые (значения в 1000 раз меньше): все подписи с запятой имеют вид «1,000», «2,500» (английская запятая разрядов или десятичная запятая с тремя знаками — неизвестно), или хотя бы за двумя подписями на той же строке ближе 0,36 высоты подписи стоит трёхзначная группа («80» «000»: текстовый слой разбил «80 000» на два слова) |
  | `WEAK_AXIS_CALIBRATION` | рисунок, ряды | ось держится на трёх подписях с нерегулярными значениями (шаг не кратен наименьшему; у log10 мантиссы не из 1; 1,5; 2; 2,5; 3…9) или отбросила подпись внутри их диапазона не на шаге: три числа легенды или подписей кривых выстроились случайно. Отброшенная подпись на шаге («0, 20, 30» без «10») — смещённая подпись исправной оси, флага нет |
  | `POINTS_OUTSIDE_PLOT_AREA` | ряд, рисунок; у точки `in_plot_area = false` | вершина лежит вне рамки графика дальше 1 % её размера. Рамка (`frame_box`) — область графика; сторона, на краю которой нет длинной нейтральной линии, отодвигается до ближайшей такой линии не дальше половины размера области (соседняя панель и рамка всего рисунка не берутся); если линии осей x и y сходятся в угол, рамка доходит до их концов (не дальше размера области) — оси часто идут дальше последнего подписанного деления. Вершину скрыл clip графика — по печатному рисунку её не проверить (пример — ранние эпохи ряда репера 98 у VKM-SRC-034 рис. 4) — или она взята с соседнего графика |
  | `EXTRAPOLATED_BEYOND_TICKS` | ряд, рисунок | больше 25 % значений ряда лежат за подписанными делениями дальше чем на четверть их размаха; справочный флаг (на исправных графиках рамка часто уходит за последнее деление) |
  | `STROKES_DRAWN_AS_OUTLINES` | рисунок | ≥ 20 цветных вытянутых заливок при вдвое меньшем числе цветных штрихов: кривые нарисованы контурами штрихов (так пишет часть PDF-принтеров), маршрут A их не трассирует — рядов не хватает |
  | `ROTATED_PAGE`, `EMBEDDED_RASTER_IN_FIGURE` | рисунок | страница повёрнута; в рамке есть встроенный растр |
  | `OCR_HELPER_UNAVAILABLE` | рисунок | ось не найдена, а помощник OCR (Tesseract + OpenCV) недоступен или выключен |
  | `CANDIDATE_RULE_NOT_EVALUATED` | рисунок | файл источника недоступен или не тот: векторная половина правила не проверена |
  | `WORK_ATTRIBUTION_AMBIGUOUS` | рисунок | у источника несколько основных работ без диапазона страниц |

  Флаги прототипа сохраняются: `X_UNCALIBRATED`, `Y_UNCALIBRATED`, `LEGEND_UNMATCHED`, `MULTI_CHAIN_STYLE`,
  `LOCAL_OCR_CALIBRATION`, `MODEL_HINT_IN_CAPTION`, `AVAILABILITY_UNKNOWN`, `SCOPE_INHERITED_FROM_SOURCE`, растровые
  `RASTER` и `TRACE_GAP_NOT_FILLED`.

## 4. Датасеты (схема `vkm.figure_series/1`)

**`figure_series_figures`** — строка на рисунок-кандидат:

| Группа | Поля |
|---|---|
| ID и место | `figure_id`, `source_id`, `page_id`, `page_index`, `work_id`, `figure_label`, `caption_block_id`, `layout_class`, `bbox_x0…y1` (PAGE_PT_TL), `page_rotation` |
| правило | `numeric_tokens_near`, `vector_line_curve_items`, `core_keyword`, `keywords_caption`, `keywords_page`, `model_hint_in_caption`, `has_embedded_raster` |
| итог | `figure_status`: `DIGITIZED` (обе оси и ≥ 1 ряд) · `AXES_OK_NO_SERIES` · `X_UNCALIBRATED` · `Y_UNCALIBRATED` · `NO_AXES` · `SOURCE_UNAVAILABLE` · `SOURCE_HASH_MISMATCH` · `ERROR` (`error` — класс и сообщение без путей); `axis_status`; `plot_box` (размах подписанных делений, расширенный линиями осей) и `frame_box` (рамка графика — граница `in_plot_area`) |
| оси | по `x_` и `y_`: `axis_kind` (LINEAR, LOG10, DATE; у растра PIECEWISE, MARKERS), `cal_method`, `cal_label_source`, `cal_n_labels`, `cal_rms_pt`, `title_raw`, `quantity_raw`, `unit_raw`; `x_is_time` |
| счётчики | `n_series`, `n_series_both_axes`, `n_points`, `n_points_both_axes`, `n_points_outside_plot`, `n_time_series`, `n_marker_series`, `n_labelled_series`; `legend_without_curve`, `notes` |
| статус | `flags`, `available_from`, `available_basis`, `publication_year`, `source_site_scope_raw`, `route`, `digitizer_version`, `config_hash`, `rule_version`, `status = DERIVATION`, `review_status` |

**`figure_series`** — строка на ряд: `series_id` (`FS-<16 hex>` от рисунка, маршрута, номера ряда, подписи и цвета;
совпадает с ID прогона FD), подпись и цвет как напечатаны, `series_nature = UNCLASSIFIED`, `sampling`
(`VECTOR_VERTICES`, `MARKER_CENTRES`; у растра `POLYLINE_VERTICES`, `CENTRELINE`, `AT_SERIES_MARKERS`,
`AT_AXIS_MARKERS`), `axes_calibrated` (`BOTH`, `X_ONLY`, `Y_ONLY`, `NONE`), оси, диапазоны `x/y_min/max`,
`x_date_min/max`, медианные погрешности, `error_model`, полная калибровка (JSON: подписи засечек с позициями,
остатки, отброшенные подписи, движок OCR), провенанс (JSON: sha256 PDF, PyMuPDF, область, версия оцифровщика, хеш
конфигурации), флаги, статусы и доступность.

**`figure_series_points`** — строка на точку: `series_id`, `i`, `figure_id`, `source_id`, `page_id`,
`series_label_raw`; `x`, `x_date`, `y` в единицах величины (`NULL` на неоткалиброванной оси) с единицами
`x_unit_raw`/`y_unit_raw`; полуширины `x_err`/`y_err`; способ и rms калибровки каждой оси; положение на странице
`x_page_pt`/`y_page_pt` и `in_plot_area`; `status`, `review_status`, `available_from`, `available_basis`.

Погрешность точки — полуширина в единицах величины: rms остатков подгонки подписей оси ⊕ квант координат 0,05 pt.
Толщина линии не добавляется: вершина — это центр линии.

## 5. Второй набор: растровый маршрут R

Опция `raster_pages=fd_monitoring` — страницы каталога мониторинга из прогона FD (9 источников, 38 страниц; список в
коде — `FD_MONITORING_RASTER_PAGES` — и в квитанции), или JSON `{"VKM-SRC-…": [страницы]}`. Отбираются растровые
рисунки этих страниц (CHART, MIXED, RASTER_IMAGE, рамка больше 100 × 60 pt; рисунок с векторами — только если
RASTER_IMAGE). Датасеты `figure_series_raster_figures`, `figure_series_raster`, `figure_series_raster_points` — та же
схема, `route = R_RASTER`, флаг `RASTER` на каждой строке.

- Позиции точек переведены из пикселей рендера 300 dpi в PAGE_PT_TL, rms калибровки — в pt. Калибровка в JSON хранит
  позиции подписей в пикселях.
- Нужны Tesseract и OpenCV. Без них каждая фигура — строка `ERROR`.
- Разрывы трассы не заполняются (`TRACE_GAP_NOT_FILLED`).
- Набор всегда требует просмотра. Инструменты поиска его не показывают без `include_raster=true`, а `get_figure_series`
  находит его ряды по ID.

- **Атрибуция:** VKM-SRC-034 — 5 оцифрованных рисунков, `source_site_scope_raw = OTHER_VKM_SITE` (как у источника).

Визуальная проверка (галерея, наложение и график по числам; ID и вердикты — в квитанции): верные значения на
графиках мониторинга (например, VKM-SRC-017 с. 5, VKM-SRC-034 с. 4); флаги по делу — две оси (VKM-SRC-193, -222,
-226, -236), «80 000» → 80 (VKM-SRC-173), «1,000» → 1 (VKM-SRC-236), 10⁰…10⁴ → 100…104 (VKM-SRC-236), подписи кривых
вместо оси (VKM-SRC-236), ось чужой панели или вставки (VKM-SRC-135, -179), легенда вместо оси (VKM-SRC-214); с
запасом — цветовая шкала и номера зон у рамки как вторая ось; пропуск — цветовая шкала, принятая за ось y
(VKM-SRC-057).

## 7. Выдача: API и MCP

| MCP | API | Что |
|---|---|---|
| `find_figure_series(text?, unit?, source_id?, time_series?, calibrated_only = true, clean_only = false, include_raster = false, limit ≤ 50)` | `GET /v1/nav/figure_series?q=…` | рисунки с совпавшими рядами: подпись (≤ 240 знаков), оси с единицами и калибровкой, статус, флаги; по ряду — подпись, число точек, диапазоны, медианные погрешности, точки вне рамки, признак `suspect`. Для использования значений — `clean_only = true` |
| `get_figure_series(ref, max_points ≤ 5000)` | `GET /v1/nav/figure_series/{ref}` | ряд `FS-…` или все ряды рисунка: точки с погрешностями, `in_plot_area`, калибровка, провенанс; рисунок без рядов — со статусом |

- Слова ищутся по леммам (морфология графа понятий) и числам в подписи, номере рисунка, названиях осей и подписях
  рядов; нужны все слова запроса.
- Единица сравнивается после нормализации: регистр, точки, `mm` ↔ `мм`, `сутки` → `сут`.
- Если в сборке нет части — `DEPENDENCY_UNAVAILABLE`, если нет объекта — `NOT_FOUND`.
- Конверт — `NAV_FIGURE_SERIES_LIST` или `NAV_FIGURE_SERIES`, `layer = PROJECTION`, `origin = DERIVED`.
- Ночной smoke (`nightly-mcp-smoke-4`, 45 инструментов чтения) вызывает оба инструмента: поиск «оседание», затем
  первый найденный ряд.

## 8. Галерея для просмотра

`python -m vkm_corpus.figures.gallery --nav-dir <сборка> --duckdb <канон> --out <PUBLIC>/work/figure_gallery` пишет
одну страницу `index.html`. Она открывается из файла без сервера, все пути относительные. Для каждого рисунка на
странице:

- область из PDF (figure box ± 12 pt, 110 dpi) с наложенными оцифрованными рядами (пунктир — ряд без калибровки обеих
  осей, серая рамка — `frame_box`);
- график, построенный заново по числам (печатные деления, названия осей как напечатаны, направление осей как в
  оригинале; точки вне рамки — бледным пунктиром, не дальше одного размаха делений);
- сводка калибровки, статус, флаги, счётчики, доступность;
- CSV всех точек рисунка (со статусными колонками).

Фильтры: маршрут, источник, статус, ряды во времени, только оцифрованные, без подозрительной калибровки, слова
подписи и осей. Подозрительные флаги выделены красным. Порядок — оцифрованные первыми. Галерея снимка 738eebee:
1 285 рисунков (A 1 230, R 55), 1 126 CSV и наложений, около 230 МБ, сборка около 25 с. Каталог git-игнорируется: в
нём подписи и названия осей корпуса, коммитить и публиковать его нельзя.

## 9. Проекция в граф NAV (для агента G2, не реализована)

Что понадобится проекции `FIGURE_SERIES` в Neo4j (модули `graph/nav*.py` эта работа не трогала):

- **Узлы.**
  - `FigureDigitization` — ключ `figure_id` + правило. Свойства: статус, `axis_status`, виды осей, названия и единицы
    осей, счётчики, флаги, доступность. Отдельный узел нужен потому, что NAV не пишет в узлы DOCUMENT (проверка N2).
  - `FigureSeries` — ключ `series_id`. Свойства: подпись, цвет, `axes_calibrated`, `x_is_time`, диапазоны, медианные
    погрешности, флаги, статусы.
- **Рёбра.**
  - `DIGITIZES`: `FigureDigitization` → `Figure` (DOCUMENT).
  - `HAS_SERIES`: `FigureDigitization` → `FigureSeries`.
  - `QUANTITY_OF` (правило вроде `quantity_term_v1`): `FigureSeries` → `Term`, по ключу лемм `y_quantity_raw` (и
    `x_quantity_raw`, если это не время). Так ряды станут находимы из понятий («оседание» → ряды оседания).
- **Точки в граф не идут.** Учёт P5: `figure_series_points` — «пропущено по правилу», точки остаются в `nav.duckdb`.
- **Растровый набор** — те же метки с `route = R_RASTER` или отдельная проекция по решению координатора.
- **Проверки:** N1 для `DIGITIZES`; число узлов и рёбер равно числу строк датасетов (N5).

## 10. Ограничения

- Пунктир из отдельных штрихов, одноцветные чертежи с выносками, категориальные оси с текстовыми подписями — как в
  прототипе (FD §7). Выноски подписей кривых иногда попадают в ряды.
- Кривые, нарисованные контурами штрихов, не трассируются — только флаг `STROKES_DRAWN_AS_OUTLINES`.
- Маркеры, нарисованные дважды (заливка и контур), фильтр «буквы плечом к плечу» может отбросить. Маркер легенды
  иногда попадает в ряд маркеров как лишняя точка; знаки «+» из двух штрихов маркерами не считаются.
- Ось калибруется по самому длинному ряду или столбцу чисел. Столбец подписей кривых или значения легенды иногда
  принимаются за ось; флаги `AXIS_LABELS_INSIDE_PLOT`, `WEAK_AXIS_CALIBRATION` и `SECOND_Y_AXIS` находят часть таких
  случаев, но не все (вторая шкала, подписи которой не в текстовом слое, не видна).
- Многопанельные рисунки (а, б, в…) — одна каноническая рамка: оцифровывается одна панель, остальные дают лишние ряды
  вне рамки (`POINTS_OUTSIDE_PLOT_AREA`), а ось другой панели — флаг `AXIS_LABELS_DETACHED`. Цветовая шкала, принятая
  за ось y, этим флагом не ловится (линии шкалы не сходятся с осью x, но своих подписей x у шкалы нет).
- Двухосевые графики: калибруется одна ось на направление, ряды другой оси получают её значения — флаг
  `SECOND_Y_AXIS`, ряды к осям не приписываются. Флаг ставится с запасом: цветовая шкала у рамки или столбец номеров
  зон у края графика тоже его получают.
- Числа с разрядами не пересчитываются: «80 000», разбитое текстовым слоем на два слова, и «1,000» английской
  запятой читаются как 80 и 1 — только флаг `THOUSANDS_SEPARATOR_AMBIGUOUS`.
- Потерянные знаки «минус» у подписей (отдельный глиф) дают ось с неверным знаком — автоматически не ловится.
- Название оси иногда берётся не то (соседняя подпись, заголовок цветовой шкалы): значения от этого не меняются, но
  единица и поиск по словам осей ошибаются.
- Классификация «наблюдение / модель» и атрибуция рудника — только при ревью.
- Сборка детерминирована в одной среде. Другая версия PyMuPDF, Tesseract или OpenCV может дать другие байты — версии
  записаны в провенансе и в `manifest.json`.
