# Контракт входной партии источниковой геометрии ВКМ

Контракт связывает существующие A (содержание источника) и B (соответствие объектам ВКМ). Он не заменяет canonical evidence и не описывает расчётную модель.

Партия — UTF-8 JSON с `batch_id`, `extraction_version`, `features`, `project_matches`, `provenance`. `features` содержит исходные A-объекты; неизвестные поля сохраняются. `project_matches` содержит независимые B-связи по `source_feature_id`.

Каждый A-объект сохраняет:

- `source_feature_id`: стабильный уникальный ID; `source_id`, зарегистрированный `work_id` и основание связи;
- `pdf_page` (нумерация с 1), `printed_page` при наличии, `figure_id`, `panel_id`;
- `geometry` в GeoJSON: фактический тип и исходные координаты, без принудительного изменения MultiLineString на LineString;
- `image_coordinate_frame`: `id`, origin, направления осей, `unit`, размер, affine к PDF при наличии, `crs`, статус регистрации;
- буквальную `source_label`, `geological_meaning` либо UNKNOWN, `legend_reference`, горизонт с основанием либо null;
- `value` и `unit` значения отдельно от единицы координат;
- `primitive_role`, `extraction_status`, `epistemic_role`, `review_status`;
- `source_image`, `source_image_sha256`, версию извлечения и историю преобразований в `provenance`.

B сохраняет `source_feature_id`, `candidate_project_object_ids`, `match_status`, `match_evidence`, `conflicts`, `limitations`. Ссылка на один рисунок не устанавливает идентичность конкретного геологического объекта. При отсутствии обоснования соответствие остаётся UNKNOWN или кандидатом.

Компонент, выделенный из ранее сохранённой многосоставной геометрии, получает производный ID с суффиксом `:component:NNNN`, `parent_source_feature_id`, `component_index`. Исходный объект не заменяется. Нельзя выдавать повторный экспорт за новое независимое наблюдение.

Пиксели и неизвестная локальная рамка не получают EPSG:32640. Источниковые координаты с y вниз сохраняются; CAD-инверсия y допускается как отдельное обратимое преобразование представления, а не геодезическая регистрация. Разрывы под текстом сохраняются; восстановленные участки имеют отдельную интерпретационную роль.

Для передачи партии нужны её JSON, исходные изображения или разрешённые доступные ссылки, SHA-256 входов и выходов, наложение, QA с заданными допусками и checkpoint. Большие геометрии не вкладываются в поисковую карточку. GeoPackage, WKB, DXF и импортная партия связываются ID и дайджестом; дополнительные поля A/B не теряются.

Для Claude: результаты SRC-064/012 передаются этим же контрактом в отдельной партии, с собственными source/work/frame IDs. Смешивание рамок в пространственных операциях запрещено без принятого преобразования. Импорт исполняет назначенный DATA-MCP owner после QA; передача файла сама по себе не разрешает запись в production.

Приёмка каждого формата: полный набор стабильных ID, типы, число частей/вершин, атрибуты, единицы, рамка и координаты в заранее заданном допуске; отдельные проверки источникового соответствия и научного допуска. COMPLETE выбранного объекта не означает COMPLETE всего рисунка. Человеческая проверка не приписывается агентскому QA.

Уточнение для ранее зарегистрированной векторной геометрии: `geometry_coordinate_frame` при наличии задаёт рамку фактических координат, а `image_coordinate_frame` остаётся описанием изображения-первоисточника. Для локальной метрической рамки `kind=LOCAL_ENGINEERING`, единица m и неизвестный абсолютный CRS не требуют выдуманных ширины и высоты изображения. Векторный вход может иметь `source_artifact` с kind VECTOR, логическим путём и SHA-256. GeoPackage TA1 использует размеры только действительно известного исходного растра; эти размеры не являются метрическими габаритами геометрии. Отсутствующее изображение не заменяется фиктивным. Исходная локальная SH5 и пиксели экспортируются отдельными партиями и слоями с явными frame/unit metadata и сохранением цепочки прежней калибровки. Raw WKB не содержит SRID; PostGIS использует неизвестный SRID 0, а GeoPackage — стандартный SRS −1 (undefined Cartesian), согласованный в contents, geometry_columns и binary headers; это не подтверждение абсолютной геодезической регистрации.


## Воспроизводимый транспорт и чтение

В проверенном окружении без установки новых зависимостей:

```powershell
python scripts/geometry_pipeline.py prepare --batch PRIVATE_BATCH.json --output work/geo-prepare-01
python scripts/geometry_pipeline.py qgis --rows work/geo-prepare-01/source.wkb.jsonl --output work/geo-qgis-01 --private-root PRIVATE_ROOT --qgis-root QGIS_ROOT
python scripts/geometry_pipeline.py cad --rows work/geo-prepare-01/source.wkb.jsonl --dxf work/geo-prepare-01/source.cad_yup.dxf --output work/geo-cad-01
```

PRIVATE_BATCH, PRIVATE_ROOT и QGIS_ROOT — параметры выбранной поставки и существующих runtime, а не пути установки. Каждая команда требует новую директорию. Prepare проверяет JSONL/WKB/DXF, QGIS вызывает существующий мост и проверяет физический GeoPackage, CAD выполняет native DWG/DXF readback в существующем изолированном job-механизме. Одно сохранение DXF не является успешным CAD-чтением. Сохранять audit и результат job, включая отрицательные проверки; текущий bridge/runtime должен быть квалифицирован отдельно.

TA1 выполняется отдельным совместимым Python, не в QGIS venv. Из существующего Linux/WSL TA1 окружения, с разрешёнными путями входов и outputs:

```bash
PYTHONPATH=src "$VKM_TA1_PYTHON" -m vkm_geometry.ta1_worker write --rows work/geo-prepare-01/source.wkb.jsonl --gpkg work/geo-prepare-01/source.ta1.gpkg --readback work/geo-prepare-01/ta1-readback.jsonl --receipt work/geo-prepare-01/ta1-receipt.json
```

Reader строит геометрию из фактически прочитанных частей, проверяет полный manifest и SQL-key, не заполняет утраченную часть из оригинала. Пустая партия и несогласованные WKB/A отклоняются. Неизвестный CRS не разрешает перезаписать существующий определённый CRS; repair-srs создаёт отдельную производную копию и сохраняет байты исходника. Единицы, приписываемые GDAL по умолчанию undefined Cartesian, не становятся единицами источника: авторитетны явные frame/unit.

Полное повторное чтение и сравнение имеет допуск 1e−9 в исходных координатах, учитывает тип, части, кольца, вершины, A/B и IDs; этот численный допуск не является точностью источниковой оцифровки. Исходное наложение и семантический QA остаются самостоятельными проверками. Поставка БД описывается отдельным адаптером; поиск в подготовленном локальном снимке не означает его активацию в production.
