# Хранение результатов физических стадий

Решение владельца от 12.11.2026. Эта политика определяет дальнейшую работу; текущие объёмы, доступность и проверки конкретных данных находятся в PRIVATE индексе поставки и операционных таблицах. Старые receipts полного восстановления остаются датированной историей.

## Что сохранять

- Исходные научные материалы и наблюдения, код, параметры, единицы, версии, seeds и порядок генерации.
- Начальное и конечное состояния, состояния до и после физических событий, нужные контрольные состояния и поля для интерпретации и визуализации.
- Физическую память выбранных состояний, привязку к миру и представлению, геометрию носителя и происхождение. Смена формата не обнуляет память и не исправляет FAIL или UNKNOWN.
- Компактную диагностику всех шагов, сведения об отклонённых пробах, команды, допуски и результаты проверок.

Стадия определяется физическим событием и целью проверки. Номер итерации решателя сам по себе не является основанием для постоянного сохранения полного массива.

## Один набор больших численных данных

Для больших массивов используется один набор типизированных Parquet с индексами dtype, shape, единиц, носителя и происхождения. Совпадающие массивы допускается хранить один раз при проверенной идентичности значений и сохранённых отдельных привязках. DuckDB читает этот набор через внешние представления. PostgreSQL хранит научные таблицы, параметры стадий и необходимые численные сводки; полные внешние массивы не объявляются материализованными в PostgreSQL.

До замены исходного формата проверить обратное чтение значений, формы, типа, памяти и метаданных; выполнить реальные запросы. Пакет должен включать переносимый читатель, параметры и привязки, а не только локальные пути. Доступ к необходимым значениям и успешная публикация подтверждаются отдельно. Закрытые данные публикуются только в PRIVATE.

## Очистка после проверки

Повторные распаковки, третьи копии, память обычных промежуточных шагов, промежуточные решения Ньютона и воспроизводимые матрицы решателя не являются постоянной поставкой. Для производной матрицы сохраняются рецепт, входы и версия реализации; смешанный файл с физическими полями сначала разбирается по содержимому. Устаревшие ансамбли могут быть сняты с хранения по явному решению владельца с сохранением статуса, параметров, выбранных результатов и диагностики.

Удаление выполняется по точному перечню после проверки сохраняемых данных и разрешённых путей. Исходники, корпус, незакоммиченные изменения и уникальные результаты не удаляются по одному имени каталога. Данные на жёстких ссылках учитываются отдельно: сумма длин файлов не равна освобождённому месту. Объём освобождения измеряется по файловой системе.

Полное восстановление любого удалённого промежуточного шага не обещается. При необходимости он рассчитывается заново от пригодного сохранённого состояния с соответствующими входами. Новая серия заранее задаёт стадии вывода и лимит диска; бесконечное накопление каждого шага запрещено.
