# Ограниченные соответствия рядов и проверка полноты receipt

Общие функции находятся в существующих пространствах `vkm_corpus.figures`
и `vkm_corpus.api`. Их используют явно вызываемые staging-адаптеры корректирующих
партий; этот PR не меняет текущий NAV backend, канон или активный ScientificReader.

`scoped_correspondence` сравнивает только объявленный фрагмент источника и ряда,
сохраняет разрывы и проверяет идентичность, рамку и единицы. Совпадение части
не выдаётся за полную идентичность кривой. Допуск и `max_gap` должны быть
конечными положительными числами; `bool`, NaN и бесконечность отклоняются.

`index_runs` компактно представляет дискретные индексы и проверяет предложенный
код по AST. Последовательность индексов не доказывает геометрическую непрерывность
линии или временной истории; исходные GAP сохраняются отдельно.

`scientific_snapshot_verification.full_checksum` читает все строки, включая
строки после 500/4096, учитывает типы/имена столбцов и кратность повторов.
`historical_receipt_audit` проверяет явные целые счётчики, полноту чтения,
отсутствие усечения и подтверждённые digest. Отсутствующее/противоречивое поле
не становится текущим PASS. Исторический verdict и его байты не переписываются.

Проверка без PRIVATE и без запросов к сервисам:

```bash
python -m pytest -q tests/corpus/test_scoped_correspondence.py tests/corpus/test_index_runs.py
```

Адаптеры PRIVATE версионируются отдельно. Receipt нового адаптера должен хранить
SHA реально импортированных PUBLIC-модулей с явными ролями; хеш соседней старой
копии не подтверждает исполненный код. Синтетическая проверка CLI, повторный
audit сохранённого полного receipt и новый настоящий запуск различаются.
Повторный audit не объявляется повторным исполнением запросов.

Логическая корректирующая партия хранит прежнюю запись и отдельное новое решение.
Она не повышает научный статус неизвестной идентичности/единиц/эпохи и не
активирует снимок. Реальные источники, значения и receipts остаются PRIVATE;
тесты этого PR синтетические.
