# Частичная пересборка NAV и зависимости

`nav build` сохраняет дополнительный контракт `vkm-nav-dependencies/1` в
`manifest.json`. Это проверка согласованности производной навигации, не научная
проверка атрибуции, чисел или интерпретаций.

Каждая построенная часть содержит `input_identity` и его SHA-256. Они связывают
канонический snapshot, версию правила, опции, фактически доступные upstream
datasets, SHA-256 их Parquet и provenance производителя. Отсутствие необязательного
входа тоже фиксируется: его последующее появление меняет условия построения.
Распакованный outline связан хешем содержимого; vector parts, конфигурация векторов
и файловые опции — хешами фактических байтов до и после построения. Пути сами по
себе не доказывают идентичность входов.

## Граф зависимостей

| Часть | Входы из NAV |
|---|---|
| sections | нет |
| formulas | sections, section_pages |
| tables | sections, section_pages, formula_symbols |
| parameters | sections, section_pages, formula_parameters, formula_symbols, table_structure, table_cells |
| duplicates | нет; отдельный вход — unit vectors |
| object_duplicates | source_overlap, dup_members, formula_context, formula_symbols |
| concepts | section_pages; dup_members только при `drop_duplicate_blocks=true` |
| translations | terms, term_edges, term_mentions, formula_symbols |
| topics | sections, section_pages, terms, term_mentions; отдельный вход — unit vectors |
| figure_series | нет; собственный источник и runtime квалифицируются отдельно |

`parameters` — конечная часть этого графа. Её изменение не должно заново строить
concepts/topics. Изменение sections затрагивает формулы, таблицы, параметры,
concepts/topics и их зависимые части, но не текстовые duplicates.

## Поведение частичной сборки

1. Загружаются проверенные текущие datasets и явные `--inputs`. Приоритет имеют
   локальные актуальные результаты; прежний внешний пакет их не подменяет.
2. Выбранные части выполняются в объявленном порядке. Нельзя подменить проверенные
   datasets через `--option` или оставить незарегистрированную SQL-таблицу для
   неявного fallback. Повторное использование соединения очищает временные
   `nav_*` регистрации.
3. После каждой части сравниваются зависимости сохранённых результатов. Изменённые
   части и их зависимые части получают `STALE_UPSTREAM`; datasets убираются из
   whitelist и capabilities. Причина и прежние хеши остаются в manifest.
4. Физические устаревшие файлы не удаляются. `load_datasets`, pack и serving
   проверяют whitelist/контракт; возврат stale-файла в список или несовпадение
   upstream identity закрывает чтение/упаковку.
5. Идентичные входы и версия правила допускают сохранение уже построенных
   зависимых частей. Явное изменение опций, правила, outline или vector bytes
   инвалидирует соответствующие результаты даже при частичном запуске.

Сборка с историческим внешним входом требует снова передать проверенный `--inputs`,
если этот вход фактически нужен выполняемому builder. Сохранённая ссылка в старом
manifest не считается загруженной таблицей. Старые внешние дочерние datasets,
построенные по другой версии текущего upstream, исключаются из входов.

После изменения sections можно построить затронутые части, передав текущий
пакет как `--inputs`; `--part` принимает только нужные части в порядке графа.
Если конкретная часть требует отсутствующие unit vectors, её обычный
`SKIPPED_NO_INPUT` сохраняется; старый результат не возвращается вместо неё.
Новый пакет может честно публиковать согласованное подмножество capabilities.
Наличие нужных capabilities остаётся отдельным gate потребителя/API.

## Старые пакеты и ограничения

Старые NAV без этого контракта остаются историческими пакетами с прежней проверкой
файловой идентичности. При первой частичной модификации сохранённые части без
доказательства зависимостей инвалидируются: объявить их согласованными автоматически
нельзя. Новая часть, использующая legacy `--inputs`, получает
`AD_HOC_UNVERIFIED`, даже если файловые SHA старого входа проверены.

Неперечисленный каталог внешних артефактов или ресурсов не сканируется рекурсивно.
Для таких входов текущий builder фиксирует `UNVERIFIED_EXTERNAL_DIRECTORY` и
сохраняет `AD_HOC_UNVERIFIED`; это не разрешение production publication.
Квалификация исходных PDF/артефактов и соответствующих runtime остаётся отдельной
задачей. Проверка векторных файлов читает их байты; её I/O необходимо учитывать
в бюджете будущего запуска.

Пересборка sections/атрибуции **не требует новых embeddings**. Если изменились
section IDs или состав секций, пересобираются соответствующие section aggregates,
topics и проекции графа с повторным использованием прежних проверенных unit
vectors. Исходные единицы и их text/model/config signatures по-прежнему проверяет
builder topics. Исходники, OCR, embeddings и production эта доработка не меняет.

## Проверки

`tests/corpus/test_nav_incremental.py` использует реальный sections builder,
Parquet/manifest/pack/publish/serving и небольшие детерминированные builders
зависимых частей. Проверяются транзитивная инвалидация, неизменные входы,
неподменяемые текущие inputs, смена rules/options/vector bytes, запрет stale
manifest, исключение старых SQL registrations, восстановление capabilities
после повторной сборки и legacy qualification. Это synthetic CPU-проверки;
реальный NAV/corpus и модели в них не обрабатываются.
