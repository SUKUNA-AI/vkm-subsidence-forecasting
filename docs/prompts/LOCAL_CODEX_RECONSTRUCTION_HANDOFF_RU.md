# Передача локальному Codex после аудита

## Авторизованная цель и обязательное ограничение

Автор проекта подтвердил: исходные измерения и GIS получить невозможно; работа идёт по восстановлению опубликованных материалов. Нужно подготовить сильный диплом с проверяемой реализацией. Не предлагать получение оригиналов или внешний фактический пилот как обязательный следующий шаг. Пользователь явно попросил исправить каталог, происхождение полей, даты доступности и статусы наблюдений и включить оптимизацию вычислений в план.

Читайте `AGENTS.md`, `README_FIRST.md` и `docs/governance/RESEARCH_DIRECTION_RU.md`. Новый документ корректирует порядок дальнейшей работы; существующие зафиксированные протоколы остаются историей.

Названия уже утверждены и не подлежат изменению:

- диплом: «Горные и маркшейдерские работы при разработке Верхнекамского месторождения»;
- специальная часть: «Алгоритм прогнозирования оседаний земной поверхности на ВКМ на основе маркшейдерских измерений».

Основной результат — алгоритм прогнозирования по истории маркшейдерских наблюдений. Реконструкция и имитационные эксперименты обеспечивают подготовку и проверку при недоступности оригиналов. Не превращайте их в новую тему диплома и не представляйте искусственные наблюдения как фактические. Условия доступности данных и ограничения выводов описывайте в содержании специальной части, сохраняя её название.

## Принятие изменений

Сначала проверьте `git status --short` и текущий commit. Не сбрасывайте и не прячьте пользовательские изменения автоматически. При расхождениях с базой используйте отдельную ветку/worktree и перенесите смысл исправлений после просмотра конфликта. Новые локальные изменения не считаются отсутствующими только потому, что их нет в GitHub.

Для чистой совместимой ветки и распакованного патча:

```bash
git apply --check path/to/reconstruction-data-contract.patch
git apply path/to/reconstruction-data-contract.patch
python scripts/repair_reconstruction_data.py --root .
python -m pytest tests/test_reconstruction_data.py tests/test_feature_contract.py tests/test_target_contract.py tests/test_split_contract.py tests/test_leakage_guards.py tests/test_gate_c_leakage_guards.py tests/test_gate_c_split_contract.py tests/test_gate_c_sequence_contract.py --basetemp=work/data_repair/pytest_tmp -q
```

Замените только путь к патчу. Среда проекта уже должна быть подготовлена. `pyproject.toml` объявляет CPython 3.13; аудит патча проведён также в Linux CPython 3.12.13 с NumPy 2.5.2 / pandas 3.0.5. Это не точное воспроизведение Windows/CUDA-окружения обучения; полный DL-прогон не выполнялся.

Ожидаемый `validation_report.json`: 17 исходных артефактов и 7 родительских таблиц проверены; 18 исправленных статусов; 0 оставшихся противоречий; 6 целей `censored_rejected_after_qc`; 14 поправок счётчика пропусков; 1274/1216 кандидатов/доступных целей; 16 признаков по умолчанию и 50 в явно объявленном дополнительном представлении. Хеши двух перестроений должны совпадать.

При несовпадении входного хеша не обновляйте его просто для обхода проверки: выясните, что поменялось, и выпустите осмысленную следующую версию.

## Следующая исполнимая задача: атлас пространственной реконструкции

Цель: выяснить, какие части пространственной картины действительно воспроизводятся из источников, какие неоднозначны и какие ограничения из них допустимо переносить в симулятор.

Входы: SRC01 Филатова и SUP01 Мусихин. Предыдущий пакет аудита содержит четыре оцифрованных профиля, маски, наложения и скрипты; если этого пакета нет в локальной рабочей папке, это дополнительный материал передачи, а не содержимое закоммиченного репозитория. Не придумывайте его наличие.

Выполнить:

1. Выбрать одну схему Филатовой и один профиль Мусихина как законченный вертикальный пример.
2. Зафиксировать подпись, страницу, единицы, знак, координатную систему, калибровку, легенду и нечитаемые участки.
3. Получить воспроизводимые оцифровку и наложение. Сохранить исходное чтение отдельно от интерполяции и подгонки к якорям.
4. Оценить чувствительность к чтению/привязке. Если независимых точек геопривязки нет, выдать пиксельные или приближённые координаты без фиктивного RMSE в метрах.
5. Проверить фрагмент, не участвовавший в настройке, если доступен; иначе прямо оставить независимую точность неустановленной.
6. Записать поддержанные диапазоны для сценариев: источник, значение/интервал, назначение, неопределённость, допущение.

Результат: рисунки «источник / реконструкция / расхождение», машиночитаемая таблица значений и ограничений, журнал и манифест. Успех не требует идеально заполнить каждый пиксель.

Не переносить 252 оцифрованных значения профилей в 252 временные эпохи. Не отождествлять исходные номера/пикетаж с искусственными ID без доказательства. Не интерпретировать подгонку к использованному якорю как независимую точность.

## Следующая задача после атласа: новый сценарный эксперимент B1/IMM

1. Разделить пространственные ограничения, временные механизмы и ошибки наблюдения.
2. Зафиксировать набор сценариев разработки и закрытых семейств/областей параметров. Смена seed сама по себе не является проверкой внешней переносимости.
3. Реализовать новый адаптер к выпуску данных; не подменять пути старых B/C runner и не перезаписывать их результаты.
4. Использовать 16 полей истории/плана по умолчанию. Пространственные прокси — отдельная абляция с явным `SIM_STATIC_KNOWN`.
5. Перестроить признаки и последовательности из исправленных статусов. Проверить время, next-planned цель, маски и отсутствие скрытой истины в estimator.
6. Закрыть известные крайние случаи ранга интервала при малой калибровочной выборке; эмпирическое покрытие не выдавать за гарантию при зависимости.
7. Выполнить ограниченное парное сравнение B1/IMM. Старые результаты GRU оставить как сравнительное свидетельство; новый прогон только под конкретную гипотезу.

Критерий: отчёт отвечает, в каких условиях метод помогает/проигрывает, а не только показывает общий MAE. Необходимости доказать победу IMM заранее нет.

## Отдельная задача PERF-01

Профилировать репрезентативную локальную нагрузку после определения нового эксперимента. Измерить подготовку/fit/оценку/I/O, CPU/GPU, память, p50/p95, cold/warm. Сначала повторное использование работы и готовые операторы. Затем compile или собственный Triton/CUDA-kernel при подтверждённом узком месте.

Требуются: эталон, численная сопоставимость (для обучения также backward), тест масок и переменной длины, одинаковые данные/разбиения/objective/checkpoint selection, измерение всего workload, fallback. Не обещать ускорение по времени одного kernel и не уменьшать бюджет эксперимента скрытно.

Текущий C1 уже имел векторизацию на GPU и fused AdamW. Сначала изучите `artifacts/model_selection/t1_gate_c1_compact_screen_v1/execution_incident_register.json`, чтобы не выдать уже выполненную работу за новую.

## Что считать завершением диплома

Прослеживаемая реконструкция, проверенный сценарный генератор, работающий прогноз, честное сравнение с простым ориентиром, измеренная стоимость, воспроизводимая демонстрация и выводы в пределах доказательств. Внешние измерения могли бы расширить этот результат, но сейчас не требуются.

Word-черновик пока отражает старый курс. При следующей редакции исправить библиографию Филатовой, next-planned семантику, происхождение таблиц и статус внешней оценки. Не запускать старый генератор DOCX вслепую: его текст также требует синхронизации.
