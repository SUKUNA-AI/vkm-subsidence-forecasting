# R02 — воспроизводимая миграция Phase-1 без автоматической научной проверки

`vkm_evidence.migration` реализует ограниченную по ресурсам миграцию выбранных
**текущих** canonical CSV из PRIVATE `11_evidence_vnext/canonical/` в журнал evidence.
В этой поставке выполнялись только синтетические проверки. Реальная миграция,
корпусный dry-run и публикация исторических записей: **NOT_RUN**.

## Что установлено по существующим форматам

Проверены заголовки, количество строк и структурная metadata текущих каталогов;
исходные цитаты в этот документ не перенесены. Форматы неоднородны:

| Группа | ID / поля связей | Особенность |
|---|---|---|
| BOREHOLES / borehole_picks | `pick_id`, `source_id`, `locator`, `vn_id` | Числовые и `as_printed` поля остаются разными; есть диапазоны и UNKNOWN. |
| MECH_RHEO / mechanics | `row_id`, `source_id`, `locator`, `vn_ids`, `prev_evidence_ids` | Область — `site_scope`; перенос LAB → MASSIF не разрешён миграцией. |
| MECH_RHEO / rheology | `rheo_id`, `source_id`, `locator`, `vn_ids` | Формула и параметры сохранены как историческая запись, не как проверенная исполняемая модель. |
| GEOLOGY_COORDS | `geo_id` или `row_id`, `source_id`, `pdf_page`, `locator` | PDF-страница сама по себе не задаёт версию канонического объекта. |
| MINING | `event_id` или `row_id`, `source_ids`, `locators` | Даты, точность дат и planned/actual не угадываются из текста. |
| MONITORING_LIFECYCLE | `cat_id`, `campaign_id` или `dc_id` | Несколько временных осей и иногда составные scope; составная область не схлопывается в одну. |
| FORMULAS | `model_id`, `source_ids`, `locator`, `vn_ids` | Авторская формула, cited primary и варианты сохранены без утверждения семантической проверки. |
| CITATIONS / PHYSICS_CAUSAL | различные ID и связи | Семейство источников не является доказательством независимости наблюдений. |
| SOURCES / vn_index | `vn_id`, `source_id`, `dir`, `line`, `record_sha1` | SHA-1 старой JSONL-записи не заменяет SHA-256 оригинала или канонического объекта. |
| QA, внешние и служебные таблицы | иной набор колонок | Не превращаются автоматически в наблюдения или научные утверждения. |

PRIVATE README предупреждает, что часть `quote` содержит пересказ. Флаги
`quote_check`, `visual_check`, `PASS`, исправления QA и старый FACT не доказывают
новое `ReviewDecision` и не означают готовность к научному использованию.

## Контракт

1. `freeze_inputs(canonical_root, specs, catalogue_policy=..., context=..., bounds=...)`
   читает только явно перечисленные CSV и возвращает `FrozenMigrationInputs`:
   относительные имена, SHA-256 исходных байтов, размеры, заголовки, количество строк,
   точное отображение колонок и ограничения ресурсов. Никаких записей на диск.
2. `plan_migration(canonical_root, inputs, bindings, canon=..., source_policy=...,
   context=..., catalogue_policy=..., output_policy=..., recorded_at=...,
   base_revision=..., review_decisions=())` возвращает `MigrationPlan`.
   Время фиксации передаётся явно. Оно не становится временем наблюдения или
   `available_from`. `plan.sha256` закрепляет весь частный план, архив строк,
   текущие политики, исходные SHA, canonical snapshot, bindings и версию правил.
3. `MigrationPublisher(...).stage(canonical_root, plan, context)` сохраняет
   частный dry-run пакет, не меняя HEAD журнала.
4. `MigrationPublisher(...).publish(canonical_root, plan, context)` — отдельная
   явная команда публикации. Она требует доверенного разрешения владельца именно
   на `plan.sha256`, издателя и исходный `base_revision`.

`CatalogueSpec` задаёт имена колонок явно; автоматического распознавания смысла
по названию файла нет. `statement_column=None` сохраняет строки неподдержанного
каталога как UNRESOLVED. Нельзя подавать legacy/frozen/bootstrap каталоги, JSONL
старого retired pipeline или произвольные пути вместо current canonical root.

`RowBinding` адресует полную старую строку по SHA-256; содержит предоставленные
оператором точные `ObjectRef` и, при необходимости, существующие `VersionRef`
зависимостей. Поиском похожего текста локатор не создаётся. `canonical_resolver`
проверяет реальную схему CanonStore, ID объекта, source SHA, snapshot, версию
извлечения, content SHA и локатор. XML path сохраняется XML path, без фиктивного bbox.

Для непустого старого `quote` обязательна явная семантика:

- `VERBATIM`: хотя бы один проверенный оригинальный character span должен иметь
  точно такой же UTF-8 SHA-256 и длину; fuzzy match и нормализация текста не заменяют проверку.
- `PARAPHRASE`: сохраняется весь старый текст, источник проверяется по binding,
  но семантика пересказа **не** считается доказанной. Запись остаётся UNREVIEWED.
- `UNSPECIFIED` или `NONE` при непустом `quote`: UNRESOLVED.
- Для отсутствующего/пустого quote применяется `NONE`; заявление берётся из явно
  выбранной `statement_column`, без подстановки правдоподобного содержания.

В плане каждая строка имеет `MIGRATABLE` либо `UNRESOLVED` и коды причин. MIGRATABLE
означает воспроизводимость архивной Claim по проверенной связи с источником,
**не** готовность к научной работе и не успешный commit. После публикации отдельный
receipt содержит MIGRATED/UNRESOLVED для всех строк. Публикация подмножества требует
`allow_unresolved=true` в разрешении владельца; потерянные строки не скрываются.

ID сохраняются буквально. Дубликаты ID внутри выбранных файлов дают UNRESOLVED
для всех конфликтующих строк. Известные status/scope/scale сохраняются без повышения.
Неотображённый старый status становится UNKNOWN с отдельной причиной и полным
старым значением в архиве; неподдержанные scope/scale остаются UNRESOLVED.
DERIVATION/INTERPOLATION без требуемых методов/входов не получают выдуманный метод.

Выход — архивная `Claim` со статусом UNREVIEWED, точным исходным высказыванием,
провенансом и `historical_quote_field`. Числа, диапазоны, даты, исходные колонки,
пустые ячейки, старые VN/evidence IDs и прочие поля дополнительно сохраняются
полностью в неизменяемом архиве. Колонки не превращаются автоматически в Quantity,
Observation, EventAssertion, ObservationSet или независимые первичные наблюдения.
Старые связи без точного VersionRef остаются историческими ссылками архива.

## Объекты без подписи извлечения (решение владельца 05.10.2026)

В действующем снимке `snap-20260929T175107Z-574daaac` `extraction_signature` пуст у
всех объектов: исторические снимки её не записывали, задним числом она не вычисляется.
Поэтому для объекта без подписи версия опоры — та, которую API отдаёт в envelope:
`<content_sha256>@<коммит канона>` (`served_object_version` в `vkm_evidence/objects.py`).
Она закрепляет точные байты обслуживаемого снимка; подпись извлечения остаётся UNKNOWN и
не выдумывается. Объект с подписью по-прежнему требует именно подпись, пустая подпись —
отказ; канон без сведений о коммите не разрешает такие объекты. Правило одинаково для
миграции, журнала, review packet, теневого графа и семантического извлечения;
`table_continuations` осталось только с подписью.

## Разрешение владельца и review

`MigrationPublisher.approved_plans` — отдельная **доверенная конфигурация оператора**,
а не JSON из недоверенного запроса. `MigrationApproval` содержит hash плана,
исходный HEAD, publisher, authority и разрешение на явно учтённые UNRESOLVED строки.
Authority должна входить в настроенный набор owners. Само наличие JSON с именем
владельца не доказывает разрешение: загрузка этого набора входит в границу доверия
операторского приложения. Предоставлять вызывающему API замену этой конфигурации нельзя.

Исторические `ReviewDecision` необязательны. Если они передаются, то должны иметь
точную версию целевой записи и полные original supports. Журнал отдельно проверяет
свой набор настроенных reviewers и publisher principal. От старых QA-флагов review
не генерируется. Даже переданная VERIFIED_TRANSCRIPTION не создаёт ScientificUseAdmission.
Состояние миграционной строки остаётся NEEDS_SEMANTIC_REVIEW; решения научного
допуска принимаются отдельным существующим протоколом.

## Приватность и сохранность

- Политика каталога проверяется до чтения пути/CSV. Политики всех распознанных
  объявленных источников проверяются и для UNRESOLVED строк, поскольку они тоже
  попадают в архив. Source policy проверяется до обращения к содержимому CanonStore.
- Полная таблица может иметь смешанные ограничения. Доверенная политика каталога
  должна покрывать весь исходный файл, включая неоднозначные строки; формат не
  угадывает закрытые источники из свободного текста. Неизвестная policy известного
  source ID, отозванный доступ или невозможность сохранить ограничения блокируют результат.
- Output policy обязана быть PRIVATE и не расширять доступ каталога и источников.
  Target/TEST_SEALED остаются отдельной ролью. Научная независимость не выводится
  из разрешения читать PRIVATE в облаке.
- Runtime root и evidence journal размещаются вне PUBLIC checkout, с частными ACL.
  PUBLIC `work/` также отклоняется. Рекомендуемое размещение — отдельный частный
  runtime вне обоих Git checkout; nested PRIVATE checkout не является исключением
  из запрета писать внутрь PUBLIC root. На Windows ACL настраивает оператор.
- Пакет содержит `original-catalogues/<sha>.csv`, `rows.json`, `map.json`,
  `plan.json`, `stage-receipt.json`, а после явной публикации — `owner-approval.json`
  и `publish-receipt.json`. **Все** эти файлы частные; общий public exporter к ним
  не применяется. Receipt не содержит текста старых цитат, но всё равно не публичный.
- Новые файлы fsync до атомарного hard-link publication без замены существующего
  файла; POSIX parent directories тоже fsync. Другие байты на прежнем имени — ошибка.
  Прерванные `.pending-*` сохраняются; автоматического cleanup нет.
- HEAD существующего EvidenceJournal — точка commit. После потери ACK повтор с
  тем же планом обращается к тому же request ID. На каждом повторе заново проверяются
  байты CSV, canonical bindings и current policies, даже при наличии старого receipt.
  Другая версия плана или устаревший HEAD не перезаписывает старые записи.
- `physical_durability=NOT_QUALIFIED` всегда: синтетический fsync/ACK drill не
  доказывает восстановление после отключения питания. На Windows
  `directory_fsync=NOT_QUALIFIED` указывается явно.

## Ограничения и порядок реального запуска

План ограничен количеством файлов, суммарными байтами, строками, колонками и размером
ячейки; batch evidence ограничен существующим журналом (4096 записей / 16 MiB).
Большой каталог не обрезается и не получает ложный PASS: оператор выбирает меньшую
поддерживаемую партию; одиночный CSV сверх верхнего лимита требует отдельного
развития partitioned planner, а не ручного изменения исходного файла. У whole-corpus
программы это остаётся явным runtime/масштабным gate.

До реальной миграции нужны: действующий частный runtime/backup; доступный pinned
CanonStore с проверенными original versions; текущие source policies и политика
всего каталога; отобранные точные row bindings; dry-run и разрешение владельца на
его hash/base HEAD. Старые неопределённые страницы, пересказы и неразрешимые
составные scopes могут законно оставить часть записей UNRESOLVED.

Публикация повторно проверяет структуру зависимостей в existing EvidenceJournal.
MIGRATABLE в dry-run не заменяет этот gate: отсутствующий или устаревший dependency
VersionRef не допускается к commit. Конкурентный publisher получает существующую
ошибку single-writer; повтор выполняется явно после проверки состояния. Удалять
stale lock или переписывать старую запись автоматически мигратор не умеет.

Синтетическая проверка:

```text
python -m pytest -q -p no:cacheprovider tests/evidence/test_phase1_migration.py
```

На workstation с общим недоступным pytest temp используйте новый выделенный
`--basetemp` вне PUBLIC checkout. Не используйте реальный PRIVATE каталог в tests.
Тесты строят in-memory DuckDB с реальным CanonStore и проверяют сохранение IDs,
scope/scale/UNKNOWN, native locators, цитаты/пересказы, потерю ACK, fsync failure,
source-policy revocation, подделанные версии/фрагменты, owner/reviewer authority,
дубликаты, malformed CSV и отсутствие public-path публикации.
