# OCR v2 и извлечение фактов: законченная схема (05.10.2026)

Цепочка корпуса: **скан → OCR → выбор слоя текста → снимок и индексы → отбор страниц →
извлечение фактов (evidence) → WorldSpec**. Пересборка корпуса (снимок, индексы) идёт до
извлечения: отбор страниц опирается на поиск по новому тексту, а записи evidence привязываются
к снимку и сверяются с его текстом. Сборка мира — после извлечения.
Документ фиксирует решения по каждому звену и
то, на чём они основаны: пилот OCR 05.10 (160 страниц, `work/ocr_pilot_20261005/`, вне git),
исследования моделей OCR и LLM по состоянию на 05.10.2026, бенчмарк поиска `topic_v1`.

## 1. Что показал пилот PaddleOCR-VL-1.6

- Скорость на RTX 5070 Ti: 0,84 стр/с (1,2 с на страницу), 0 сбоев. Видеокарта загружена в
  среднем на 56–60 %, сервер vLLM недогружен (1–6 запросов одновременно): узкое место —
  клиент (разметка, подготовка, чтение PNG с диска Windows через WSL).
- Качество против текущего текста: явный выигрыш на страницах нашего GLM-OCR (словарные слова
  0,883 → 0,944, смесь кириллицы и латиницы 1,15 → 0,03 на 100 слов), DjVu, «мусорных» шрифтах,
  таблицах, которые GLM-OCR не читал, разворотах. На чужом вшитом OCR в PDF выигрыша нет.
- Провалы: почти все дало автоопределение поворота (10 из 10 «поворотов» ложные); модель не
  отказывается на испорченной картинке (выдумывает текст); редкие японские символы на
  крапинках; большие таблицы обрезаются по длине ответа.

## 2. Ключевые факты о модели (из установленного пакета)

- Страницу режет на блоки разметка PP-DocLayoutV3; каждый блок распознаётся отдельно.
  **Перед подачей в модель вырезка ужимается до `max_pixels` = 1 003 520 (≈1 Мп)** — одинаково
  для текста, таблиц и формул. Таблица на всю страницу при 300 dpi (7–8 Мп) сжимается в 7–8 раз.
  Лимиты задаются отдельно: `ocr_*`, `table_*`, `formula_*_pixels`. Это главный рычаг качества
  на таблицах и мелком шрифте — важнее DPI страницы.
- Длина ответа по умолчанию 4 096 токенов (`max_new_tokens`) — причина обрезанных таблиц.
- Номера формул распознаются как блоки `formula_number`, но скрываются при сборке markdown
  (`show_formula_number=False`). Номера страниц — блоки `number` (пригодятся для печатных
  номеров страниц).
- Серверы: vLLM, SGLang, FastDeploy. У нас проверен vLLM-образ под Blackwell (sm_120).

## 3. OCR v2 — как запускать

**Какие страницы.** GLM_OCR (6 509) и DjVu со вшитым слоем (893) — целиком; страницы с битым
слоем, «мусорными» глифами, шрифтами без ToUnicode и расхождением native/OCR > 10 % — тоже.
Чужой вшитый OCR в PDF не трогаем. Около 8–9 тыс. страниц.

**Подготовка картинок** (процессор, заранее, на диск WSL):
- у сканов — исходный растр (`pdfimages`) с проверкой ориентации по 8 вариантам относительно
  страницы PDF; при несоответствии — отрисовка pdfium 300 dpi; DjVu — `ddjvu` в исходном
  разрешении; векторные страницы — 300 dpi; оттенки серого, без бинаризации и «выпрямления»;
- выравнивание наклона 0,3–5° (по строкам), угол записывается;
- развороты (широкие страницы с белым «корешком») режутся на левую и правую половины с
  перекрытием, подстраницы a/b;
- пустые страницы (почти без «чернил») не распознаются — `EMPTY_PAGE`, без выдуманного текста.

**Распознавание:**
- автоповорот выключен; поворот только по данным PDF и явным признакам, сомнительное — в проверку;
- лимиты пикселей: ~~текст ~2 Мп, таблицы ~4 Мп, формулы ~2 Мп~~ — **по итогам A/B 06.10 для всех блоков 1 Мп**
  (стандартный лимит модели, см. «Итоги A/B 06.10» ниже); `max_new_tokens` ~10 000,
  `max-model-len` сервера с запасом под картинку и ответ; температура 0, без штрафа за повторы
  (иначе портятся повторяющиеся цифры таблиц);
- большая таблица, ответ которой обрезан или «не прямоугольный», режется на горизонтальные
  полосы (и по вертикальному просвету, если это две таблицы рядом) и распознаётся по частям;
  куски сохраняются по порядку как фрагменты одной таблицы.

**Сборка текста страницы** (свой рендер из JSON блоков, а не стандартный markdown):
- порядок чтения из разметки; таблицы — HTML и текстовая развёртка для поиска; формулы — LaTeX
  с номером `(6.49)` из блока `formula_number`; колонтитулы, номер страницы, сноски — отдельно;
- нормализация: HTML-сущности, переносы строк внутри ячеек, латинские «двойники» внутри
  русских слов (не в формулах и обозначениях), десятичная **запятая сохраняется**; любая правка
  записывается в журнал нормализации страницы.

**Защита** (на блок и на страницу): зацикливание (n-граммы, серии точек и экранов, сжимаемость),
чужие алфавиты (японский, бенгальский и т. п.), пустой ответ на блоке с «чернилами», формула
не компилируется, таблица не прямоугольна. Сначала повтор блока с другими параметрами, затем —
пометка; страница с проваленной защитой остаётся на старом тексте.

**Скорость:** картинки заранее на ext4; сервер `gpu-memory-utilization` ≈ 0,4,
`max-num-batched-tokens` 16 384, без префиксного кэша; 2 клиента по шардам, по 64 страницы за
вызов, ~64 одновременных запроса к серверу. Ожидание 1,3–1,8 стр/с → 8–9 тыс. страниц за
1,5–2 часа. Перед прогоном закрыть то, что держит видеопамять (обои Wallpaper Engine и т. п.).

**FP8 и SGLang.** Модель 0,9 млрд параметров, сервер не был узким местом, поэтому FP8 даст
немного, а для посимвольного OCR есть риск ошибок. Проверяется отдельным вариантом на тех же
160 страницах и принимается, только если быстрее ≥ 15 % без потери качества. SGLang не нужен,
пока сервер недогружен.

**Утренний порядок:** A/B на 160 страницах (по ~3 мин): базовая v2; v2 + FP8; v2 без разрезки
разворотов. Затем полный прогон с возобновлением по манифесту и отчётом.

**Итоги A/B 06.10** (160 страниц пилота, 156 в сравнении; сравнение по страницам и квитанции — в рабочем каталоге
прогона, вне git):

| Вариант | частей/с | словарная доля | числа | зацикливания | решение |
|---|---|---|---|---|---|
| v1 пилота (1 Мп, автоповорот, 4 096 токенов) | — | 0,929 | 8 545 | 1 | база |
| v2, текст 2 Мп / таблицы 4 Мп / формулы 2 Мп | 0,355 | 0,916 | 9 219 | 0 | отклонён |
| v2, 1 Мп для всех блоков | 1,233 | 0,928 | 9 542 | 0 | **принят** |
| v2, 1 Мп, сервер FP8 | 0,813 | 0,929 | 9 425 | 1 | отклонён (медленнее на 34 %, меньше чисел) |
| v2, 2 Мп, без разрезки разворотов | 0,379 | — | — | — | разрезка остаётся (на 16 разворотах не хуже) |

- Лимит выше 1 Мп портит текст: на тех же вырезках появляются посимвольные ошибки («ширинной», «ненсправностей»),
  на 9 страницах словарная доля ниже, чем у v1, на 0,08–0,23 (например, оглавление: 0,973 → 0,748). При 1 Мп словарная
  доля на 5 из 9 страниц равна v1 до третьего знака, на остальных 4 — ближе к v1, чем при 2 Мп.
  Модель обучена на вырезках до ~1 Мп; более крупные картинки выводят её из обучающего распределения.
- Таблицы при 1 Мп сохраняют выигрыш v2 (числа 1 372 против 736 у v1) за счёт `max_new_tokens` 10 000 и повторов
  полосами. Для формул разницы между 1 и 2 Мп нет (совпадение текста 0,999).
- Повтор блока со штрафом за повторы 1,05 на оглавлении с точками-заполнителями дал искажённые слова (одна страница из
  160): штраф портит повторяющиеся слоги так же, как цифры. Это учитывается при проверке результата полного прогона.
- Полный прогон: BF16, 1 Мп, разрезка разворотов, 3 клиента; 8 363 страницы → 8 641 часть.

**Итоги полного прогона 06.10** (10:52–12:43, 1 ч 51 мин, 1,30 части/с; отчёт и данные — в рабочем каталоге прогона,
вне git):

- 8 641 часть из 8 641, сбоев 0. Вердикты страниц: OK 7 371, OK с пометками 766, откат на старый текст 190 (2,3 %),
  пустых 36. Формул 19 032 (с номером 9 777), таблиц 1 607.
- Словарная доля, было → стало: GLM_OCR 0,894 → 0,948 (6 303 страницы), DjVu 0,954 → 0,972 (880), PDF со шрифтами без
  ToUnicode 0,960 → 0,958 (952; выигрыша нет). Медиана длины текста на GLM_OCR 1 402 → 2 031 символа.
- По страницам: лучше 2 897, так же 1 217, хуже 226, несравнимо 3 797 (меньше 30 русских слов). 584 почти пустые
  страницы получили текст. Заметно хуже — 40 страниц, 31 из них в одном плохом машинописном скане (VKM-SRC-240).
- Следующий шаг — правило выбора основного слоя страницы по качеству с записью причины (новый слой на GLM_OCR и DjVu,
  старый там, где новый хуже), затем новый снимок.

**Результат — новый производный слой текста** (`AUTO_EXTRACTED_UNREVIEWED`, модель, хеши весов,
версии, параметры, защита), старые слои не затираются. В снимок он попадает отдельным шагом:
новый тип слоя в конвейере и правило выбора основного слоя страницы по качеству с записью
причины. Затем новый снимок, переиндексация CORE, перенос evidence (записи привязаны к снимку),
повторный бенчмарк поиска.

## 4. Вспомогательные модели

- **Облачная VLM для страниц, не прошедших защиту** (обычно 10–15 %): по API это
  ≈ $1–2 за 1 000 страниц (Qwen3.8-Flash, оценка по прайсу) и минуты. Локальная Qwen3.8-Flash-Next через Strata
  для этого невыгодна: ~20–40 с на страницу, блокирует 35–55 ГБ памяти ПК, по одному запросу.
- **GLM-5.3-Flash для рисунков** — не на этапе OCR. На этапе извлечения — точечно для нужных
  рисунков (кривые оседаний, профили мульд, карты): описание и чтение значений, ≈ $0,002–0,005
  за рисунок. Сравнивается с уже работающим маршрутом оцифровки графиков `figure_series`.

## 5. Извлечение фактов со страниц (обновлено 09.10.2026)

Выбор облачной модели по API (GLM-5.3-Flash / Qwen3.8-Flash) **отменён решением пользователя 08.10**: без платных
API, без ключей и без сравнения моделей. Текст после OCR v2 уже есть; трудная часть — привязка (порода, лаборатория
или массив, рудник, условия), поэтому нужна сильная модель.

- **Производитель** — GPT-6.1 Sol через `codex exec` на подписке ChatGPT пользователя. Модель и уровень рассуждения
  передаются в каждом вызове (`-m gpt-6.1-sol -c model_reasoning_effort="high"`); `~/.codex/config.toml` не читается
  (`--ignore-user-config`) и не меняется; инструменты Codex (shell, браузер, веб-поиск, память, агенты) отключены,
  песочница read-only, пустая рабочая папка. Параллельность — несколько независимых `codex exec`, по одному на пакет.
- **Уровень** — high на весь прогон. Пробный прогон 09.10 на тех же 20 страницах: medium нашёл 89 % чисел high
  и совпал по привязке в 75 % случаев (расходится масштаб LAB / MASSIF / MODEL), поэтому на medium не переходили.
- **Отбор страниц** (`scripts/extract_select_pages.py`): страницы, на которые ссылаются каталоги Phase 1, досье
  тем и рисунки-кандидаты, плюс детерминированный поиск по потребностям C1–C4 и наблюдений; ярусы A (СКРУ-1 и
  числа, задающие диапазоны миров), B (прочие площадки ВКМ), C (аналоги); 2003 страницы, 151 источник;
  дубликаты NAV и копии одной работы склеены; VKM-SRC-252 (внутренний документ предприятия) исключён.
- **Пакеты** (`scripts/extract_build_packets.py`): 5–8 страниц одного источника (мелкие остатки — смешанные
  пакеты), таблицы страницы, заголовки и подписи соседних страниц как помеченный контекст; не больше
  32 000 знаков и 400 напечатанных чисел; 323 пакета. Пакеты, выданные двойной проверке, закреплены.
- **Схема** (`src/vkm_world/extraction/schema.py`) — одна запись на число или факт: PARAMETER / LAW / GEOMETRY /
  HISTORY / OBSERVATION / ENTITY / CITATION; значение и единица как напечатаны, min/max; порода/слой как
  напечатаны; масштаб LAB / MASSIF / NORMATIVE / MODEL / FIELD; площадка как напечатана и `site_norm`; условия,
  метод, число образцов; дословная цитата; оригинал или пересказ и ссылка. Чего нет — null / UNKNOWN.
- **Проверка** (`src/vkm_world/extraction/verify.py`, `scripts/extract_accept.py`): число в напечатанном виде
  (запятая, пробелы, степени десяти, знак) и единица есть на странице; min/max — эти же числа; цитата —
  подстрока страницы с нормализацией пробелов, переносов, тире, кавычек, «ё». Не прошедшие — в REJECTED с
  причиной, не удаляются. Все ответы — AUTO_EXTRACTED_UNREVIEWED.
- **Архив** на пакет: задание + пакет (stdin), поток `--json`, stderr, последний ответ, `meta.json` (sha256 пакета,
  задания, схемы, запроса; версия codex, модель, уровень, флаги; время; код выхода; токены; попытки).
  Продолжение с места остановки по маркерам `DONE`; при ошибке лимита подписки все потоки ждут сброса.
- **Двойная проверка**: 27 пакетов (206 страниц яруса A) независимо записаны субагентами Claude по той же схеме и
  тексту, без доступа к ответам Sol; сверка по числу и привязке — `scripts/extract_accept.py --compare`;
  расхождения идут в список на разбор и не усредняются.
- **Куда попадает**: записи, сравнения и квитанции — PRIVATE `11_evidence_vnext/canonical/WORLD_EXTRACTION/`,
  сырой архив — PRIVATE `12_work_exports/extraction_20261009/` (`scripts/extract_export_private.py`); в канон
  корпуса и журнал evidence ничего не пишется. Дальше записи идут в паспорт мира
  (`scripts/build_world_passport.py`, [WORLD_PASSPORT_RU.md](../worldspec/WORLD_PASSPORT_RU.md)).

## 6. Затраты (оценка)

- OCR v2: локально, ~2 часа видеокарты основного ПК.
- Облачная VLM для проваленных страниц: ≈ $1–2.
- Извлечение фактов (2 000 страниц): $0 сверх подписки ChatGPT пользователя (решение 08.10; платные API не
  используются).
- Рисунки (точечно, сотни — 2 000 штук): ≈ $1–10.
- Итого — порядка $20 и меньше. Цены сверяются с прайсом провайдера перед запуском.
