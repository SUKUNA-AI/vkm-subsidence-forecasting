## 5. Правила работы (сверх AGENTS.md)

- **Git:**
  - своя ветка `gpt/<тема>-<дата>` (или worktree);
  - коммиты по путям, небольшие и тематические; PR и описания — на русском;
  - **в `main` не мёржить без слова владельца**; без force-push;
  - не экспортировать `GIT_DIR` / `GIT_WORK_TREE`, не менять git config; окончания строк — как в HEAD.
- **Конфиг Codex.** Локальная папка `.codex/` с токенами и путями машины — в `.gitignore`. Не добавлять её в git и не
  печатать её содержимое.
- **GPU:** одна тяжёлая задача за раз. Замок — `work/gpu.lock` (JSON: owner, purpose, started). Создавать атомарно,
  удалять после задачи.
- **Нельзя:**
  - трогать канон и сервисы CORE/EDGE;
  - запускать `docker system prune`;
  - запускать решатели, «миры» и новые поисковые эксперименты.
- **Безопасность:** пароли не вводить, секреты не печатать. Скачивания и покупки — только с согласия владельца.
- **Квитанции.** У каждого преобразования — квитанция: входы, команда, модели и хэши промптов, SHA-256 выходов.
- **Перед завершением** прогнать тесты гигиены и утечки в WSL:

  ```bash
  ~/vkm/venv-corpus/bin/python -m pytest -q -p no:cacheprovider tests/corpus/test_public_hygiene.py
  ```

  ```bash
  ~/vkm/venv-corpus/bin/python -m pytest -q -p no:cacheprovider tests/world/test_foundation.py -k leak
  ```

- **Прошлые сбои — не повторять:**
  - параллельные тяжёлые задачи на GPU роняли WSL по памяти (`wsl --shutdown` чинит);
  - блокирующий вопрос остановил работу на 4,5 часа. Спрашивай текстом и продолжай другие части.

## 6. Как отчитываться

- **Статус.** Каждые 30–40 минут — короткий статус владельцу: что сделано, что дальше, сколько примерно осталось.
- **Итоговый отчёт** — коротко по-русски:
  - что сделано и где результаты (`REVIEW_V2_RU.md`, `REVIEW_GEO_RU.md`);
  - какая точность, что спорно;
  - что не сделано и почему;
  - ссылки на PR.
- **Названия в документах для владельца** — простые русские, без англицизмов.
