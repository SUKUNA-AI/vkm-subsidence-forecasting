# Активный этап — AMHF / специальная часть
Редакция 26.11.2026. Решения владельца для этой кампании; научные гипотезы не приняты как доказанные. Объект — всё поле СКРУ-1, локальная детализация по целевым величинам. Дипломное название не изменяется.

## Маршрут
1. Установить фактические checkout, HEAD/ветки, незакоммиченные изменения, runtime, VKM_RESOURCES_ROOT и задачу. Не трогать чужую работу геологии/горной/маркшейдерии.
2. Прочитать AGENTS, этот документ, [A01](../amhf/A01_AMHF_ALGORITHM_SPEC_RU.md) и [A02](../amhf/A02_IMPLEMENTATION_RECALC_VERIFICATION_RU.md) и [A03](../amhf/A03_REVIEW_AND_LEGACY_RU.md) адресно. В PRIVATE — AGENTS и текущий индекс нужных входов. Не начинать с миссии R3/Phase 1/Phase 2.
3. Использовать готовые C1/C4 и материалы пишущихся глав. После их фиксации импортировать адресные изменения в существующие PostgreSQL/DuckDB/Parquet с provenance и readback. Не повторять геологическую реконструкцию, скважины, карты и ансамбли; новая сетка механики на той же геометрии — не новая геология.
4. Приоритет: C2/C3/C5, связанная физика, проверка механики на принятом C1, операторы наблюдения и поверхности, физическая обратная задача, прогноз AMHF.
5. Теория [T01](../theory/T01_FRAMEWORK_V03_RU.md), [T02](../theory/T02_OPERATORS_MICROKERNELS_V03_RU.md), [T03](../theory/T03_SURFACE_OBSERVABILITY_HYPOTHESES_V03_RU.md) — рабочая v0.3-draft. Ведётся параллельное ревью; научные контракты v0.2 и статусы сохраняются до квалификации. Не задерживать реализацию проверенных операторов из-за исследовательских расширений.
6. Ansys — детальная механика; MATLAB/SciPy — независимые математические проверки; существующий Python/L3, WSL CuPy/RAPIDS/CUDA — основной вычислительный контур. QGIS адресно для пространственной проверки. Новые OGS/MFront, CAD/Civil 3D для спецчасти, GPR и дополнительные геофизические кампании PARK. CAD текущих глав не трогать.
7. Только локальная workstation, имеющаяся GPU. Сообщённые владельцем прежние решения Ansys 1–5 мин — ориентир, не benchmark нового мира. Не арендовать, не использовать Colab/платные делегации. FP64 эталон, FP32/mixed после сравнения, BF16 лишь квалифицированные некритичные операции.
8. Разрешено разрабатывать алгоритм, контракты, guard, синтетические проверки и read-only postprocessing. Физические запуски — в рамках отдельной порученной задачи и бюджета. Реальная калибровка, отбор миров по данным, прогнозный benchmark, sealed holdout, обучение, production/merge и платные ресурсы требуют отдельного решения. Не путать разработку с валидацией.

## Правила продолжения
R3, H8, Named37, L080/BH128, C1-поставки и предыдущие receipts — датированные доказательства и зависимости, не обязательный список повторов. При несовпадении входов выяснить затронутую зависимость, не начинать весь аудит. UNKNOWN не становится FACT, непригодность одного мира не блокирует независимую работу. Существующие OGS/CAD/legacy и уникальные расчёты не удалять по названию; очистка по проверенному manifest и решению владельца. [Состояние](../../PROJECT_STATE_RU.md).
