# Научные правила проекта ВКМ / СКРУ-1 (действуют после scientific reset)

Названия фиксированы и не изменяются:

- диплом — «Горные и маркшейдерские работы при разработке Верхнекамского месторождения»;
- специальная часть — «Алгоритм прогнозирования оседаний земной поверхности на ВКМ на основе маркшейдерских измерений».

## 1. Эпистемические статусы

Каждый объект и каждое значение имеет ровно один статус:

| Статус | Когда применяется |
|---|---|
| `FACT` | прямо утверждается или измерено источником; есть локатор (страница/таблица/рисунок) |
| `DERIVATION` | получено из фактов явной процедурой: метод + входы |
| `INTERPOLATION` | оценено между наблюдениями пространственным/временны́м методом: метод + входы |
| `MODEL_CHOICE` | выбор проекта: область, упрощение, параметр, представление; письменное обоснование обязательно |
| `ENGINEERING_ASSUMPTION` | инженерное допущение без прямых данных; обоснование обязательно |
| `ANALOGUE` | значение с другого объекта: другой рудник ВКМ, другое месторождение, другой масштаб |
| `UNKNOWN` | нет данных; значения нет |

Статусы не смешиваются. Правила проверяются кодом `vkm_world.core.provenance` и тестами `tests/world/`.

## 2. Запреты подмены

| Нельзя выдавать… | …за это |
|---|---|
| UNKNOWN | известное; нет данных ≠ 0; нет информации ≠ однородность |
| среднюю скважину | реальный участок; скважина 75 ≠ СКРУ-1; одна скважина ≠ месторождение |
| лабораторный образец (LAB) | массив (MASSIF); перенос только через явный `Transfer` |
| аналог (соседний рудник, другое месторождение) | site-specific значение |
| нормативное / проектное значение | измерение; проект ≠ фактическая отработка |
| учебный пример (TEACHING_EXAMPLE) | факт о СКРУ-1 |
| интерполяцию | наблюдение |
| результат модели или решателя (в т. ч. OGS) | измерение |
| GPR | оседание поверхности (это локальная геометрия у выработки) |
| InSAR | нивелирование (разные наблюдаемые, опорные точки и ошибки) |
| 2D-сечение | весь 3D-объект |
| MODEL_CHOICE | FACT |
| вторичную цитату | первоисточник; при сомнении ищется оригинал |

## 3. Провенанс и прослеживаемость

Для каждого значимого параметра сохраняется цепочка:

`источник` → `страница/таблица/рисунок` → `evidence-запись` → `интерпретация` →
`метаданные модели/параметра` → `WorldSpec` → (Phase 2) `вход расчёта` → `предсказанное состояние` →
`предсказанное наблюдение` → `реальное наблюдение`.

Критичные числа (параметры, координаты, отметки, отбивки, атрибуции рудников и линий, формулы)
проверяются по цепочке:

`text layer` → `OCR` → `отрендеренная страница` → `подпись` → `окружающий текст` →
`библиография/контекст` → `перекрёстная проверка по другим источникам`.

Что не разрешено до конца, остаётся UNRESOLVED в `evidence/qa/visual_ocr_qa_ledger.csv`.

## 4. Противоречия

Противоречащие значения не усредняются. Хранятся все версии со своими источниками, плюс запись
о конфликте (conflict note) и, если есть, обоснованное решение с явным статусом.

## 5. Время и утечка информации

Различаются даты:

- физического события;
- измерения;
- обработки;
- публикации;
- доступности (`available_from`).

Прогноз на дату t0 может использовать только данные с `available_from ≤ t0`. Данные с неизвестной
доступностью не используются. Параметры не подбираются по test/evaluator truth.

## 6. Границы текущей фазы

Phase 1 (cloud) — только информация и архитектура: чтение, извлечение, провенанс, каталоги, дизайн,
схемы, лёгкие тесты.

Тяжёлые вычисления выполняет локальная Phase 2:

- напряжения, ползучесть;
- интерполяция, кригинг;
- FEM: OGS + MFront (основная ветка), ANSYS Mechanical (независимая сверка); gprMax как оператор наблюдения GPR (D-18);
- Monte Carlo, чувствительность.

До отдельного решения **запрещены**: ML, прогнозный бенчмарк, физический ансамбль, утверждения
о field validation и цифровом двойнике.
