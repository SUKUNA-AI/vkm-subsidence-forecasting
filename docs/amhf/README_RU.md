# AMHF — карта проекта, теория, исполнение и результаты

В кампании AMHF-R1-SURFACE сначала исследуются [математика и наблюдаемость](../theory/R1_THEORY_SUBSIDENCE_EVOLUTION_RU.md). [Ревью R1](../theory/R1_REVIEW_AND_OPEN_QUESTIONS_RU.md) связывает T01–T06 с проверками и указывает условия перехода к исследованиям физического замыкания. К исполнению A01/A02 переходят по отдельной задаче.
26.11.2026. Читать этот индекс для понимания всей работы; отдельные документы являются её рабочими спецификациями, а не независимыми канонами.

## 1. Что строим
Задача ВКР — алгоритм прогнозирования оседаний земной поверхности на ВКМ на основе маркшейдерских измерений. Текущий объект — всё поле СКРУ-1. Готовая геология и горные работы -> согласованный PhysicalWorld -> связанная механика и память -> наблюдательные операторы -> ограниченная обратная задача -> допустимые физические траектории -> прогноз и ограничения. Геологические и горные агенты передают версионированные готовые входы; AMHF не повторяет их работу. Не весь framework должен быть реализован в дипломе, но каждый используемый механизм должен быть научно и вычислительно определён.

## 3. Карта работ и критериев выхода
| Задача | Вход | Исполнение | Выход / критерий |
|---|---|---|---|
| W01 — входы | текущие главы C1/C4, существующие БД и receipt | закрепить идентичность, время, систему координат, материал/закон; импорт только дельты | совместимый pin и readback; отсутствие новой геологической реконструкции |
| W02 — физический блокер | последний принятый PRE нового C1 | Ansys и существующий solver, контакты/сетка/ограничения/касательная/балансы, воспроизвести failure | допущенный POST или строго локализованный блокер; не ослаблять допуск |
| W03 — память | H8, прошлые траектории и material packages | проверить actual integration, fixed law/basis/support, exact/qualified transfer; прямые/SOE проверки | memory load, work, replay, rollback; не считать архивное чтение restart |
| W04 — C2/C3/C5 | материалы реологии, Rock Physics, Carcione, гидрогеология | совместимые свойства/тензоры, начальные поля, контакт/давление, сценарии | формулы и параметры с локаторами, units, scope и test paths |
| W05 — поверхность | сохранённые поля, фактическая сеть/эпохи | операторы leveling, GNSS/LOS при наличии, гладкое/слабое восстановление, Hess, maxima, increments, G3 | синтетический эталон, noise/geometry check, masks, единицы |
| W06 — взаимодействия | изменившаяся физика | адресные Ansys K/G, fine/coarse, Schur/DtN только при необходимости | qualification по портам, целевым величинам и памяти; не обрезать дальние связи |
| W07 — обратная задача | W03/W05, допустимые theta | bounded trust-region, sensitivities, nuisance projection, synthetic/negative controls | проверяемая реализация без натурной калибровки до допуска |
| W08 — наблюдаемость | trajectory sensitivities, covariance, future horizon | A_eff, B_H, local SVD, контрастные физические траектории | наблюдаемые/неразличимые направления и влияние на прогноз |
| W09 — интеграция | W01–W08 | finite-budget loop, calibration/screening отдельно после разрешения, future scenario | траектории, диапазоны, маски, unresolved, lineage; не выдавать за натурно validated |
| W10 — проверка | замороженный кандидат и отдельный допуск | сравнение baselines, AMHF с/без G3, независимый holdout | факт допуска или FAIL/ограничение, не тюнинг по test |
| W11 — расширения | теория T01–T03 | Вольтерра высоких порядков, гармоники, курвлеты, KL/PCE, топология при обосновании | исследовательские результаты; не критический путь |
| W12 — cleanup | actual workstation inventory | KEEP HOT/ARCHIVE/PARK/CLEAN_CANDIDATE; проверить владельца, dependencies, bytes, hash, restore | утверждаемый список, без массовой чистки; никаких удалений этой документной задачей |

## 4. Что может идти параллельно
Научное ревью T01–T03 и адресное чтение книг параллельно W01–W05 и физическому ремонту. Программные контракты, operators, синтетические проверки, profiling и обратная задача в development не ожидают всей теории. Реальная физическая траектория нового C1 зависит от принятого состояния и конкретного отказа; прогноз по натуре зависит ещё и от observation admission и отдельного gate. Нельзя запускать всё сочетание миров/законов ради счётчика.

## 5. Вычислительная дисциплина
Локальная workstation; WSL/Ansys/MATLAB/SciPy/CuPy/RAPIDS/CUDA. Прежние времена Ansys 1–5 минут — пользовательский ориентир, не прогноз новой кампании. Измерить время accepted/rejected steps, assembly/solve/IO, memory peak, корректность FP64 и FP32/mixed. H8 и sparse/matrix-free прежде грубой потери точности; BF16 только проверенные блоки. Аренда/Colab не планируются. Сохранять выбранные физические состояния/память и компактные поверхностные ряды, не все trial 3D.

## 6. Статус
Документационная ревизия; новые гипотезы TEST_REQUIRED, AMHF не выполнен, новые расчёты и научные тесты не заявляются. Независимое ревью оригиналов книг и локальный аудит вложенных инструкций/хранилища остаются отдельными действиями.
