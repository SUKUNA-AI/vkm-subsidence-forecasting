26.11.2026. Рабочая программа, не разрешение на тяжёлые запуски. [Активный этап](../planning/AMHF_ACTIVE_STAGE_RU.md), [A01](A01_AMHF_ALGORITHM_SPEC_RU.md). Одна локальная workstation; никаких аренд/Colab. Сообщённое владельцем время решения прежних больших задач Ansys 1–5 мин использовать как ориентир для измерения, не переносить автоматически на нелинейную историю.

## 1. Готовые входы
Принять актуальные готовые C1/C4, geometry IDs и ограничения, не реконструировать и не запускать новый геологический ансамбль. Проверить фактический pin из готовящихся глав; при обновлении только дельта, импорт в существующие PostgreSQL/DuckDB/Parquet с проверкой ID/единиц/версий/readback. Не строить вторую БД, не активировать production/ScientificReader. Отдельно pin наблюдения, provenance и датум. Старые связанные истории и поля сохранять на их исходном мире, применять для постобработки/сравнения. Не выдавать их за физику новой геометрии. PRIVATE карта входов и литературы — AMHF_INPUTS_AND_MATERIALS_RU.md.

## 2. Очередь работ с выходом, а не круговой аудит
P0 параллельно:
- F01 pin и прочитать принятые состояния/поля, проверить readback/restart и доступность компактных поверхностных эпох; инвентаризировать H8 maxwell_coefficients.py/maxwell_sparse_history.py и их тесты; не переписывать память.
- F02 новый C1 -> механика: восстановить соответствующий PRE 1939,5 и конкретную неуспешную совместную выемку из принятых входов. Сопоставить geometry, material, BC, initial stress, event activation, contact, constraints, mesh, tangent, residual, активные DOF и потерю локальной жёсткости. Сохранить исходный failure. Разделить физическую нестабильность, моделирование, дискретизацию, решение. Не ослаблять порог для PASS. Успех — допущенный POST либо локализованный воспроизводимый блокер и независимая ветвь.
- F03 prior Ansys/quadrature FAIL, AC19/AP09-02 и энергия: проверять только затронутую выбранным семейством зависимость. Для незамкнутого события — отдельный баланс массы, работы, памяти и неизвестный получатель; не объявлять энергию теплом. Не закрывать все старые 80 действий по умолчанию.
- M01 научные операторы наблюдения (разности эпох, covariance, datum, duplicate lineage), физическое поле поверхности, gradient/Hessian, extrema, приращения; синтетическая аналитика + старые сохранённые поля.
- T-review параллельно: точное чтение нужных источников, проверка T01–T03 и контрпримеры. Не блокировать проверенные компоненты ожиданием всех исследований.

P1: C2/C3/C5 материальные и контактные пакеты по источникам; Ansys несколько пространственно разных областей/пластов, не только №75; локальное уточнение сетки 4→2→1 или иной оправданный ряд, время/память/контакты, K/G по изменившимся зависимостям. Согласовать физические законы, начальное состояние и BC. Для уже принятой траектории не переносить историю на новый C1 без квалификации. Выполнить replay только от самой ранней затронутой стадии; при отсутствии совместимого checkpoint — от начального состояния. Не требовать полной новой истории каждого семейства до диагностики.
P1 параллельно: квалифицировать CPU FP64 и CUDA FP64/FP32/mixed, математическая сверка MATLAB/SciPy, построить bounded inverse и NROY orchestration в development/synthetic режиме, тесты ошибок/ресурсного лимита, observation operators.
P2: выбранные связанные исторические интервалы и ветви; целевые поверхности и G3, проверка predictive observability, затем реальная калибровка/screening/прогноз и benchmark только после отдельного допуска. Не требовать всех 48 C1 x всех законов x всех событий. OGS/MFront, CAD, GPR, геофизические расширения PARK; QGIS для адресной проверки и карты. Сохранить исторический OGS как reference, не объявлять новую независимую сверку.

## 3. Производительность и точность
Ansys локально — детальный механический расчёт и проверка K/G; MATLAB — независимое уравнение, интегралы, точность, проверка на согласованных примерах; SciPy CPU — эталон, sparse solvers/optimization; CuPy/CUDA — массивы, sparse/dense primitives, FFT, material kernels, batch worlds; RAPIDS/cuDF/cuGraph/RAFT — обработка данных и графов, не физический solver. Переиспользовать WSL. Общий GPU lock и текущие задачи, измерить GPU/RAM/VRAM/диск, версии и реальные времена. Не переставлять стек автоматически.
Профиль: assembly/factor/solve, material update, events, transfer, IO, verification, rejected steps; сравнить walltime, peak allocated VRAM, ошибки и число accepted steps на одной задаче. Использовать H8 exact support storage прежде чем приближённо резать память. Для batch независимых миров разделять topology/law; сохранять связанные равновесия, не параллелить ядра как независимые физические системы. Matrix-free, повтор факторизаций где оператор тот же, low-rank с контролем ошибки. Не обрезать дальние связи.
FP64 reference (геодезические координаты, accepted state/memory, residual, balances, near-singular tangent, sensitive Hess). FP32 candidates: локальные операции и преобразования после масштабирования; BF16/TF32 — предобусловливание/некритичные плотные блоки при проверке. Нельзя хранить всю физическую память BF16. Для mixed solve считать остаток и correction в более высокой точности, проверять convergence/stagnation и fallback FP64; sparse не гарантирует Tensor Core speedup. Не менять acceptance thresholds по dtype. Точные tolerances назначать из цели, baseline и измерений, не круглых произвольных чисел. Сравнение с FP64 на длинной памяти, unload/reload, PRE/POST, local stress/pressure, surface Hess, energy. Принятый checkpoint — полная квалификация precision/storage.

## 4. Выбор следующего расчёта
Вместо обязательной огромной серии: сначала 1 репрезентативный solve + повтор, затем стоимость и чувствительность; бюджет определяется владельцем, не заранее выдуманные сроки. Refinement при нарушении допуска пространства/времени/памяти/портов/целевой величины. Не улучшать сетку, когда ограничение эпистемическое. Ранжировать задания по критическому пути и измеренной цене/влиянию на прогноз. Stop: физический/численный отказ, ресурс, отсутствие входа, неподдержанная гипотеза; сохранять диагностику, не циклически повторять. 
## 5. Приёмка
Каждый case: pin, команды, geometry/basis/law/memory IDs, units, time/event, precision, runtime, wall time, solver residual, conservation/energy where applicable, convergence, exact restart/replay evidence, output fields and limitations. Различать научную приёмку от code/test PASS. Стадии PRE/POST и нужные checkpoint плюс компактные поля поверхности/реперов на нужных эпохах, не хранить все trial 3D поля. Один типизированный пул, метаданные и readback; existing storage_disposition/stage_retention. Адаптация не переносит статус с одной модели на другую. Аренда и внешние вычисления не входят в текущую задачу.
## 6. Готовность

Минимальная законченная цепочка pin->physics->observation operator->bounded inverse->NROY->future->diagnostic outputs; разработка и синтетические проверки разрешены, натурная калибровка/benchmark отдельно. Финальный результат обязан содержать источник, сценарии, реальные проверки, ограничение наблюдаемости и NOT_RUN; не называть модель валидированной по синтетике.
