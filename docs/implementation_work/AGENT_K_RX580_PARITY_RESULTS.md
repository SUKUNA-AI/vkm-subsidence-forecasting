# AGENT K — RX580: parity против эталона (§30–31)

Дата: 28.09.2026. Бэкенд — [BACKEND_RESEARCH](AGENT_K_RX580_BACKEND_RESEARCH.md); матрица моделей —
[MODEL_MATRIX](AGENT_K_RX580_MODEL_MATRIX.md).

## 1. Методика

- **Эталон.** HF transformers **fp32 на CPU** WORKSTATION (RTX 5070 Ti в это время был занят GLM-OCR на 92–100 % и
  15,9 из 16,3 GB — по CP-26 OCR не прерывается; fp32 CPU — самая точная эталонная точность, та же реализация модели).
  Для каждого текста эталон хранит **те же token ids**, что строит сервис (`SpecTokenizer`), и выход после той же
  постобработки (`postprocess`). Привязка к официальному пути: на 48 запросах и 48 документах каждой модели выход
  сверён с библиотекой карточки модели — sentence-transformers (dense) / PyLate (ColBERT) / `encode()` модели (pplx
  context): совпадение ids и cos ≥ 0,9995 (pplx: int8 совпадают в 94–95 % компонент, расхождение ≤ 1 шага квантования).
  Модуль `vkm_corpus.embeddings.reference`, venv WORKSTATION (torch 2.11 CPU, transformers 5.3 / 5.17,
  sentence-transformers 5.3 / 6.1, PyLate 1.6).
- **Проба.** 1918 канонических объектов dev-канона C (`staging_dev`): 1655 блоков (стратификация по источнику, типу
  блока и длине), 122 формулы, 80 страниц (длинные, усечение 512 токенов), 61 таблица; источники 249, 023, 037, 044, 033.
  60 запросов (RU, EN, смешанные, формулы, номера рисунков/таблиц, длинные) — собственные формулировки K, не цитаты.
  **Вторая проба — канон canary** (staging C после canary-прогона): 1788 объектов из 15 источников, в том числе
  OCR-страниц, стратификация по источнику, типу и длине; те же 60 запросов, тот же эталонный путь. Данные проб —
  runtime (WSL/CORE), в git не попадают.
- **RX580.** Тот же GGUF-квант, `llama-server` (Vulkan), ids → выход → та же постобработка.
- **Метрики** (`vkm_corpus.embeddings.parity`): косинус векторов одного объекта (mean / p1 / min; для ColBERT — по
  токенам); ранжирование 60 запросов по 1918 объектам: пересечение top-10 и top-50, Spearman и Kendall на объединении
  top-100, rank-agreement nDCG@10 (эталонные скоры как gains). Recall/nDCG на qrels — у J после канона.
- **Gate** (MODEL_CHOICE, записан в каждом результате): cos mean ≥ 0,995, cos p1 ≥ 0,98, top-10 ≥ 0,90, top-50 ≥ 0,90,
  Spearman ≥ 0,95.

### 2.1 Выводы по parity

- **Q8_0 — PASS у всех dense- и ColBERT-выходов на обеих пробах** (dev-канон и канон canary), кроме multi-vector
  BGE-M3 (27 строк «модель × проба × выход»): средний косинус векторов документа 0,9986–1,0000, p1 ≥ 0,992;
  top-10 0,967–0,992, top-50 0,979–0,993, Spearman 0,993–0,999. На canary (в том числе OCR-тексты, другие источники) метрики те же, что на dev-пробе: RX580
  воспроизводит эталон на уровне шума квантования Q8_0, не подстраиваясь под пробу.
- **Q6_K** — PASS у большинства с меньшим запасом (top-10 0,94–0,97), но **FAIL у pplx-embed-0.6b и Giga-480M** по
  среднему косинусу (0,994–0,995 < 0,995; ранжирование при этом близко, Spearman 0,966–0,99); причина не
  исследовалась. Для этих моделей — только Q8_0.
- **Q5_K_M — FAIL** у granite-97m-r2 (скрытый размер 384, K-кванты заменены запасными типами), mDenseOn, mLateOn,
  Qwen3-Embedding-0.6B и BGE-M3; PASS у granite-311m и jina-v5 nano/small.
- **F16 — эталонная точность** (cos 1,00000, top-10 1,0): арифметика fp32 RADV совпадает с fp32 эталоном; путь
  неэффективен по скорости (MODEL_MATRIX).
- **BGE-M3 multi-vector — FAIL по заранее заданному токенному критерию на обеих пробах** (p1 косинуса токенов 0,975 на
  dev и 0,949 на canary при Q8_0; min 0,15). Диагностика 400 документов / 45 503 токенов: худшие токены —
  пунктуация (`,` и `.`, id 5 и 6), у которых проекция `colbert_linear` почти вырождена; токены конца
  последовательности в порядке (0,9997). Ранжирование по MaxSim при этом совпадает (top-10 0,977–0,987, Spearman
  0,995–0,996). Порог не пересматривался. Dense-выход BGE-M3 (тот же проход) — PASS/одобрен. **BGE-M3 F16 проходит
  все критерии на обеих пробах** (multi-vector: p1 токенов 0,998 / 0,997, top-10 0,998 / 0,992) — все три выхода
  BGE-M3 одобрены в F16 ценой ≈ 3× латентности запроса (p50 93 против 32 мс) и 659 против 389 MiB VRAM.
  Альтернатива — маскирование пунктуации в Q8_0 (изменение модели → новая подпись; решение J).
- **pplx-embed-context — ограничение эталона, не RX580.** Контекст (до 4 соседних блоков одного источника через
  `<|endoftext|>`) эталон и сервис усекают до 2048 токенов (слот `llama-server` при `-c 8192 -np 4`). Сверка эталона
  с официальным `model.encode` (PPLXQwen3ContextualModel): на dev-пробе 93 % int8-компонент совпадают, расхождение
  ≤ 1 шага; на canary — 86 % и максимум 105 шагов: один из 12 сверенных контекстов длиннее 2048 токенов, его чанки
  усечены (официальная модель видит контекст целиком). На canary 144 из 1254 контекстов упираются в предел, 6 чанков
  пусты (на dev — 11 из 951). Gate RX580 против эталона проверяет бэкенд на одинаковых ids, поэтому вердикт по
  pplx-context действителен только с правилом построения контекстов ≤ 2048 токенов (длинный контекст делится по
  границам чанков); без такого правила модель не одобряется.
- Проверка токенизации: ids сервиса совпали с официальной библиотекой на 100 % проверенных текстов у всех моделей
  (ST / PyLate), pplx-late и mLateOn — token cos 1,0 против PyLate.
- Патчи 0003 и 0004 численно нейтральны: A/B старого и нового бинарника — побитно равные выходы (BACKEND_RESEARCH §4).

## 3. FINAL_CORPUS_ENCODER_APPROVED

Правило (§31): RX580 кодирует корпус только в конфигурации, прошедшей gate на репрезентативном каноническом
подмножестве. Вердикт выдаётся на пару «модель + GGUF-квант» и на каждый выход (dense / multi-vector; подпись
эмбеддинга включает sha256 весов, DN-K2): **FINAL_CORPUS_ENCODER_APPROVED** — gate PASS и на dev-пробе (1918 объектов
dev-канона), и на canary-пробе (1788 объектов канона canary, 15 источников, в том числе OCR) на production-бэкенде
(Vulkan, Mesa 25); один FAIL — NOT_APPROVED; canary не прогонялась (кванты кроме Q8_0) — PENDING_CANARY. Пороги не
пересматривались. Колонка n — число объектов (dense) или токенов документов (multi-vector). Дельта Recall/nDCG на qrels
J — отдельный шаг J (тот же харнес после публикации канона и qrels).
