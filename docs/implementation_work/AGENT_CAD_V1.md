# Агент CAD — `vkm-cad` v1: рисование, команды и объекты Civil 3D без GUI (28.09.2026)

Запрос пользователя (28.09): мост должен рисовать, выполнять команды и строить объекты Civil 3D — точки, TIN,
структурные линии, горизонтали, мульды, трассы и профили, — выводить листы в PDF; только в **новых** документах, не в
открытом AutoCAD пользователя. Дополнение координатора: три слоя — универсальный канал исполнения (scr, AutoLISP,
объектная модель), типизированные инструменты для диплома, обнаружение возможностей (`cad_capabilities`).
Справочник инструментов — [MCP_TOOLS.md §4](../corpus_platform/MCP_TOOLS.md); квитанция живого прогона —
[`cad_v1_smoke.json`](../corpus_platform/receipts/cad_v1_smoke.json). Проект v0 —
[AGENT_G_API_MCP_CAD_DESIGN.md §3](AGENT_G_API_MCP_CAD_DESIGN.md) (часть его допущений опровергнута, §2).

## 2. Инженерные решения (проверены на WORKSTATION)

1. **Headless-движок — `accoreconsole.exe`** (AutoCAD 2026, 25.1.164): `/i <dwg|dxf>` (без `/i` — новый чертёж из
   шаблона профиля), `/s <скрипт>`, `/product ACAD|C3D`, `/l ru-RU`, `/isolate vkm-bridge <каталог>` — системные
   переменные и профиль живут в `$VKM_WORK/cad_jobs/_isolated/<продукт>`; реестр профиля пользователя не меняется
   (кроме следов §5.1). Первый запуск C3D в новом изолированном профиле 5–17 с, дальше ≈ 3,5 с на прогон.
2. **Скрипты**: UTF-8 с BOM и CRLF (кириллица в путях и именах работает; cp1251 и UTF-16 тоже, UTF-8 без BOM —
   нет), глобальные имена команд `_.`/`_`, маркеры пишет LISP в `markers.txt` (`BEGIN`, `FAIL`, `END … OK|FAILED`).
   **Пустая строка в приглашении команды повторяет последнюю команду** — .NET-команда выполнялась трижды; в эпилоге
   пустых строк нет. `stdin = DEVNULL`: без скрипта консоль ждёт ввода с клавиатуры (зависание, которое видел
   координатор: «Команда:» ×3), с DEVNULL — сразу выходит; ошибка `CAD_SCRIPT_NOT_READ`.
3. **Civil 3D без GUI**: `/product C3D` грузит все AECC-модули (`aeccland.dbx`, `aeccroadway.dbx`, …), но не
   UI-команды Civil; объекты создаются через .NET API. ActiveX в Core Console нет (`vlax-get-acad-object` → nil).
4. **.NET без установки SDK**: установлен только SDK 6.0.201 (net8.0 через MSBuild не собрать). Компилятор Roslyn
   (`csc.exe` Visual Studio 2026 или `csc.dll` SDK 6, C# 10) компилирует против управляемых DLL установленного
   рантайма .NET 8.0.22 и `AcCoreMgd`/`AcDbMgd`/`C3D/AeccDbMgd`/`ACA/AecBaseMgd`; 0,2–0,7 с, кэш по содержимому
   (`_plugins/`). `NETLOAD` при `SECURELOAD=0` в изолированном профиле.
5. **Скрытый полный экземпляр**: `DispatchEx("AutoCAD.Application.25.1")` запускает продукт по `CurVer` (обычный
   AutoCAD — Civil 3D COM не загружается) и может присоединиться к чужому серверу — не используется. Работает
   `acad.exe /Automation /product C3D /nologo` + поиск своего объекта в Running Object Table по CLSID и PID окна
   (9 с до готовности; `AeccXUiLand.AeccApplication.13.8` доступен). Цена — изменения профиля пользователя (§5.2),
   поэтому канал закрыт флагом `VKM_CAD_ALLOW_HIDDEN_INSTANCE=1` (решение пользователя) и отказывает, пока открыт
   AutoCAD пользователя.
6. **PDF**: `-PDFIMPORT` работает в Core Console (допущение Phase 0 «не поддерживается» опровергнуто); единицы — дюймы
   страницы при масштабе 1, если PDF не несёт свой масштаб (PDF, напечатанные AutoCAD, возвращаются в мм).
   Печать — `-PLOT` с каноническими именами форматов `DWG To PDF.pc3` (`ISO_full_bleed_A3_(420.00_x_297.00_MM)`):
   отображаемые имена локализованы («ISO без полей A3 …») и в скриптах не используются.
7. **Задания**: `$VKM_WORK/cad_jobs/<job_id>/` — `in/` (копии, SHA-256 до и после), `runs/R001/` (скрипт, запрос,
   консоль, маркеры, копия чертежа на входе и выходе), `out/` (SHA-256 и запись о происхождении), `work/drawing.dwg`
   (продвигается только при `END OK`), `receipt.json`. Один процесс AutoCAD на все задания (`_engine.lock`).
8. **Аварии**: ненулевой код выхода, дочерний процесс-репортёр (`senddmp`, WER), видимое окно процессов задания или
   таймаут → дерево процессов задания убивается (сироты тоже), прогон `CRASHED | DIALOG | TIMEOUT`, ничего не
   продвигается. Отчёты об авариях не отправляются, настройки CER не меняются (пользователь отключил `senddmp`).
9. **Резервный путь** (без Autodesk): Delaunay (scipy 1.18.1, Qhull; координаты центрируются), горизонтали marching
   triangles, dz-TIN с точными объёмами выемки/насыпи, профили. На игрушечных данных совпадает с Civil 3D: 162
   треугольника, dz_min = −1,4091, объём 3567,4 против 3566,2 м³ (0,03 %).

## 4. Наука и провенанс

Выходы — DERIVED: TIN — INTERPOLATION, горизонтали, разности, профили, листы, импорт PDF — DERIVATION; у каждого файла
в `receipt.json` — метод, движок (`CIVIL3D_HEADLESS_DOTNET`, `AUTOCAD_CORE_CONSOLE`, `PURE_PYTHON_FALLBACK`,
`EZDXF`), список MODEL_CHOICE (триангуляция, структурные линии, граница, интервал, правило имён точек…), допущения,
`derived_from` с SHA-256, `crs_status = UNKNOWN_CRS` (или `EXPLICIT_TRANSFORM` с основанием, записанным как
MODEL_CHOICE), `epsg = null`, `review_status = AUTO_EXTRACTED_UNREVIEWED`, `never_input_of_extraction = true`.
Неизвестная отметка точки остаётся неизвестной (точка 2D, в TIN не входит). Разность поверхностей помечена
допущением «не наблюдение». Имена COGO-точек уникальны в чертеже: для нескольких эпох одних реперов —
`name_policy = group_prefix` (записывается как MODEL_CHOICE).

## 5. Побочные эффекты (аудит каждого прогона — в квитанции)

### 5.1 Headless (`accoreconsole /isolate`)

Аудит читает `HKCU\Software\Autodesk\AutoCAD` (только имена значений; лицензионные не читаются) и файлы профилей до
и после прогона. Следы: `R25.1\LastLaunchedProduct` меняется при смене продукта ACAD/C3D; один раз создаются ключи
`AEC\8.8\AecBase80\ObjectDefaults`, `ACAD-9101:419\AcEPlotX`, `DWF Common`; каждая печать оставляет
`PlotandPublishLog*.CSV` в `%LOCALAPPDATA%\Autodesk\<продукт>\rus`; счётчик CER-сессий. Профили пользователя
(`Profiles\…`, `*.aws`, `*.cuix`) не меняются. Автоматического отката нет: мост ничего не пишет в реестр.

### 5.2 Скрытый полный экземпляр (разведка 28.09, три запуска)

Каждый запуск `acad.exe` меняет: положение окна (`FixedProfile\Application Window`), значения профиля (`Osmode`,
`Pickstyle`, путь `ACAD`…), `CurVer` и `LastLaunchedProduct`, файлы `Profile.aws`/`FixedProfile.aws`; автозагрузчик
плагина ANSYS Workbench 2026 R1 дописал частичное меню в `acad.CUIX` обычного AutoCAD (оригинал AutoCAD сохранил как
`acad.bak.cuix` в той же папке) и создал `Workbench261.cuix/.mnr`. Изменения реестра после разведки откатаны точно
(сверка экспорта); восстановление `acad.CUIX` и перенос созданных файлов отклонены системой разрешений — оставлены
пользователю (§8).

## 7. Ограничения и открытые вопросы

- `python_com` живьём после разведки не запускался (решение пользователя; §5.2). Юнит-тесты — на подделках.
- Резервный TIN не соблюдает структурные линии (только их вершины) — записано как MODEL_CHOICE.
- Точки Civil 3D подписываются стилем шаблона NCS; на листе с несколькими эпохами подписи накладываются.
- `ExtractContours(interval)` Civil 3D начинает отсчёт от минимума поверхности; мост строит уровни кратно интервалу
  через `ExtractContoursAt`.
- Пустая строка в пользовательском `scr` повторяет команду — ответственность автора скрипта (описано в справке).
- Сеточные поверхности, сечения, коридоры, сети — через `csharp`, без типизированных инструментов.
- WSL: `test_parquet_commits::test_admission_conflict_does_not_block_others` падает и без этих изменений (не CAD).

## 8. Нужно решение пользователя

1. Разрешить ли `python_com` (`VKM_CAD_ALLOW_HIDDEN_INSTANCE=1`) при изменениях профиля из §5.2.
2. Вернуть ли `acad.CUIX` обычного AutoCAD из `acad.bak.cuix` (та же папка `Support`) и убрать ли созданные разведкой
   `Workbench261.cuix/.mnr`, `maperrorlog*.xml` (21:09, 21:10), `PlotandPublishLog*.CSV`; при следующем запуске
   обычного AutoCAD автозагрузчик ANSYS снова допишет меню.
3. `HKCU\Software\Autodesk\AutoCAD\R25.1\LastLaunchedProduct` меняется прогонами (сейчас — значение последнего
   продукта моста); при необходимости его обновит обычный запуск Civil 3D.
