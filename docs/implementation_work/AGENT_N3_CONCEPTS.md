## Как строится

1. Блоки первичного слоя: TEXT, HEADING, TITLE, CAPTION, LIST_ITEM, ABSTRACT. Из текста убирается LaTeX `$…$`.
   Чинятся OCR-смеси алфавитов («kерна» → «керна», «сiльвинит» → «сильвинит»).
2. Кандидаты:
   - русский — шаблоны pymorphy3 «Прил* + Сущ (+ группы в родительном)», 1–4 слова, с согласованием;
     составные предлоги («с помощью», «в пределах») не становятся терминами;
   - английский и немецкий — цепочки знаменательных слов, у английского главное слово в единственном числе;
   - аббревиатуры: ВЗТ, НДС, InSAR, СКРУ-1; единицы измерения исключены.
3. Единица совместной встречаемости:
   - раздел N1, если передан `section_pages`;
   - иначе страницы от заголовка до заголовка;
   - иначе страница;
   - длинные единицы режутся окнами по 5 страниц.
4. Фильтр терминов:
   - ≥ 2 единиц и ≥ 2 источников (или сид);
   - C-value > 0;
   - кандидат, который в ≥ 90 % случаев стоит внутри одного более длинного («interferometric synthetic»), отбрасывается.
5. Рёбра:
   - `CO_OCCURS`: NPMI ≥ 0,2, ≥ 3 общих единиц, ≥ 2 источников; top-30 соседей на термин по
     `score = npmi·n/(n+2)`; вложенные пары не считаются;
   - `DEFINED_AS`: «X — это», «X называется / называется X», «под X понимается», «X (от …) —», «is defined as»,
     «is called»;
   - `SAME_AS`: «водозащитная толща (ВЗТ)», «ползучесть (creep)»;
   - `CONTAINS`: «длительная прочность» ⊂ «предел длительной прочности»;
   - N2 добавит `SYMBOL_OF` в ту же схему.
6. Пары считаются на GPU (cuDF), если он есть, иначе в DuckDB. Сообщества Leiden строит cuGraph; на CPU поле
   `community` пустое.

## Открытые вопросы (для координатора)

1. ID терминов зависят от морфологии: ключи pymorphy3 и стеммера разные. На CORE нужен extra `navigation`,
   иначе столбец `morphology` покажет `snowball` или `crude`, а ID будут другими.
2. В NAVIGATION_LAYER §4 поля называются `df_sections` и `n_sections`. В коде — `df_units` и `n_units`, потому что
   единица не всегда раздел. Есть и новое: ребро `CONTAINS` и лишние поля (`lemma_key`, `kind`, `cvalue`, `idf`,
   `community`, `morphology`, `edge_id`, `rule`, `example_block_ids`). Документ и README квитанций ведёт координатор.
3. Шум:
   - фамилии авторов из ссылок внутри блоков TEXT;
   - повторённые аннотации в 3–4 источниках завышают NPMI у редких терминов («реология»).
   Следующий шаг — учитывать `duplicate_page_candidates` или minhash единиц и помечать имена по доле заглавных.
4. Форма показа:
   - родительный хвост остаётся как напечатан («ползучесть солей»);
   - изредка pymorphy даёт две леммы одного слова («снимок» и «снимка»); запрос скрывает такие дубли.
5. С реальными разделами N1 связка не проверялась: разделов ещё нет, тест синтетический.
6. `vkm-corpus nav build --part concepts` регистрирует N1. `build(con, **kwargs)` игнорирует чужие аргументы,
   статистика — в метаданных схемы `terms`.
7. Результат лежит в WSL: `~/vkm/nav/out/concepts/full_gpu/` (`full_cpu/` — контроль). `manifest.json` пишет CLI.
