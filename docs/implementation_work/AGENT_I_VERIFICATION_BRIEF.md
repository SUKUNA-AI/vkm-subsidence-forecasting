# Бриф агента I — независимая проверка Corpus Platform v0

Агент I проверяет готовую платформу **независимо от исполнителей**: не по их отчётам, а по репозиториям, данным и
живым сервисам. Итог каждого критерия — одно из `PASS`, `FAIL`, `BLOCKED`, `NOT_RUN`, без смягчений. `FAIL` по любому
основному критерию означает, что задача NOT READY, пока его не исправят (постановка §61).

## Что можно и чего нельзя

| Можно | Нельзя |
|---|---|
| читать оба репозитория, данные `$VKM_DATA_ROOT` на CORE и STAGING на WORKSTATION | менять код, данные, реестр, конфигурацию, compose, секреты |
| запускать тесты (`tests/corpus`, `tests/world`) в WSL и read-only команды CLI (`status`, `validate`, `verify`, `smoke`, `query`) | перезапускать или останавливать сервисы; трогать текстовый реранкер на EDGE |
| read-only SSH-команды на CORE и EDGE (`docker ps`, `docker inspect`, `nvidia-smi`, `curl` на health/status) | вызывать GLM-OCR мимо pipeline, запускать прогоны pipeline, публикацию, reconcile, пересборку проекций |
| вызывать API и MCP (read-сервер) как клиент | ставить или подтверждать задания в `vkm_ops` |
| один проверочный вызов каждого реранкера (text и visual) и один одновременный | печатать секреты, токены, адреса, пути хоста в отчёт |

Если проверка требует запрещённого действия (например, демонстрации пересборки), агент I пишет `BLOCKED` с причиной и
ссылкой на квитанцию исполнителя, которую он проверил (квитанция сама по себе — не доказательство `PASS`).

## Критерии

Для каждого критерия — команда или запрос, фактический результат (числа, идентификаторы), вердикт.

1. **CareerOps (§54)** — квитанция вывода существует; архив есть и его SHA-256 совпадают с квитанцией; старые сервисы,
   таймеры, SeaweedFS и БД `careerops` отсутствуют; текстовый реранкер работает (не перезапускался: `StartedAt`,
   `RestartCount`); PostgreSQL-сервер работает; SSH и сеть работают.
2. **GLM-OCR (§55)** — ревизия модели и digest образа совпадают с pin; GPU/CUDA работают; в каноне есть страницы
   `OCR_OK` сканов, таблицы и формулы, полученные OCR; сырые ответы (`OCR_RAW`) сохранены и читаются по ID артефакта;
   запуск описан воспроизводимо (DEPLOYMENT).
3. **Реранкеры (§31, §56)** — text работает; visual принимает настоящие изображения страниц; обе модели резидентны на
   GTX 1650 одновременно; одновременные запросы проходят; нет OOM; нет выгрузки/перезагрузки моделей между запросами;
   точные квантизация и ревизии записаны.
4. **Канон (§57)** — реестр обработан (251 ID, статусы источников); хеши сверены (`registry verify`); нет тихих потерь
   (у каждой страницы каждого активного источника есть строка со статусом; число страниц = ожидаемому); Parquet
   читается; DuckDB работает; provenance полон (`provenance_trace` / MCP `trace_document_provenance` для выборки
   объектов каждого вида); валидатор снимка PASS (`canon validate --deep --acceptance --expected-sources 251`).
5. **Пересборка (§46)** — квитанция удаления и восстановления DuckDB, Neo4j и OpenSearch из канона: числа до и после
   совпадают; проверить квитанцию и текущие числа.
6. **Neo4j (§58)** — Source → Work, Work → Author, Source → Pages, Page → objects, Work → citations (где надёжно);
   каждый узел прослеживается до канонического ID/источника/страницы (`graph verify`); скрипт пересборки есть.
7. **OpenSearch (§59)** — русский поиск (`search smoke`), фильтры, стабильные ID в ответах, ID кандидатов принимает
   реранкер; пересборка описана и выполнялась.
8. **MCP (§60)** — сценарий только через MCP: `search_text` → кандидаты-страницы → `rerank_text` → `get_page` →
   рисунки страницы → `rerank_visual` → `get_object` → `trace_document_provenance`; повторить самостоятельно через
   read-сервер MCP.
9. **Научная безопасность (§49)** — автоматические объекты имеют `AUTO_EXTRACTED_UNREVIEWED`; нет FACT,
   REVIEWED_MEASUREMENT, ACCEPTED_PARAMETER, ACCEPTED_FORMULA в автоматике; OCR не выдаётся за факт; дубли источников
   не считаются независимыми подтверждениями (Work ≠ Source).
10. **Интерпретируемость (§50)** — для случайной выборки объектов каждого вида ответить на вопросы §50 по данным.
11. **Тесты (§47)** — полный прогон `tests/corpus` и `tests/world` в WSL; перечислить PASS/FAIL/SKIP; живые тесты
    (`services`, `gpu`, `desktop`) — отдельно; не запущенное — `NOT_RUN`.
12. **Гигиена репозиториев** — `scripts/verify_canonical_repository.py` (с `VKM_RESOURCES_ROOT`), тест утечек, нет
    данных выполнения, секретов, адресов и путей хоста в отслеживаемых файлах; ссылки документов разрешаются.
13. **Мост Autodesk и draw.io** — статус моста (обнаружение, read-only COM), MCP draw.io создаёт и экспортирует схему в
    scratch.
14. **Топология и документация (§53)** — DEPLOYMENT, OPERATIONS, MCP_TOOLS, MODEL_SERVICES, DATA_CONTRACTS,
    ARCHITECTURE, CAREEROPS_MIGRATION_RECEIPT существуют и соответствуют факту (выборочно сверить команды и версии).
