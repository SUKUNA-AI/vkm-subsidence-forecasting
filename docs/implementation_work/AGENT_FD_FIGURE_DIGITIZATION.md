# Агент FD — оцифровка графиков корпуса: прототип v0 (29.09.2026)

Запрос пользователя (29.09): «оцифровка графиков — AutoCAD с Civil вроде сами переводят векторные чертежи; тут надо
посмотреть». Цель — числовые ряды из графиков корпуса (оседания и конвергенция во времени, профили мульд по
профильным линиям, ряды реперов) с провенансом: реальных рядов наблюдений не хватает для проверки прогноза.
Уточнения координатора по ходу работы: сначала маршрут AutoCAD и быстрая витрина; затем решить три ограничения —
скрытый текст страницы, подписи осей в виде контуров глифов, растровые графики.

Код — пакет [`src/vkm_corpus/figures/`](../../src/vkm_corpus/figures/__init__.py), тесты —
`tests/corpus/test_figures_*.py` (синтетические графики), квитанция —
[`figure_digitization_v0.json`](../corpus_platform/receipts/figure_digitization_v0.json). Мост AutoCAD —
[AGENT_CAD_V1.md](AGENT_CAD_V1.md), [MCP_TOOLS.md §4](../corpus_platform/MCP_TOOLS.md); векторы конвейера —
[PIPELINE.md §6](../corpus_platform/PIPELINE.md).

## 3. Маршрут B: AutoCAD

1. **Вырезка** (`figures/crop.py`). Страница копируется без изменения содержимого, CropBox ставится по рамке рисунка
   (+12 pt). `-PDFIMPORT` берёт CropBox за начало координат чертежа: 1 единица = 1 дюйм, начало — левый нижний угол
   рамки. Геометрию вне рамки импорт всё равно тащит, поэтому после импорта пути обрезаются по рамке.
2. **Импорт** — `cad_pdf_import` (`-PDFIMPORT`, headless `accoreconsole`, изолированный профиль). Пакетами до 20
   страниц: одностраничные вырезки собираются в пакетные PDF. Прогон: 16 пакетов, задание
   `CADJ-20260929T094022Z-92219db2`, 320/320 DXF, 0 отказов, ≈ 4 с на страницу.
3. **Что делает `-PDFIMPORT` и как это учтено** (`figures/dxf_route.py`):

   | Наблюдение | Учёт |
   |---|---|
   | Текст → MTEXT с позицией и высотой; ширины нет | центр подписи оценивается по ширинам знаков, затем уточняется словами PDF |
   | Кривая (Безье) → обычно один SPLINE на сегмент | концы — вершины пути PDF, то есть нанесённые точки |
   | На 49 из 320 рисунков цепочка сегментов переаппроксимирована одним SPLINE с двойными узлами | узлы совпадают с вершинами PDF лишь в 49 % случаев, остальные лежат внутри сегмента; берутся только концы, ряд получает флаг `SPLINE_INTERIOR_NOT_RECOVERED`; замкнутый сплайн — контур маркера |
   | Прямые участки → LWPOLYLINE и дуги огромного радиуса | берутся концы |
   | Слои без смысла: «PDF _Геометрия», «PDF _Сплошная заливка», «PDF _Текст» | ряды различаются цветом, толщиной и штрихом |
   | Объекты цвета слоя пишутся BYLAYER; цвет слоя — цвет первого объекта | цвет берётся через таблицу слоёв (без этого терялся ровный ряд 1990 г. на рис. 3) |
   | В вырезке строка подписей «187 188 … 196» склеивается в один MTEXT | MTEXT сверяется со словами видимого текстового слоя той же вырезки: разбивается, позиции точные |
   | Текст, лежащий в PDF за пределами видимой страницы (VKM-SRC-017 с. 3: 752 знака из 4 605), импорт кладёт на чертёж | MTEXT без видимого соответствия отбрасывается |
   | Отсечение (clip) соблюдается | часть ряда за пределами области графика не импортируется (рис. 2а) |
   | Повёрнутые подписи, записанные в PDF контурами, → SPLINE и HATCH | §4.2 |
   | CIRCLE — маркеры | берутся как маркеры |

   Насколько вершины DXF совпадают с вершинами путей PDF той же страницы (прогон по 320 рисункам, допуск 0,15 pt):

   | Элемент DXF | Вершин | На вершине PDF |
   |---|---|---|
   | вершины LWPOLYLINE | 152 336 | 99,93 % |
   | концы ARC | 1 054 | 99,91 % |
   | концы односегментных SPLINE | 123 551 | 99,96 % |
   | концы многосегментных SPLINE (49 рисунков) | 4 842 | 95,9 % |
   | внутренние узлы многосегментных SPLINE | 3 139 | 48,9 % |

   Все внутренние узлы — двойные: кубика склеена с непрерывной касательной. По самим сплайнам нельзя понять, какой
   узел — вершина PDF, а какой делит сегмент. Проверка «одна и та же кубика по обе стороны узла» их не различает:
   куски приближают исходную кривую с точностью около 0,01 pt, а не повторяют её. Поэтому маршрут B берёт у таких
   сплайнов только концы и ставит флаг. Маршрут A этих потерь не имеет.

   Отвергнутый вариант вырезки: вымарывание текста вне рамки (redaction MuPDF). Оно переписывает весь поток
   содержимого, а режим удаления графики `REMOVE_IF_COVERED` удаляет пути нулевой высоты — ровный ряд, линию оси.
4. **Калибровка** (`figures/calibrate.py`):
   - строка числовых подписей даёт ось x, столбец — ось y;
   - шкала линейная, log10 или даты (dd.mm.yyyy, mm.yyyy, десятичная запятая, «–60»);
   - подписи привязываются к засечкам и сетке, горизонтальность проверяется с наклоном ≤ 3 % (PDF округляет до 0,1 pt);
   - до двух выбросов отбрасываются (номер рисунка в строке подписей);
   - подписи легенды (например, «1 … 6») в оси не берутся;
   - остатки подгонки сохраняются.
5. **Кривые** (`figures/series.py`):
   - куски группируются по стилю (цвет, толщина, штрих) и сшиваются по совпадающим концам;
   - оси, сетка, засечки (короткие штрихи на рамке) и контуры штрихов пунктира отбрасываются;
   - легенда — короткий горизонтальный образец и слова справа от него;
   - подпись присваивается стилю, только если он один ряд: монохромный чертёж остаётся без подписей, флаг `MULTI_CHAIN_STYLE`;
   - маркеры: ≥ 3 малых фигур одного цвета и размера, точка — центр; буквы-контуры отсекаются по плотности.
6. **Погрешность точки** — полуширина в единицах величины: rms остатков подгонки подписей оси ⊕ квант координат
   0,05 pt. Толщина штриха не добавляется: вершина — это центр линии.

## 4. Решённые ограничения

### 4.1 Скрытый текст страницы

Вырезка + сверка MTEXT с видимым текстовым слоем (§3.3). Проверено на VKM-SRC-017 с. 3:
- в потоке страницы 4 605 знаков; 752 из них (442 из 1 202 фрагментов) лежат вне видимой области страницы;
- импорт всей страницы дал 221 MTEXT, 155 из них видимым текстовым слоем не подтверждаются;
- в вырезке рисунка 25 MTEXT: 3 неподтверждённых отброшены, 1 склеенная строка разбита;
- подписи обеих осей привязываются к засечкам.

Тесты `test_merged_row_is_split_and_offpage_text_dropped`, `test_crop_sets_cropbox_and_keeps_content`.

### 4.2 Подписи осей в виде контуров глифов

Пример — даты на VKM-SRC-034 рис. 4: в PDF это заливки контуров, текста нет; в DXF — SPLINE и HATCH.

Порядок работы:
1. Сначала — текст корпуса в области: канонические блоки и `OCR_RAW` страницы. Ядро принимает его параметром
   (`corpus_labels`), но прогон v0 его не подаёт. Для рис. 4 в полосе подписей текста корпуса нет.
2. Затем включается локальный помощник, только для калибровки производного объекта:
   - кусочки глифов вне области графика кластеризуются (одиночная связь, радиус 1,1 высоты прописной);
   - направление подписи находится по PCA (45°);
   - подпись рендерится из PDF в 600 dpi, закрывается маской своего повёрнутого прямоугольника (соседние подписи
     в осевом прямоугольнике перекрываются) и поворачивается горизонтально;
   - OCR-чтение;
   - привязка — конец подписи, ближний к графику, со снапом к вертикальным линиям сетки;
   - подгонка оси дат.

Выбор помощника — **Tesseract 5.5.3** (уже установлен в WSL):
- CPU, детерминирован, режим одной строки `--psm 7`, белый список `0123456789.,-/`;
- GLM-OCR через transformers потребовал бы загрузки модели на GPU ради 14 коротких числовых подписей;
- сопоставление с шаблонами глифов из того же PDF требует шрифтозависимой сегментации знаков.

Провенанс: `calibration.ocr = {engine, version, psm, whitelist, render_dpi}`, `label_source = LOCAL_OCR`, флаг
`LOCAL_OCR_CALIBRATION`. В канон ничего не пишется.

Результаты:
- рис. 4: 14/14 дат прочитаны верно, rms оси 0,034 pt; оба маршрута;
- в прогоне по кандидатам помощник откалибровал ось у 19 (A) и 6 (B) рядов.

Контроль:
- 9 вершин кривой рис. 4 за 2010–2022 гг. попадают точно на 9 дат эпох из легенды рис. 3;
- значения совпадают с рис. 3 в позиции категории 99 с точностью ≤ 0,5 мм;
- в позиции 98 расхождение до 7 мм: нумерация реперов двух рисунков расходится на один;
- это записано как замечание к рисункам, не разрешено.

### 4.3 Растровые графики

Модули `figures/raster.py`, `raster_digitize.py`.

1. **Оси.** Длинные линии находятся морфологическим открытием по нейтральным тёмным пикселям. Разрывы от цветных
   меток на оси (красный кружок на линии СКРУ-1) продлеваются.
2. **Подписи.** Сначала текст корпуса в рамке (параметр `corpus_words`; прогон v0 его не подаёт, у растров витрины
   его нет). Иначе Tesseract по четырём полосам вокруг рамки: связные компоненты группируются в подписи с учётом
   точек и запятых, каждая подпись читается отдельно. Разреженный OCR всей картинки склеивал соседние подписи в
   одну строку.
3. **Особые оси:**
   - кусочно-линейная ось — подписи на неравных расстояниях; неверно прочитанная подпись отсекается по наибольшей
     монотонной подпоследовательности;
   - **ось маркеров** — точки реперов на линии профиля нумеруются счётом, напечатанные номера только сверяют
     смещение; устойчиво к неравному шагу и непрочитанным подписям.
4. **Кривые.** Многокривое слежение по столбцам: каждый отрезок пикселей кривой в столбце отдаётся треку с ближайшим
   прогнозом (последняя точка + наклон), цвет чернил — вторичная стоимость. Кластеризация k-means в Lab отброшена:
   ореолы сглаживания и JPEG делили одну кривую на несколько кластеров.
5. **Сшивка фрагментов** — по прогнозу и цвету, через разрывы под подписями на кривой.
6. **Подписи кривых.** Надписи на кривой («1992») — по геометрии, легенда — по цвету.
7. **Разрывы не заполняются**, флаг `TRACE_GAP_NOT_FILLED`.
8. **Выборка точек:**
   - в маркерах реперов, если они есть;
   - иначе в вершинах ломаной линейного графика (Дуглас–Пекер; соседние вершины сливаются);
   - иначе в маркерах ряда;
   - иначе по осевой линии.
9. **Контроль повторным рисованием:** доля чернил вблизи восстановленных кривых и доля перерисованных пикселей на
   чернилах.
10. **Погрешность:** rms калибровки ⊕ половина исходного пикселя ⊕ половина толщины линии.

Результаты:

| Рисунок | Результат |
|---|---|
| VKM-SRC-011 рис. 4.7б (линия 12 СКРУ-1) | 5 эпох по 28–29 реперов (46–76); ось x по 38 маркерам и 10 согласных подписей; ±6–7 мм на точку (растр ≈ 100 dpi); контроль: чернила 0,96, точность перерисовки 0,87; точки под надписями эпох и бледное дно мульды 2004 г. не заполнены |
| VKM-SRC-024 рис. 26 / 27 | 12 и 11 вершин; против таблицы данных под графиком: все ≤ 0,5 / ≤ 0,8 мм |
| VKM-SRC-002 слайд 15, линия 6 | обе оси (15 подписей x с десятичной точкой, 7 подписей y); против ручной оцифровки в PUBLIC: нивелирование rms 2,4 мм (n = 24), InSAR rms 1,1 мм (n = 12); крупные маркеры дробят кривую |
| VKM-SRC-012 рис. 2.8 | отказ: подписи y не прочитаны, 26 похожих цветов дробятся, легенда не сопоставлена |

Витрина растров снята по рамкам, заданным вручную. Рис. 4.7б в каноне отдельным рисунком не выделен: на с. 131 один
объект-рисунок, он покрывает верхнюю часть страницы. Растровый прогон (§1) идёт по рамкам канона. Там у рис. 26 и 27
VKM-SRC-024 ось x остаётся неоткалиброванной: подписи категорий — обозначения реперов, а не числа.

## 5. Маршрут A и сравнение маршрутов

Маршрут A — `figures/pdf_route.py`:
- пути PyMuPDF с учётом отсечения: путь вне всех активных clip отбрасывается, как это делает `-PDFIMPORT`;
- тонкие залитые прямоугольники считаются линиями;
- текстовый слой — слова с направлением строки; подпись оси собирается из всей строки PDF, иначе от «Время, сут»
  оставалось одно слово и терялись величина, единица и признак оси времени.

Витрина, 5 векторных рисунков (итоговый код):
- на четырёх рисунках число рядов и точек A и B одинаково: 15 × 110, 10 × 10, 3 × 11, 6 × 412;

## 6. Набор `figure_series`

Схема `vkm.figure_series/0`, модуль `figures/dataset.py`. Строка — один ряд. Поля:

| Группа | Поля |
|---|---|
| идентификаторы | `series_id`, `figure_id`, `source_id`, `page_id`, `work_id`, `figure_label`, `caption_block_id` |
| ряд | `series_label_raw` — как напечатано; `series_color`; `series_nature = UNCLASSIFIED` |
| оси | `x/y_quantity_raw`, `x/y_unit_raw`, `x/y_title_raw`; `x/y_axis_kind` (LINEAR, LOG10, DATE, PIECEWISE, MARKERS); `x_is_time` |
| точки | `points[]`: x, дата, y, `x_err`, `y_err`, координаты чертежа; `x/y_err_median`, `error_model` |
| калибровка | JSON: подписи, привязки, остатки, отброшенные подписи, OCR |
| происхождение | `sampling`, `route`; `status = DERIVATION`, `review_status = AUTO_EXTRACTED_UNREVIEWED`; `available_from` и `available_basis` — дата публикации; только год → последний день года; нет года → `UNKNOWN`, флаг `AVAILABILITY_UNKNOWN` |
| прочее | `source_site_scope_raw` (флаг `SCOPE_INHERITED_FROM_SOURCE`); `provenance` — sha256 источника, вырезка, задание CAD и sha256 DXF, версия оцифровщика, хеш конфигурации |
| флаги | `X_UNCALIBRATED`, `Y_UNCALIBRATED`, `LEGEND_UNMATCHED`, `MULTI_CHAIN_STYLE`, `LOCAL_OCR_CALIBRATION`, `SPLINE_INTERIOR_NOT_RECOVERED`, `RASTER`, `TRACE_GAP_NOT_FILLED`, `MODEL_HINT_IN_CAPTION`, `AVAILABILITY_UNKNOWN`, `SCOPE_INHERITED_FROM_SOURCE` |

Проверка строк:
- статусы FACT, REVIEWED_MEASUREMENT и прочие отклоняются;
- откалиброванное значение без погрешности отклоняется;
- доступность без даты и без явного UNKNOWN отклоняется.

Модельный результат и наблюдение автоматически не различаются. Слова «расчёт», «прогноз», «МКЭ» в подписи рисунка
ставят только флаг `MODEL_HINT_IN_CAPTION`.

Набор собран оцифровщиком `fd-0.1.2` (версия и хеш конфигурации — в провенансе каждой строки). Размещение —
NAV-подобная часть на WORKSTATION рядом с выходами сборки NAV: `nav/out/figure_series/<снимок>/`.
- `figure_series_v0.parquet`: маршруты A и B, 3 968 рядов;
- `figure_series_raster_v0.parquet`: маршрут R, 215 рядов;
- JSONL-копии и `manifest.json`;
- sha256 — в квитанции.

В PUBLIC значений нет. На CORE набор не выкладывался.

## 7. Что не работает

- **Сканы и растры низкого разрешения.**
  - Растровый маршрут калибрует обе оси у 36 % графиков каталога.
  - Отказы:
    - подписи мелкие или в том же цвете, что линии;
    - много похожих цветов (VKM-SRC-012 рис. 2.8, 26 эпох);
    - крупные маркеры;
    - оси без линий.
- **Пунктир из отдельных штрихов** (оба векторных маршрута). Сшивка по концам соединяет только касающиеся куски.
- **Одноцветные чертежи** с несколькими кривыми и выносками. Подписи кривых не сопоставляются, выноски иногда
  примыкают к кривым.
- **Категориальные оси** с текстовыми подписями (обозначения реперов): x не калибруется. Индекс категории есть
  порядок вершин; его нужно сопоставить с таблицей.
- **Повёрнутые страницы** (31 рисунок) в v0 пропускаются: кадр DXF повёрнутой страницы не обработан.
- **Классификация** «наблюдение / модель» и атрибуция рудника — только при ревью.

## 8. Продуктизация: оценка трудозатрат

1. Маршрут A как стадия NAV (`vkm-corpus nav build --part figures`) по артефактам `VECTOR_PATHS_JSON` и блокам
   канона. Текст и пути уже есть в каноне и артефактах, PDF не нужен. Выкладка в `nav.duckdb` и инструмент MCP
   `find_figure_series`. Около 2–3 дней.
2. Ревью-очередь: витрина из трёх картинок на каждый ряд. Переход в evidence — только через правила evidence
   (статус FACT ставит человек по печатному первоисточнику). Около 2 дней.
3. Растровый маршрут:
   - посев цветов из легенды;
   - вычитание сетки;
   - маркеры произвольной формы;
   - GLM-OCR конвейера вместо Tesseract для подписей с кириллицей.

   Около 1 недели. Отдельно — сканы DjVu.
4. Штрихи и одноцветные чертежи: сшивка коллинеарных штрихов с зазором, разбор выносок. Около 2–3 дней.
5. Маршрут B оставить как сверку и путь к DWG (профили Civil 3D для графической части).

## 9. Воспроизведение

Драйвер — `python -m vkm_corpus.figures.sweep <шаг>`; все пути машины передаются аргументами.

```text
# 1. кандидаты: копия DuckDB снимка и артефакты — только чтение
sweep discover --db <DuckDB снимка> --artifacts <корень артефактов> --out <W>/candidates.json
# 2. одностраничные вырезки в пакетных PDF по ≤ 20 страниц + manifest.json
sweep prepare --cands <W>/candidates.json --private-root <клон PRIVATE> --out-dir <W>/batches
# 3. маршрут B: каждый пакет — vkm-cad cad_pdf_import (консоль, CP-43);
#    jobs.json: {"batch_NNN.pdf": {"job_id": "CADJ-…", "out_dir": <каталог out задания>}}
# 4. маршруты A и B → figure_series_v0.{jsonl,parquet}, sweep_log.json, summary.json
sweep digitize --cands <W>/candidates.json --private-root <клон PRIVATE> --batches-dir <W>/batches \
      --jobs jobs.json --out-dir <W>/figure_series
# 5. маршрут R по страницам каталога мониторинга ({"VKM-SRC-…": [страницы]}, список — в квитанции)
sweep raster --db <DuckDB снимка> --private-root <клон PRIVATE> --pages-json pages.json --out-dir <W>/figure_series
# 6. NAV-подобная часть с manifest.json (только WORKSTATION)
sweep publish --src <W>/figure_series --dst <nav out>/figure_series/<снимок> --snapshot <снимок>
# тесты: синтетические графики; OCR- и растровые тесты — при Tesseract и OpenCV
python -m pytest -q tests/corpus/test_figures_*.py
```

Прогоны выполнялись так:
- тяжёлые шаги — в WSL под `systemd-run --user --scope -p MemoryMax=12G -p MemorySwapMax=0`;
- AutoCAD — через `vkm-cad` в консоли: задания `CADJ-20260929T085856Z-4c8b4f0f` (витрина) и
  `CADJ-20260929T094022Z-92219db2` (прогон);
- отчёты об авариях не отправлялись, документы пользователя не открывались.
