Ветка `claude/agent-n2-nav-formulas-2026-09-28` (от `claude/corpus-platform-v0-2026-09-28`). Проект слоя —
[NAVIGATION_LAYER.md](../corpus_platform/NAVIGATION_LAYER.md), §3. Квитанция —

Статус всех строк — `AUTO_EXTRACTED_UNREVIEWED`. Это навигация, а не свидетельства. Смысл формул, законы и значения
параметров не утверждаются. Кандидаты параметров — сырьё для будущего слоя L2 с проверкой по правилам evidence.

## Что сделано

- `src/vkm_corpus/navigation/formulas.py` — `build(con, *, section_pages=None, sections=None) -> dict[str, pa.Table]`.
  Только правила, без LLM и моделей. Полный снимок собирается за 13 с. Возвращает четыре таблицы:
  - `formula_context` — номер формулы, вводный блок, блоки «где…», блок-хозяин INLINE-формулы, раздел.
    Источники номера по порядку:
    1. блок `FORMULA_NUMBER` рядом с формулой;
    2. строка текстового слоя, которая заканчивается номером и выходит правее формулы;
    3. `\tag{}` или хвост `(3.2)` в LaTeX;
    4. `equation_label` строки.
  - `formula_symbols` — идентификаторы LaTeX с нормализацией (`\sigma_{1}` → `σ_1`, `\dot{\varepsilon}` → `ε̇`) и
    стороной `=` (LHS/RHS/UNKNOWN). Определения из списка «где σ — напряжение, МПа» дают описание и единицу.
    Символы сопоставляются после нормализации обеих сторон:
    - LaTeX ↔ Unicode;
    - строки индексов текстового слоя (`ВМП` + `Q` → `Q_ВМП`);
    - похожие кириллические и латинские буквы.

    Поддержан английский вид «where σ is the stress».
  - `formula_refs` — ссылки в тексте («по формуле (3.2)», «подставляя (2.1) в (2.4)», «Eqs. (7.11)–(7.13)»,
    «формулу 4.1»). Каждая разрешается в формулу с тем же номером того же источника. Порядок выбора: единственная;
    тот же раздел или глава (если передан `section_pages`); ближайшая предыдущая по порядку чтения.

    Тип ссылки определяется по глаголу предложения: `MENTION` / `SUBSTITUTION` / `DERIVATION_HINT`. Поле
    `citing_formula_id` — формула, перед которой стоит текст ссылки. Так видно, какие формулы из каких получены.
  - `formula_parameters` — кандидаты «символ = число [единица]» из блока «где…», следующего блока или из
    формулы-присваивания. Диапазоны сохраняются как `value_min`/`value_max`. Условия (`t = 0`, `α = 1`),
    перечисления индексов и произведения (`2 V_i`) отбрасываются.
- `src/vkm_corpus/navigation/formulas_query.py` — чистые функции для MCP:
  - `get_formula_context(con, formula_id)`;
  - `find_formulas(con, *, concept=None, symbol=None, source_id=None)`.

  Поиск по символу работает только внутри одного источника. Голый символ между книгами не сопоставляется — это
  `ValueError`. Книги встречаются только через слова определений (`concept`).
- `tests/corpus/test_nav_formulas.py` — 11 тестов на синтетических строках: LaTeX, «где…», номера, ссылки,
  параметры, сборка на синтетическом каноне, детерминизм, запросы. Результат: 11 passed в WSL venv-corpus;
  `test_public_hygiene.py` — 6 passed.

## Ручная проверка (40 случайных на вид, новое зерно после настройки правил)

| Вид | Точность | Критерий |
|---|---|---|
| номер DISPLAY-формулы | 40/40 | номер напечатан у этой формулы (проверено по раскладке страницы) |
| блок «где…» | 40/40 | это пояснение сразу после формулы или её группы |
| символ ↔ определение | 38/40 | определение описывает этот символ |
| ссылка → формула | 40/40 | ссылка указывает на нужную формулу источника; тип верен в 39/40 |
| кандидат параметра | 31/40 | строго: значения-случаи, индексы и неверные единицы считаются ошибкой |

Виды ошибок:

- параметры:
  - значения-случаи («при n = 2», «t = 1 мин»);
  - присвоения индексов;
  - показатель «10–4», потерянный в текстовом слое;
  - `tan θ = 0,42` → θ;
  - усечённая единица;
- определения:
  - описание — не смысл («calculated at …»);
  - символ составного термина (`Π₁v` → `v`).

До настройки (зерно 20260928) было:

- номера — 35/40: цифры без скобок, индекс «(1)» в строке формулы;
- определения — 36/40: описания-указатели «given by Eq. …»;
- ссылки — 38/40: простые номера из списков шагов;
- параметры — 14/40: условия и перечисления.

Эти виды ошибок исправлены правилами.

## Как пользоваться

```python
from vkm_corpus.navigation import formulas, formulas_query as fq

tables = formulas.build(con)                                   # con: DuckDB снимка со схемой canonical
tables = formulas.build(con, section_pages=sp, sections=secs)  # после N1: section_id и предпочтение главы
fq.register_tables(con, tables)             # или fq.attach_parquet(con, "<каталог derived/navigation/<snapshot>>")
fq.get_formula_context(con, "VKM-SRC-044:p0072:m…")            # номер, вводная, «где…», символы, ссылки, параметры
fq.find_formulas(con, concept="скорость ползучести")           # формулы разных книг через смысл символов
fq.find_formulas(con, symbol=r"\sigma_1", source_id="VKM-SRC-044")
```

Регистрация в CLI остаётся за N1: `vkm-corpus nav build --part formulas` вызывает `build(con, **kwargs)`. Лишние
аргументы игнорируются. `section_pages` принимается в любом из видов:

- таблица Arrow;
- список словарей;
- путь к parquet.

Нужны столбцы `section_id` и `page_id`. Если передан `sections` с `parent_section_id`, ссылки разрешаются сначала
внутри главы.

Для графа и N3:

- `symbol_id` (`FSY-…`) — символ внутри источника;
- `definition_key` — грубые основы слов определения, опора для рёбер `SYMBOL_OF`.

## Открытые вопросы

1. `section_id` пока NULL: датасета N1 ещё нет. После него нужно пересобрать слой (13 с).
2. INLINE-формулы: не разбираются пояснения «где…» внутри того же абзаца и приложения вида «скорость ползучести ε̇».
3. Кандидаты параметров: около 20 % — значения-случаи и индексы. Для L2 нужен отбор с проверкой.
4. Покрытие номеров — 60 % DISPLAY. Часть формул не нумерована. У OCR-кропов номер мог не попасть в блок.
   Для регионов с несколькими номерами первый номер основной, остальные — в `extra_numbers`.
5. Блок «где…» после группы формул прикрепляется ко всем формулам группы. Определения без символа в LaTeX
   прикрепляются только к последней формуле.
