# Пространственная сборка ВКМ

Сборщик [`build_spatial_model.py`](../../scripts/build_spatial_model.py) связывает существующие входы,
планы трёх рудников, скважинные ограничения, календари и DMA. Геометрические пакеты остаются в PRIVATE
или ignored `work/`. Полномочия — [D-20](../governance/SPATIAL_MODEL_AUTHORIZATION_2026-10-16_RU.md).

Это геометрический этап. Решатели, обучение и прогнозный бенчмарк не запускаются. Научный допуск
производных — NOT_CHECKED; проверка чтения агентом не становится HUMAN_REVIEWED.

## Воспроизведение

Используется уже установленный Python QGIS с GDAL, numpy, scipy, shapely, Pillow и matplotlib. Для экспорта и CPU-просмотра
3D используется существующий ParaView. Корень PRIVATE задаётся через `VKM_RESOURCES_ROOT`, путь к `pvpython` —
через `VKM_PARAVIEW_PYTHON`. Абсолютные пути машины в конфигурации не записываются; версии GIS и версия/хэш
исполняемого файла ParaView фиксируются при `--pin`.

Для отдельных чистых Python-проверок зависимости описаны extra `geometry` в `pyproject.toml`.
Python проекта и Python поставки QGIS — разные окружения: установка extra проекта не заменяет GIS runtime.
При launcher, который удаляет Git из PATH, задайте `VKM_GIT_EXECUTABLE` полным путём существующего Git.
Для пакетной сборки используйте `PYTHONUTF8=1` и `QT_QPA_PLATFORM=offscreen`.

```powershell
# Выполнять из PUBLIC через существующий python-qgis launcher.
python-qgis scripts/build_spatial_model.py --pin --config work/spatial_run/model.json
python-qgis scripts/build_spatial_model.py --config work/spatial_run/model.json --out work/spatial_run/package
```

`--pin` сохраняет точные хэши выбранных входов и кода; существующую конфигурацию не заменяет. После изменения
опоры или кода создаётся новая конфигурация. Шаги переиспользуются только при совпадении входов, параметров,
кода, зависимостей и проверенных хэшей каждого выхода. Изменение геологических опор не пересобирает DSM.
Прерывание сохраняет незавершённую запись cache для диагностики; она не считается готовым результатом.

В конфигурации можно изменять `regional_pixel_m` (не меньше 30 м) и `regional_buffer_m` (0–10000 м).
Более мелкая сетка не создаёт более точную съёмку. Метод существующего DMA-пакета фиксирован:
30 м, буфер 2000 м. [Описание исходного продукта и DMA](DMA_SKRU1_SURFACE_RU.md).

## Что открывать

- `01_surface_and_planimetry.qgz` — непрерывный региональный DSM, DMA и отдельная группа приблизительного
  горизонтального совмещения планов. Географические координаты планов — производная интерпретация.
- `02_skru1_local.qgz`, `03_skru2_local.qgz`, `04_skru3_local.qgz` — исходные локальные системы. Автоматические
  точки подписей скрыты по умолчанию; отдельный слой содержит знаки скважин с поправками.
- Геология сохраняет собственные source/section frames. Разрез без установленной трассы не помещается
  под DSM. Скважина без устьевой отметки не получает её из DSM молча.
- `05_geology_local_constraints.qgz` — проверенные знаки скважин, таблицы отбивок и раздельные локальные
  интервальные сценарии nearest/IDW1/IDW2/linear. Значение интервала не становится абсолютной высотой.
  `06_source_geological_section.qgz` — графические области и границы исходного разреза в отдельной
  метрической системе; неподдержанные белые участки сохранены пропусками.
- `paraview/scene.pvsm` — поверхность ×1 и отображаемые на ней контуры планов. Их драпировка предназначена
  для просмотра и не задаёт высоту выработок. `paraview/data/scene_global.vtm` — независимый VTK-экспорт.
  `paraview/open_scene.py` загружает состояние с переназначением каталога `data` после переноса пакета.
- `paraview/scene_with_separate_sections.pvsm` содержит также отдельные виды исходного разреза;
  между ним и поверхностью не установлена пространственная привязка.
- При наличии исходных геологических разрезов они открываются отдельными source frames, без совмещения
  с DSM. В ParaView поверхность можно пересекать фильтром Slice; готовый диагностический вертикальный
  срез сохраняется в `paraview/data/terrain_vertical_slice.vtp`.
- GeoPackage и сопровождающие таблицы сохраняют IDs, источники, связи, интерпретации, неизвестные пласты
  и даты. Таблицы связей и событий доступны через браузер GeoPackage в QGIS.

Рельеф — Copernicus DSM, высоты EGM2008, эпоха исходных съёмок 2011–2015. Это поверхность с растительностью,
сооружениями, отвалами и выровненной водой; дно водоёмов и поверхность голой земли не восстановлены.
Переход EGM2008 к высотам рудника/Балтийской системе остаётся UNKNOWN. HEM — случайная компонента ошибки,
а не полная неопределённость рельефа. Поддержка и категориальные маски экспортируются отдельно.

Планы различают области панелей, оставшиеся запасы, отработанные области, целики и неизвестную штриховку.
Область панели не превращается в пустоту или закладку. Совпадение номера и пространственное пересечение
создают кандидата связи; они не доказывают тождество. Нормированные DMA-индексы не назначаются давлением.
Исходные датированные состояния — отдельные слои с полями времени; неизвестный календарь не заполняется
событиями из года публикации. Связи событий и объектов просматриваются в таблицах GeoPackage.

## Проверки и ограничения

Каждый шаг сохраняет input/code hashes и output inventory. Проверки охватывают баланс исходных записей,
сохранение неоднозначностей, невязки привязки и LOO, геометрическую корректность, чтение экспорта и перенос
пакета в другой каталог. Побайтовое совпадение и семантическое равенство контейнеров проверяются отдельно.

Некорректные исходные полигоны сохраняются с FAILED_SOURCE_GEOMETRY_VALIDITY; объёмное использование
блокируется. UNKNOWN у высотной связи и неизвестные календари не заполняются ради прохождения проверок.
Полноценное построение подземных объёмов требует достаточных отбивок нужных пластов, координат скважин,
согласованного высотного датума и интерпретации фактической выемки/закладки.

[`verify_spatial_model.py`](../../scripts/verify_spatial_model.py) проверяет полный inventory, читает каждый
GeoPackage и растр, открывает QGIS-проекты и проверяет, что относительные источники остаются внутри пакета.
Проверку следует повторить на копии в другом каталоге из независимого рабочего каталога:

```powershell
python-qgis scripts/verify_spatial_model.py --package work/spatial_run/package --report work/spatial_run/verify.json
```

`--against <другая сборка>` отдельно сравнивает bytes и семантику основных данных. Область семантического
сравнения записывается в отчёт: для QGIS сохраняются фильтры, vector renderer и raster pipe, исключаются
генерируемые UUID символов, категорий и диапазонов, камера и состояние дерева интерфейса. Значения категорий,
границы диапазонов, цвета и прочие настройки renderer сохраняются в сравнении. Полное побайтовое равенство QGZ-контейнеров
не обещается. Перенос состояния ParaView проверяется его loader с `--verify-state` в отдельном процессе.

Проекты открывают GeoPackage как immutable/read-only: обычное чтение не должно менять даже заголовок SQLite.
Для исправления опоры изменяют версионированный вход и создают новую конфигурацию, затем новый выходной
каталог. Итоговые GeoPackage, растр и mesh вручную не редактируют. Схема скважинных колонок также изолирует
настройки matplotlib от предыдущих шагов, поэтому кеширование рельефа не меняет её отображение.
