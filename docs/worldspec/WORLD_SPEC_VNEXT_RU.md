# WorldSpec vNext — спецификация мира ВКМ / СКРУ-1 (3D + время + provenance + неопределённость)

Статус документа: **DESIGN (Phase 1, cloud)**. Схема реализована как типизированная модель
`src/vkm_world/**` (pydantic) и экспортирована в `schemas/worldspec_vnext.schema.json`.
Численное наполнение (интерполяция горизонтов, объёмная реконструкция, сетки) — задача локальной Phase 2.

## 1. Зачем нужен новый WorldSpec

Прежняя архитектура строилась так: **одна «репрезентативная» скважина (№ 75) → слоистый 2D-прямоугольник → модель OGS**.
Модель решателя фактически подменяла собой описание объекта. Отсюда три системные ошибки:

1. **Пространственная.** Одна скважина выдавалась за месторождение: «средняя скважина» — это не реальный участок.
2. **Эпистемическая.** В одной таблице стояли рядом факт, лабораторное значение, аналог и модельный выбор.
3. **Временнáя.** Не различалось, когда событие произошло и когда о нём стало известно. Для будущего
   прогнозного бенчмарка это прямой путь к утечке информации из будущего (leakage).

WorldSpec описывает **что существует и что о нём известно**, а не то, как это дискретизирует решатель.

## 2. Четыре слоя, которые нельзя смешивать

| Слой | Что содержит | Где в коде | Чем НЕ является |
|---|---|---|---|
| **WORLD** | объекты, геометрия-как-данные, хронология, свойства, наблюдательные системы, пробелы | `vkm_world.*` → `WorldSpec` | не сетка, не входной файл решателя |
| **PROCESS MODEL** | определения физических процессов и ссылки на математические модели | `physics.processes`, `mathmeta` | не результат расчёта |
| **OBSERVATION MODEL** | операторы «латентное состояние → предсказанное измерение» | `observations.catalog.ObservationOperatorSpec` | не сами измерения |
| **VALIDATION** | сравнение предсказанных и реальных наблюдений с учётом доступности во времени | будущий модуль (Phase 2+) | не калибровка по тестовой истине |

OGS, MATLAB, FLAC/PLAXIS, gprMax, GemPy, Micromine — **адаптеры** (потребители), а не носители мира.
Любое 2D-сечение или локальная 3D-модель — это производное представление (derived view) со своим
списком `MODEL_CHOICE`. Оно никогда не перезаписывает мир.

## 3. Эпистемика каждого значения

Каждый объект — это `WorldObject(id, name, provenance, notes)`. Каждое число — это `Quantity` (точка,
диапазон, дискретный набор гипотез или ничего), всегда с `Provenance`:

| Поле | Смысл |
|---|---|
| `status` | `FACT` · `DERIVATION` · `INTERPOLATION` · `MODEL_CHOICE` · `ENGINEERING_ASSUMPTION` · `ANALOGUE` · `UNKNOWN` |
| `sources` | `SourceRef(source_id, pdf_page, printed_page, locator, evidence_ids, extraction_method)` |
| `evidence_type` | MEASURED, LAB_TEST, NORMATIVE, DESIGN_VALUE, CALCULATED_BY_AUTHOR, MODEL_CALIBRATED, TEACHING_EXAMPLE … |
| `scope` | SKRU1 (всё шахтное поле); SKRU1_SKRU2_PILLAR (зона междушахтного целика СКРУ-1/СКРУ-2 — для СКРУ-1 только локально или через `Transfer`); SKRU1_OR_SKRU2_UNATTRIBUTED (источник не разделяет рудники); SOLIKAMSK_GROUP (пул СКРУ-1/2/3); SKRU1_SKRU2 (устаревшая неоднозначная метка первых каталогов — СКРУ-1 не засчитывается); SKRU2, SKRU3, BKPRU1–4, USOLSKY, OTHER_VKM_SITE, VKM_REGIONAL, OTHER_POTASH_SITE, NON_VKM, GENERAL_METHOD, PROJECT, UNSTATED |
| `scale` | LAB · MASSIF · CALIBRATED_EFFECTIVE_MODEL · FIELD · DESIGN · NOT_APPLICABLE (у величины нет масштаба материала: дата, геометрия) · UNSTATED (по умолчанию; ошибка там, где масштаб нужен; параметр материала обязан указать масштаб) |
| `spatial` | уровень иерархии и узел, к которому относится утверждение |
| `temporal` | `event_date`, `measurement_date`, `processing_date`, `publication_date`, **`available_from`**; точность `precision` и `available_from_precision` (day · month · year · decade · unknown) |
| `uncertainty` | тип (интервал, распределение, набор гипотез, UNKNOWN) и компоненты: measurement, spatial, temporal, source_conflict, interpolation, model_form, parameter, transferability, engineering_assumption |
| `transfer` | явная запись переноса LAB→MASSIF или аналог→СКРУ-1 (метод, статус, обоснование) |

Правила проверяются кодом и тестами (`tests/world/`):

- UNKNOWN не несёт значения. Нет данных ≠ 0.
- FACT и DERIVATION требуют источника. DERIVATION требует метода. INTERPOLATION требует метода и входов.
- MODEL_CHOICE и ENGINEERING_ASSUMPTION требуют письменного обоснования.
- TEACHING_EXAMPLE никогда не FACT. ANALOGUE никогда не имеет scope СКРУ-1.
- LAB-значение как MASSIF или значение соседнего рудника как значение СКРУ-1 — только через явный `Transfer`.
  Без `Transfer` для СКРУ-1 не засчитываются: зона целика (кроме локального использования), данные без атрибуции
  между СКРУ-1 и СКРУ-2, пул трёх рудников, литературные диапазоны (GENERAL_METHOD) со статусом FACT.
- диапазоны не схлопываются в точку, а противоречащие гипотезы (например, K0 = 0.6 | 0.71 | ≈1)
  хранятся как `DISCRETE_SET`.

## 4. Пространственная иерархия

`ВКМ (deposit)` → `район Соликамска (district)` → `СКРУ-1 (mine)` / соседние рудники (`neighbour_mine`) /
межрудничные целики (`intermine_pillar`) → `шахтное поле` → `панель` → `блок` → `участок` →
`выработка` / `камера` / `целик` → `пласт` / `междупластье` / `геологический элемент` →
`скважина` → `интервал скважины` / `образец`; `GPR-профиль`; `маркшейдерская линия` → `репер`.

Это не жёсткое дерево фиксированной глубины. Допустимые родители заданы таблицей
`spatial.hierarchy.ALLOWED_PARENTS`. Например, разведочная скважина может висеть прямо под месторождением
(она старше рудника), профильная линия может пересекать несколько панелей (`also_within`).
Каждое evidence-утверждение по возможности получает `spatial_support`.

## 5. Системы координат и высот

`spatial.crs`: `CoordinateSystem(kind, epsg, vertical, axes)` и `CoordinateTransform(kind, parameters,
control_points)`. Виды систем:

- STATE_GEODETIC / STATE_PROJECTED — СК-42, СК-63, СК-95, ГСК-2011, МСК-59;
- LOCAL_MINE_GRID — условная система рудника;
- MAP_ONLY — координаты только снимаются с карты, система не указана;
- PROJECT_ENGINEERING — MODEL_CHOICE проекта;
- UNKNOWN.

Высоты: Балтийская система 1977 г., абсолютные отметки без названия системы, глубины от устья
и от поверхности. Неизвестные сдвиги и параметры преобразований остаются UNKNOWN. Трансформация
без параметров или контрольных точек является ошибкой валидации. Численная нормализация координат —
задача Phase 2.

## 6. Геология

- **Стратиграфическая колонна** (`StratigraphicUnit`): ранги complex / formation / zone / seam /
  interseam / marker / interlayer / protective. Порядок `order_index` задаётся сверху вниз.
  Функциональные инженерные единицы (ВЗТ) помечаются `functional=True`, потому что пересекают формации.
- **Скважины** (`BoreholeRecord`): тип, псевдонимы, привязка к узлу иерархии, место как напечатано
  (координаты или ссылка на карту), глубина, дата, наличие керна, каротаж, лабораторные данные,
  вердикт `usable_for_3d` с обоснованием.
- **Наблюдения ≠ интерпретации.**
  - `PickObservation` — отбивка ровно как напечатана в одном источнике: глубина от устья, абсолютная
    отметка или только мощность. Если источники расходятся, хранятся все отбивки.
  - `PickInterpretation` — решение проекта о согласовании отбивок. Обязано ссылаться на исходные
    наблюдения и никогда их не перезаписывает.
  - Инверсия порядка слоёв обнаруживается (`ordering_errors`), но **не удаляется**: это повод
    проверить источник или OCR.
- **Горизонты** (`Horizon`) имеют несколько представлений:
  - PICKS_ONLY / SOURCE_MAP / SOURCE_SECTION / GPR_TRACED / SEISMIC_TRACED — из источников;
  - INTERPOLATED_SURFACE — только в Phase 2 и только со статусом INTERPOLATION, методом и входами.
- **Контакты** (глинистые прослои, ослабленные контакты) и **структуры**: складки, флексуры,
  разломы, нарушенные зоны, геодинамические зоны, зоны растворения, размывы/замещения, аномалии.

## 7. Горные работы и закладка

- `MiningObject`: ствол, капитальная/подготовительная выработка, панель, блок, камера, целик,
  барьерный/межрудничный/предохранительный целик, отработанное пространство, заложенный объём.
  Для каждого указаны: признак `DESIGN | ACTUAL | TEACHING`, пласт(ы), система разработки
  (как напечатано), размеры как `Quantity`, коэффициент извлечения, степень нагружения, глубина.
- `BackfillRecord`: способ (гидро/сухая/…), материал, доля заполнения, задержка после выемки,
  плотность, пористость, влажность, прочность, модуль, уплотнение, контакт с кровлей, ссылки на события.

Проект, фактическая отработка и учебный пример не смешиваются.

## 8. Время: хронология и доступность информации

`chronology.Event` делит события на **физические** (строительство, ввод, проходка, выемка
start/end/period, закладка, обрушения, динамические явления, водопритоки, затопление, смена
гидрорежима, закрытие) и **информационные** (кампании мониторинга, съёмка выработок,
лабораторные испытания, геофизика, обновление геомодели, обработка, публикация, ввод норматива).

Проверяемые правила:

- конец события не раньше начала;
- закладка объекта (или его потомка) не раньше начала его выемки;
- выемка и закладка не раньше ввода рудника в эксплуатацию, если дата ввода известна;
- все ссылки на объекты существуют.

Неточные даты сравниваются как интервалы. «1930» с точностью «год» означает весь 1930 год. Ошибка порядка
фиксируется, только если она достоверна: самое позднее возможное начало закладки раньше самого раннего
возможного начала выемки. Для ввода рудника берётся самая точная из записанных дат: «май 1930» важнее «1930».

**Семантика доступности.** У каждого информационного объекта есть `available_from`.
`known_at(events, t0)` возвращает только то, что прогнозист мог использовать на дату t0.
Неточная доступность разворачивается к последнему возможному дню. Книга «1999» доступна с 31.12.1999, а не с 1 января
(решение D-03, находка CHRONOLOGY-014).

Состояние мира на t0 — это физические события, **о которых было известно** на t0, а не все события с
`event_date ≤ t0`. Функция `known_physical_at(events, t0)` возвращает физическое событие, если известна и не позже t0
его собственная `available_from` или доступность информационного события из `revealed_by` (съёмка, срез ГИС,
публикация). Пример: закладка 2016–2017 гг. зоны, опубликованная срезом ГИС в 2026 г., не видна на t0 = 2018.
Роль прогнозиста (оператор рудника или внешний исследователь) задаёт, какие информационные события ему доступны.
По умолчанию проект моделирует внешнего исследователя.
Если доступность неизвестна, данные **не используются** (`usable_at → None`). Это основа будущего
честного walk-forward бенчмарка (Phase 3+).

## 9. Материалы

`MaterialParameter(variable, material, unit_id, quantity, test_method, n_samples, conditions, law_id)`.
Единицы хранятся как напечатаны. `core.units` знает их размерность и неоднозначность: например,
«т/м3» может означать плотность или удельный вес в тс/м³, а «кгс/см²» — напряжение. Несовместимая
единица — ошибка, неоднозначная — флаг для QA-реестра. `use_errors(MASSIF, SKRU1)` показывает, какие
переносы потребуют явного `Transfer`.

## 10. Процессы и математика (метаданные)

- `ProcessDefinition`: домен, причинная роль, управляющие переменные, ссылки на
  `MATHEMATICAL_MODEL_REGISTRY`, нужные параметры, evidence, масштабы, идентифицируемость,
  **планируемый** `ExecutionStatus` (COMPUTED_3D … UNKNOWN), готовность `Readiness`,
  инструменты-кандидаты.
- `MathModelRecord`: точная форма уравнения из источника, переменные с единицами, допущения,
  масштаб, применимость, источник+локатор (обязательны), происхождение
  (ORIGINAL_SOURCE / CITED_IN_SOURCE / EXTERNAL_PRIMARY / TEXTBOOK_STANDARD / DERIVED_THIS_PROJECT),
  известные варианты и конфликтующие формы.

## 11. Наблюдения

- `ObservationSystem(modality, observable, equipment, datum, crs, precision, systematic_errors, spatial/temporal support, latent_state_link)`.
  Модальности разведены: нивелирование ≠ профильные линии ≠ горизонтальные деформации ≠ GNSS ≠ InSAR ≠
  гидронивелирование ≠ подземные станции/конвергенция ≠ GPR ≠ каротаж ≠ сейсмика ≠ ультразвук.
- `ObservationDataset`: временная поддержка с доступностью; где лежат значения; признак оцифровки
  с рисунка (тогда обязателен локатор рисунка).
- `ObservationOperatorSpec` (**только дизайн**): входы латентного состояния → выход-наблюдение, шумовая
  модель, преобразование носителя (точка/площадь/разность с репером), инструменты-кандидаты.
  Операторы-кандидаты:
  - нивелирование: `u_z(x_i, t) − u_z(x_ref, t)` → Δh;
  - InSAR: `u·ê_LOS` → LOS-смещение относительно опорной точки;
  - GPR: геометрия + ε, σ → радарограмма;
  - сейсмика: упругая структура → времена/отклик.

## 12. Пробелы как объекты

`UnknownItem(what, why_it_matters, blocks, resolution_path)` — неизвестное входит в мир явно.
Оно перечисляет, какие процессы или объекты оно блокирует.

## 13. Что сознательно НЕ входит в Phase 1

Интерполяция горизонтов, объёмная модель, сетки, трансформации координат с подбором параметров,
расчёты напряжений, ползучести, оседаний, прямые модели GPR/сейсмики. Все эти представления
должны появляться в WorldSpec **только** как производные объекты со статусом INTERPOLATION/DERIVATION
и ссылками на входы. Это задача Phase 2 на локальной workstation.

## 14. Инструменты Phase 2 и форматы обмена

| Задача | Инструмент | Обмен |
|---|---|---|
| горизонты, поверхности, 3D-геология | GemPy / Micromine / альтернативная интерполяция | CSV отбивок (из `PickObservation`) → grid / TIN (GeoTIFF, VTK) → `HorizonRepresentation(INTERPOLATED_SURFACE)` |
| геометрия выработок | AutoCAD (через MCP) / Micromine | DXF → полигоны `MiningObject.geometry_ref` |
| символьная и численная математика | MATLAB (Symbolic/PDE/Optimization/Statistics), Python | registry id → код → отчёт |
| механика, реология (основная ветка) | OGS + MFront (кастомная реология соли) | представление под решатель (VTU/MSH) + список MODEL_CHOICE; результаты → `ObservationOperator` |
| независимая FEM-сверка | ANSYS Mechanical | те же согласованные benchmark-сценарии; результат — сверка, а не истина и не field validation |
| дополнительные сверки | FLAC / PLAXIS / MATLAB | при наличии лицензий, на toy-кейсах |
| GPR (оператор наблюдения) | gprMax | локальная геометрия + ε, σ (HDF5) → синтетическая радарограмма; это не модель оседаний |
| визуализация | ParaView / PyVista / QGIS | VTK/GeoPackage (только представление) |

Принцип (решение D-18): инструмент получает **срез WorldSpec** (JSON + ссылки на геометрию) и возвращает
**производный объект с провенансом**. Сам мир не бывает специфичным для решателя: представление под решатель,
в том числе 2D-сечение, — производный объект, который мир не перезаписывает.

## 15. Известные пробелы схемы (к Phase 2)

D-18 требует, чтобы WorldSpec описывал начальное состояние и граничные условия. Явных объектов для них в схеме
пока нет. Сейчас они есть только как процессы каталога физики со статусами INITIAL_CONDITION (PC-02, PC-03, PC-48)
и BOUNDARY_CONDITION (PC-05, PC-41, PC-51). Расширение схемы — задача P2-04 handoff. Значения берутся только из
evidence или как явно маркированные сценарии; UNKNOWN допустим.
