# Пакет входов и проверка результата V2

Сначала используй текущие код, A/B, registry reference, receipts и сохранённые извлечения. Для модели сформулируй недостающее действие и проверяемый выход. Внешняя модель не выполняет предложенный shell/SQL/CAD код: его рассматривает и запускает native-владелец в разрешённой изолированной области.

## Явные входы

V2 real job: `synthetic:false`, `task_kind`, выбранный `profile`, `prompt`, положительный `max_tokens`, схема ответа и `input_package`. Необязательные `reasoning_effort` / `reasoning_justification` определяются [ROUTING_V2.md](ROUTING_V2.md). `synthetic:true` остаётся только настоящей синтетикой; этот флаг не обходит ограничения исходников или бюджета.

Для V2 discovery передавай `discover --task-kind <kind> --profile <profile>`: клиент получает exact endpoint и модельные reasoning capabilities. `check`/`mock`/`call` берут `task_kind` из job либо согласованного `--task-kind`; конфликт значений отклоняется. Live без V2 `task_kind` запрещён. Legacy check/mock/offline replay остаются допустимыми; старый job не получает новое разрешение на POST.

`input_package` имеет точные поля:

| Поле | Значение |
|---|---|
| `schema` | `vkm.delegate-artifact-package/2` |
| `authorization_scope` | `VKM-MULTIAGENT-DELEGATION-V2` |
| `selection_rationale` | Почему именно эти артефакты нужны для данной подзадачи |
| `artifacts` | Явно отобранные inline фрагменты/изображения с происхождением |

Каждый artifact содержит `artifact_id`, `kind`, `source_id`, `work_id`, `logical_name`, `full_sha256`, `fragments`, `images`; необязательный `registry_reference` сохраняет основание ссылки, а не повышает её статус. `kind`: `SOURCE`, `PUBLIC_CODE`, `PRIVATE_CODE`, `PUBLIC_TEXT`, `PRIVATE_TEXT`. Для SOURCE нужны реальные source/work IDs; для CODE/TEXT допустимы явные null там, где библиографическая идентичность неприменима. `logical_name` — относительный локатор происхождения; клиент ничего по нему не загружает.

Text fragment: `{text, sha256, locator:{kind,value}}`. Image reference: `{image_index, sha256, locator:{kind,value}}`, где hash относится к декодированным байтам соответствующего inline PNG/JPEG job image. `locator.kind`: `LINES`, `PAGE`, `EXCERPT`, `FULL_FILE`, `CROP`; `value` сохраняет конкретную область/версию. Клиент проверяет hash переданного fragment/image по его байтам. `full_sha256` относится к полному исходному артефакту; если передан только фрагмент, его соответствие оригиналу проверяет native-владелец. Не выдавать hash crop за hash оригинала. Все изображения должны иметь ссылки в package.

PNG/JPEG image по-прежнему передаётся inline как `mime`, `data_base64`, `width`, `height`, `bbox`. Crop/resize сохраняет переход к оригиналу и исходную рамку в locator/provenance: x/y направления, размеры, pixel centres и масштаб. Bbox модели относится к отправленному изображению, не автоматически к PDF, SH1 или метрам. Не применять кроп к исходным координатам без обратного преобразования и проверки.

Никаких автоматических file/URL reads, env/DSN/токенов/паролей, секретных headers, лишнего персонального содержимого или сырого transcript. Реальный материал не маскировать под synthetic. Действующие AGENTS разрешают внутреннее облачное чтение доступного PRIVATE; публикация, production, ключи и отдельные ограничения материала остаются самостоятельными границами. Marker authorization — проверяемое заявление caller о scope, не автоматическое доказательство права или истинности источника.

## Задание по компетенции

**DeepSeek:** приложи интерфейс и нужный исходник/DDL/A-B пример; назови наблюдаемое нарушение или ограниченный модуль. Требуй конкретный кандидат патча, тесты и сохранение исключений/UNKNOWN. Его область включает backend, CLI, SQL/ETL, геоданные, provenance и полноценные ограниченные модули; не сводить к `add(a,b)`.

**Hydrogen:** для кода/математики достаточно нужных текстовых артефактов; изображения не обязательны для каждого задания. Для визуальной задачи приложи адресный оригинал/crop и вопрос: легенда, текст против штриха, источник расхождения наложения, классификация видимой линии. Требуй наблюдения и область уверенности. `unreadable` допустим и не превращается в подтверждение ручной версии; не оплачивать повтор того же нечитаемого входа.

**Kimi:** приложи конкретные файлы/инварианты/контрпример сложного GIS/CAD или численного интерфейса; отдели алгоритм от исполнения. Требуй проверяемые предпосылки, отказ на недопустимых входах, patch/псевдокод и критерий. Выделяй complementary подзадачу, а не дублируй уже заданный другой модели вопрос.

## Native-проверка и возврат

Проверь JSON/schema/finish_reason и полезный content. Нулевой результат при потраченных reasoning tokens — API-исполнение, но не выполненная задача. Для кода — адресные тесты и реальные входы; для математики — независимый вывод/контрпример/размерности; для визуального результата — оригинал и координаты; для документации — фактические интерфейсы и evidence.

Источник A (что изображено) и B (с чем связано) не смешиваются с моделью. Сохраняй source/work/page/figure/panel, ID, frame/units, input hash, extraction/review/epistemic статусы и transformation history. Нет значения или связи — UNKNOWN; source palette/совпавший номер не подтверждают один горизонт/объект. Нельзя автоматически присвоить EPSG пикселям/SH1, замкнуть контакт через подпись или объявить COMPLETE по наличию одной серии.

Результат сохраняется в private/ignored run directory с input/output hashes и receipt. Не публиковать source crops, reasoning или конфигурацию ключей. Отдельная оценка `VKM_DELEGATE_EVALUATION_V2` фиксирует request/profile/endpoint, requested и confirmed reasoning, task kind, API/schema/tests/source/review статусы, принятое/отклонённое изменение и причину, latency/tokens/cost/rework. Пропущенные проверки остаются NOT_RUN; человеческая и научная приёмка не выдумываются.

При недостающем provider proof проверь сохранённые wire/generation/catalogue offline/GET, сохрани отдельную переоценку с хешами; прежние receipts не переписываются. Unknown cost/outcome прекращает новые расходы того же ledger. Кеш применим только при совпадении входов, вопроса, модели/endpoint, параметров и актуального результата проверки.

Legacy jobs поддерживают только свои прежние check/mock/replay контракты; legacy raw receipts сохраняются. Новые real задачи используют V2 после интеграционной приёмки клиента. Смена профиля/версии пакета не сбрасывает бюджет, reservation count, source ограничения или обязанности главного Codex.
