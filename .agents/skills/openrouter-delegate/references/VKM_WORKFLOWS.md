# Ограниченные задания

`cheap_code`: маленькая функция с сигнатурой, входами и тестируемым контрактом. Ответ — кандидат кода внутри JSON result, исполняет и проверяет Codex.

`vision_documents`: нужное ограниченное изображение с вопросом, известными width/height и рамкой [x0,y0,x1,y1]. Для синтетики — synthetic=true; для разрешённого реального входа VKM-GEO-01/VKM-GEO-01-MA — synthetic=false и строгий пакет ниже. Реальные документы сначала искать существующим корпусным маршрутом; этот клиент не читает PDF/исходные файлы/URL и не включает OCR plugin. Проверять числа/координаты детерминированно.

`engineering_research`: сложная инженерная разработка с ограниченной постановкой, контрактом, нужным diff/кодом и evidence. Kimi возвращает обоснованный кандидат решения; основные решения, независимая проверка и интеграция остаются за Codex. Непроверенные ответы не становятся научными данными.

Выбирай один подходящий профиль на операцию. Несколько моделей запускаются отдельно только ради конкретной проверяемой необходимости, с явным вопросом для каждой. Carbon/`critical_review` имеет `BLOCKED_403` и не является активным профилем; call/mock/check/discover для него запрещены, fallback отсутствует.

Минимальный job:

```json
{"task_id":"synthetic-add","synthetic":true,"profile":"cheap_code","prompt":"Return a Python add(a,b) function in result.","max_tokens":512,"schema":{"type":"object","properties":{"result":{"type":"string"}},"required":["result"],"additionalProperties":false}}
```

Допустимые поля: task_id, synthetic, profile, prompt, max_tokens, schema, images, input_package. `images` — максимум два объекта {mime,data_base64,width,height,bbox}; только проверяемые PNG/JPEG до 1 MiB каждый, максимум 2048 по стороне/4M пикселей суммарно. Prompt до 16000 UTF-8 байтов; schema до 8192 байтов, без $ref и внешних ссылок. Не использовать изображения для передачи секретов или персональных данных. Маркер synthetic — утверждение подготовившего пакет, не автоматическое доказательство содержания.

## Явный реальный визуальный пакет VKM-GEO-01 / VKM-GEO-01-MA

Только `profile=vision_documents`, `synthetic=false`, ровно одно inline PNG/JPEG и `input_package` **со всеми и только** следующими полями:

| Поле | Требование |
|---|---|
| work_id | Для MA точно VKM-WRK-011 по подтверждённой source/work связи. Для прежнего VKM-GEO-01 — существующий ID произведения; если реестр не отделяет work ID от source ID, разрешён work_id=VKM-SRC-011 как явная конвенция caller, не новая сущность. |
| source_id | Точно VKM-SRC-011. |
| page | Объект number:целое1..10000 и scheme:PDF_1_BASED либо PRINTED; фактический номер и систему страниц проверяет вызывающий агент. |
| figure_id | Строка точного вида1.xx: VKM-GEO-01 разрешает25..31, VKM-GEO-01-MA разрешает25..63; suffix и другие диапазоны запрещены. |
| panel_id | Существующий идентификатор выбранной панели. |
| frame | Объект id,units,crs: существующий ID рамки, units=pixel либо px, crs=UNKNOWN. Значения units/id сохраняются без нормализации. Исходный source JSON с crs=null не изменять: UNKNOWN здесь явно обозначает неопределённость пакета, не регистрацию. |
| image_sha256 | 64 lowercase hex SHA256 байтов PNG/JPEG **после base64 decode**, включая файловый контейнер; не хеш текста base64 и не массива пикселей. |
| authorization_scope | Точно VKM-GEO-01 либо VKM-GEO-01-MA с соответствующим диапазоном; вызывающий агент подтверждает действующее разрешение владельца на эту конкретную передачу. |

Идентификаторы work/panel/frame — ограниченные токены до128 символов без пробелов, `/` и `\`; их соответствие реестру и изображению проверяет caller. Клиент проверяет форму, разрешённые scope/source/figure и совпадение хеша, но не читает реестр/оригинал и не удостоверяет человеческое разрешение. Строка authorization_scope не выдаёт нового разрешения или бюджета. Frame ID должен обозначать фактически переданные пиксели/производное изображение; нужные преобразования сохраняются существующим pipeline, не выдумываются клиентом.

Без пакета synthetic=false отклоняется. Synthetic=true вместе с input_package отклоняется, чтобы реальный пакет не маскировался синтетическим флагом. Другие источники/профили/URL/пути/лишние поля не принимаются. Ограничения размерности и decode остаются прежними. Receipt содержит input_kind=AUTHORIZED_SOURCE_VISUAL, synthetic=false, input_authorization_basis=EXPLICIT_CALLER_ASSERTION и input_provenance без base64; полный input hash связывает пакет с заданием. В запрос модели автоматически попадают только назначенные prompt и inline image, не весь источник.

Результат модели — кандидат визуальной интерпретации для проверки Codex, не FACT/измерение/научный допуск. Используется существующий бюджет/ledger; пакет не сбрасывает расходы и не расширяет synthetic-only исключение `--owner-local-cap-only`.

Ledger содержит бюджет, key fingerprint, оплаченные суммы, reservations и блокировку unknown. Файл lock не удалять при конкурирующем запуске. Зависший pending или unknown снимает только оператор после сверки кабинета/generation, сохраняя исходный ledger и receipt; автоматического reset/forgive нет. Один key/партия должны использовать один ledger; отдельный серверный key limit защищает совокупные расходы других программ. Ненулевой статус запрещает считать результат успешным; reservation остаётся при неизвестном исходе.

При технической проверке уже полученного Kimi-ответа не отправляй новый POST ради отсутствующего endpoint поля. Используй сохранённые sanitized wire response, generation и свежий исходный endpoint snapshot; `prepare` строит полный список Decart candidates, `validate_response(..., endpoint_evidence=...)` проверяет ограниченный routing inference. Не переписывай прежний receipt: сохрани отдельный результат переоценки с входными хешами и `route_verification`. Входы/результат задачи и модельные выводы по-прежнему проверяет Codex. Если proof неполон, сохраняется PROVENANCE_UNCONFIRMED; рекламная MXFP4 не становится наблюдаемой physical precision.

Явный `--owner-local-cap-only` — исключение только для разрешённых трёх synthetic smoke-проб с локальным бюджетом<=1USD. При unlimited server key общий бюджет контролирует один ledger; защиты расходов других программ серверным cap здесь нет. Persistent `reservation_count` увеличивается внутри process-safe lock и не уменьшается после settle; четвёртая reservation запрещена. Менять режим/budget/key существующего ledger нельзя. Это не отменяет unknown-блокировку, stop/no retry или ограничения маршрутов.
